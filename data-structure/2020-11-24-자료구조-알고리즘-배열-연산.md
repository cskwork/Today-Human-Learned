# 배열 연산 — 읽기, 검색, 삽입, 삭제가 실제로 몇 단계인가

> **TL;DR**
> 배열은 인덱스 덕분에 읽기는 1단계지만, 삽입과 삭제는 데이터를 밀어야 해서 최악 N+1단계가 걸린다.

---

## 배열 연산을 왜 따로 공부해야 하는지 감 잡기

"배열 쓰면 되지"라고 생각하기 쉽지만, 어떤 위치에 데이터를 넣느냐에 따라 실행 속도가 몇 배로 달라진다. 데이터가 100만 개인 배열에서 맨 앞에 값 하나를 삽입하면, 기존 값 100만 개를 전부 한 칸씩 오른쪽으로 밀어야 한다. 이 비용을 모르면 나중에 성능 문제가 생겼을 때 원인을 못 찾는다.

알고리즘을 공부할 때 "단계 수(step count)"로 연산 비용을 측정한다. 단계가 적을수록 빠른 코드다.

`핵심 흐름: 연산 종류 → 위치(처음/중간/끝) → 단계 수 결정`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| 인덱스(Index) | 배열에서 각 칸의 번호. 0부터 시작하므로 첫 번째 칸은 인덱스 0이다. |
| 단계 수(Step Count) | 연산 하나를 완료하는 데 필요한 최소 작업 횟수. 알고리즘 속도를 비교하는 기준이다. |
| 삽입(Insertion) | 배열 안에 새 값을 끼워 넣는 작업. 중간에 넣으려면 기존 값을 옆으로 밀어야 한다. |
| 삭제(Deletion) | 배열에서 값을 제거하는 작업. 빈 칸이 생기면 오른쪽 값을 왼쪽으로 당겨야 한다. |
| 집합(Set) | 중복 값을 허용하지 않는 배열. 삽입 전에 전체를 뒤져 중복 여부를 확인해야 한다. |

## 예를 들어 설명하면

배열 `[A, B, C, D]`가 있을 때 각 연산의 단계 수를 직접 세어 보자.

- **읽기**: 인덱스 2번 값을 달라 → 메모리 주소에 2를 더해 바로 접근 → **1단계**.
- **검색**: 값 `C`가 어디 있는지 모른다 → 0부터 하나씩 확인 → 최악 4단계(N단계).
- **삽입 (맨 끝)**: 인덱스 4에 `E`를 놓는다 → **1단계**.
- **삽입 (인덱스 0)**: `Z`를 맨 앞에 넣으려면 A→B→C→D를 각각 오른쪽으로 이동(4단계) 후 삽입(1단계) → **5단계(N+1단계)**.
- **삭제 (중간)**: 인덱스 1의 `B`를 지우면 빈 칸이 생겨 C→D를 왼쪽으로 이동 → **N단계**.

집합은 삽입 전에 중복 검사를 위해 전체를 한 번 순회하므로 최악 **2N+1단계**가 필요하다.

## 이 단계에서 중요한 판단 기준

"삽입·삭제가 자주 일어나고 위치가 중간이라면, 배열 대신 다른 자료구조를 고려해야 한다."

## 한 줄 요약 — 이것만 기억하면 된다

**배열 읽기는 항상 1단계지만, 중간 삽입·삭제는 기존 데이터를 밀어야 해서 N단계까지 늘어난다.**

## 나중에 더 깊게 들어가면

- 빅오 표기법(Big-O Notation): 단계 수를 수식으로 표현하는 방법
- 동적 배열(Dynamic Array): 크기가 자동으로 늘어나는 배열의 내부 동작
- 링크드 리스트: 중간 삽입·삭제 비용이 배열과 어떻게 다른지
