# DNS in Firewall — 방화벽에서 DNS가 하는 역할

> **TL;DR**
> DNS 방화벽은 도메인 이름 단계에서 악성 사이트 접속을 차단하여, IP·포트 기반 방화벽이 놓치는 DNS 터널링·악성 도메인 위협을 막는다.

---

## DNS 방화벽을 왜 쓰는지 감 잡기

전통적인 방화벽은 패킷의 IP 주소와 포트 번호만 본다. 그런데 DNS 쿼리(포트 53)는 대부분 그냥 통과시킨다. 공격자들은 이 허점을 파고든다. 악성 도메인으로 멀웨어를 배포하거나, DNS 쿼리 안에 데이터를 숨겨 외부로 빼내는 DNS 터널링이 대표적이다. DNS 방화벽은 IP 레벨이 아니라 도메인 이름 레벨에서 트래픽을 검사해서 이런 위협을 차단한다.

초보자는 처음에 이렇게 이해하면 된다.

`핵심 흐름: 클라이언트 DNS 쿼리 → DNS 방화벽(도메인 검사) → 악성이면 차단, 아니면 상위 DNS로 전달 → 응답 반환`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| DNS 터널링(DNS Tunneling) | DNS 쿼리 패킷 안에 다른 데이터를 숨겨서 방화벽을 우회하는 공격 기법. |
| 위협 인텔리전스(Threat Intelligence) | 알려진 악성 도메인 목록을 실시간으로 관리하는 데이터베이스. DNS 방화벽의 판단 근거가 된다. |
| C&C 서버(Command & Control) | 감염된 기기에 명령을 내리는 공격자 서버. 악성코드가 이 서버와 DNS로 통신하는 것을 막아야 한다. |
| DNS 리졸버(Resolver) | 도메인 이름을 IP 주소로 변환해 주는 서버. DNS 방화벽은 이 앞에 위치한다. |
| DGA(도메인 생성 알고리즘) | 악성코드가 매번 다른 무작위 도메인을 생성해 차단을 피하는 기법. |

## 예를 들어 설명하면

클라이언트가 `evil.com`을 조회하는 시나리오:

```
클라이언트 → DNS 방화벽 → 위협 인텔리전스 DB 조회
                              ├── 악성 도메인이면 → 차단 응답(NXDOMAIN 또는 싱크홀 IP)
                              └── 정상이면 → 상위 DNS 리졸버로 전달 → 실제 IP 반환
```

DNS 방화벽은 네트워크 경계에만 두지 않고 클라이언트에 가까운 위치에도 배치해야 내부 감염 기기가 C&C 서버와 통신하는 것을 잡아낼 수 있다.

## 이 단계에서 중요한 판단 기준

DNS 방화벽은 네트워크 방화벽의 대체제가 아니라 보완재다. IP·포트 기반 차단과 도메인 기반 차단을 함께 써야 다층 방어가 완성된다.

## 한 줄 요약 — 이것만 기억하면 된다

**DNS 방화벽은 도메인 이름 단계에서 악성 연결을 차단해, 기존 방화벽이 통과시키는 DNS 기반 공격을 막는 추가 방어선이다.**

## 나중에 더 깊게 들어가면

- DNS over HTTPS(DoH), DNS over TLS(DoT) 트래픽에 대한 인스펙션 방법
- DNSSEC을 함께 적용해 DNS 캐시 포이즈닝을 방어하는 구조
- 오픈소스 DNS 방화벽(Pi-hole, RPZ) 직접 구성 실습
