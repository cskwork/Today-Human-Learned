# GPT-5-Codex-Mini — 4배 더 쓰는 경량 코딩 모델

> **TL;DR**
> GPT-5-Codex-Mini는 기존 GPT-5-Codex보다 사용 한도가 4배 많고, 성능은 약 3% 낮은 비용 효율 모델이다.

---

## GPT-5-Codex-Mini를 왜 쓰는지 감 잡기

복잡한 리팩토링이나 대규모 코드 리뷰를 하다 보면 ChatGPT Plus 플랜의 Codex 사용 한도가 예상보다 빨리 소진된다. 한도에 걸리면 마감 직전에 작업이 멈춘다. GPT-5-Codex-Mini는 이 문제를 해결하기 위해 2025년 11월 8일 OpenAI가 발표한 경량 모델이다.

SWE-bench Verified 벤치마크를 보면 GPT-5-Codex가 74.5%인 반면 GPT-5-Codex-Mini는 71.3%다. 3.2%포인트 낮지만, 4배 많은 사용량을 고려하면 일상적인 코딩 작업에서 더 높은 실용 가치를 제공한다.

초보자는 이렇게 이해하면 된다.

`핵심 흐름: 한도 90% 도달 → Codex가 Mini 전환 제안 → 확인 → 작업 중단 없이 계속`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| GPT-5-Codex | GPT-5를 에이전트형 소프트웨어 엔지니어링에 특화시킨 전체 모델 |
| GPT-5-Codex-Mini | Codex의 경량 버전; 사용 한도 4배, 성능은 약 3% 낮음 |
| Rate Limit | 일정 시간 동안 사용할 수 있는 요청 횟수 제한 |
| SWE-bench Verified | 실제 오픈소스 저장소 이슈 해결 능력을 측정하는 500개 작업 벤치마크 |
| 자동 전환 | 한도 90% 도달 시 Codex가 Mini로 전환을 제안하는 기능 |

## 예를 들어 설명하면

CLI에서 Mini 모델을 직접 지정하려면:

```bash
codex -m gpt-5-codex-mini
```

자동 전환을 활용하면 수동으로 모델을 바꾸지 않아도 된다. Codex가 한도 90%에서 제안을 띄우면 확인만 하면 이어진다.

작업 유형별 모델 선택 기준:

| 작업 | 권장 모델 |
|---|---|
| 단순 버그 수정, 테스트 작성, 문서화, 간단한 리팩토링 | Mini |
| 대규모 아키텍처 변경, 복잡한 알고리즘, 보안 취약점 분석 | 전체 모델 |

## 이 단계에서 중요한 판단 기준

작업 복잡도를 먼저 평가하라. 단순 구현은 Mini로 시작하고, 설계·보안처럼 판단이 중요한 작업은 전체 모델을 유지한다.

## 한 줄 요약 — 이것만 기억하면 된다

**간단한 코딩 작업은 Mini로 처리해 한도를 아끼고, 복잡한 판단이 필요한 작업에만 전체 모델을 쓰는 것이 실용적 전략이다.**

## 나중에 더 깊게 들어가면

- Codex CLI의 고급 옵션과 IDE extension 연동
- 플랜별(Plus, Pro, Enterprise) 사용량 한도 정책 변화 추적
- Mini와 전체 모델 혼합 전략의 비용 계산 방법
