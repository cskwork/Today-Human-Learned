# SKT 콜센터 AWS Bedrock Claude 사용 사례

> **TL;DR**
> SKT는 Claude를 상담사 보조 도구로 도입해 LLM 응답 품질을 34% 향상시켰고, AI가 상담사를 대체하는 것이 아니라 인지 부담을 줄이는 방향으로 설계했다.

---

## 콜센터 AI 도입을 왜 쓰는지 감 잡기

콜센터 상담사는 동시에 많은 것을 처리해야 한다. 고객 말을 듣고, 관련 정책을 찾고, 답변을 구성하고, 통화 후 기록까지 남긴다. 여기에 AI를 붙이면 정보 검색과 사후 처리를 자동화할 수 있다.

SKT는 27년 연속 국내 고객 서비스 1위를 유지해 왔다. 대기 없이 빠른 응답, 지역 방언까지 반영하는 개인화된 응대가 기준이다. 이 수준을 유지하면서 증가하는 상담량을 처리하려면 상담사를 보조하는 AI가 필요했다.

`고객 전화 → 상담사 수신 → AI가 실시간 문서 검색 및 답변 제안 → 상담사 검토 후 응대 → 통화 종료 후 AI가 요약/분류/할 일 생성`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| In-Call Assist | 통화 중 상담사에게 실시간으로 관련 문서와 답변 후보를 제시하는 기능 |
| Post-Call Processing | 통화 종료 후 요약, 주제 분류, 할 일 생성, 감성 분석 등을 자동 처리하는 기능 |
| RAG (검색증강생성) | AI가 답변을 만들 때 외부 문서를 실시간으로 검색해서 근거로 사용하는 방식 |
| HITL (Human-in-the-loop) | AI 출력을 사람이 최종 검토·승인하는 설계 방식 |
| 지능 강화 (IA) | AI가 사람을 대체하는 것이 아니라 사람의 능력을 확장·보조하는 접근법 |

## 예를 들어 설명하면

SKT가 Claude를 선택한 이유는 세 가지였다.

첫째, 브랜드 안전성. 고객 상담에서 AI가 부정확하거나 공격적인 응답을 내놓으면 브랜드 손상으로 직결된다. Anthropic의 안전 중심 설계가 이 기준을 충족했다.

둘째, 한국어 문화적 맥락 처리. 지역 방언, 공감 표현, 빠른 응답 속도 기대치는 일반적인 LLM이 처리하기 어렵다. Claude는 다른 모델보다 자연스러운 한국어 대화를 생성했다.

셋째, Amazon Bedrock 통합. 대규모 처리량과 낮은 지연시간이 필요했고, Bedrock이 커스텀 모델 서빙과 자원 확장을 안정적으로 지원했다.

SKT는 자체 RAG 모델을 Claude와 결합해 통신사 LLM 성능을 3.3에서 4.3 이상으로 끌어올렸다.

## 이 단계에서 중요한 판단 기준

상담사 보조 AI를 설계할 때 핵심은 "AI가 틀릴 수 있다"는 전제 아래 사람이 최종 판단을 유지하는 구조를 먼저 잡는 것이다.

## 한 줄 요약 — 이것만 기억하면 된다

**SKT의 AI 도입 원칙은 상담사 대체가 아니라 상담사의 인지 부담 경감이며, 그 결과 응답 품질 34% 향상과 저품질 응답 68% 감소를 달성했다.**

## 나중에 더 깊게 들어가면

- 통신사 특화 파인튜닝 모델과 범용 LLM의 성능 비교 방법론
- Amazon Bedrock에서 커스텀 모델을 서빙할 때의 처리량·지연시간 최적화
- 다국어 콜센터 AI에서 방언과 문화적 뉘앙스를 처리하는 설계 패턴
