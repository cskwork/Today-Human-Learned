# Claude Agent SDK: 효과적인 에이전트 구축 가이드

> **TL;DR**
> Claude Agent SDK는 Claude에게 컴퓨터 접근 권한을 주어 "맥락 수집 → 행동 실행 → 작업 검증"의 루프로 자율 에이전트를 구축하는 프레임워크다.

---

## Claude Agent SDK를 왜 쓰는지 감 잡기

Claude는 대화를 잘하지만, 실제 업무 자동화에는 파일을 읽고, 코드를 실행하고, 외부 서비스와 연결하는 능력이 필요하다. Claude Agent SDK는 Claude Code를 구동하던 에이전트 하네스를 일반 에이전트 구축에 개방한 것이다.

핵심 설계 원칙은 단순하다: "에이전트에게 컴퓨터를 주면 사람처럼 일한다." bash 실행, 파일 편집, 웹 검색이 가능해지면 코딩 이외의 금융 분석, 리서치, 고객 지원도 자동화할 수 있다.

`핵심 흐름: 맥락 수집 → 행동 실행 → 작업 검증 → 반복`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| 에이전트 루프 | 맥락 수집 → 행동 실행 → 검증을 반복하는 에이전트의 기본 동작 패턴 |
| 서브에이전트 | 오케스트레이터가 특정 작업을 위해 띄우는 독립 에이전트 — 병렬 처리와 컨텍스트 격리에 유용 |
| 컴팩션(Compaction) | 에이전트가 오래 실행될 때 이전 메시지를 자동 요약해 컨텍스트 한계를 피하는 기능 |
| MCP(Model Context Protocol) | Slack, GitHub, Asana 같은 외부 서비스를 인증 코드 없이 연결하는 표준 통합 프로토콜 |
| 에이전트 검색 | Claude가 파일시스템을 직접 탐색해 관련 정보를 찾는 방식 — 벡터 검색보다 느리지만 투명하고 정확 |

## 예를 들어 설명하면

이메일 에이전트를 구축하는 시나리오:

**맥락 수집**: 이전 대화를 `Conversations/` 폴더에 저장해두고, 질문이 오면 grep으로 관련 이메일을 검색한다. 여러 검색 서브에이전트를 병렬로 실행해 속도를 높인다.

**행동 실행**: `fetchInbox`, `searchEmails` 같은 커스텀 도구를 정의하고, 첨부 PDF가 있으면 bash로 다운로드해 텍스트로 변환한다. Slack MCP 서버로 팀 컨텍스트를 확인한다.

**작업 검증**: 이메일 주소 유효성을 규칙으로 검사하고, HTML 이메일이면 스크린샷을 찍어 Claude에게 시각적 확인을 시킨다. 톤이 적절한지 별도 서브에이전트로 평가한다.

## 이 단계에서 중요한 판단 기준

에이전트가 반복 실패한다면 도구를 더 추가하기 전에 — "에이전트가 필요한 정보를 찾을 수 있는 구조인가?"를 먼저 확인하라. 대부분 검색 구조나 도구 설계 문제다.

## 한 줄 요약 — 이것만 기억하면 된다

**Claude Agent SDK의 핵심은 에이전트에게 컴퓨터를 주는 것이고, 루프(맥락 수집 → 행동 → 검증)를 얼마나 잘 설계하느냐가 에이전트 품질을 결정한다.**

## 나중에 더 깊게 들어가면

- 에이전트 검색과 시맨틱 검색의 트레이드오프 (언제 벡터 DB를 추가할 것인가)
- LLM을 평가자로 쓰는 패턴의 비용-성능 트레이드오프
- Agent Skills와 SDK를 함께 쓸 때의 구조 설계
