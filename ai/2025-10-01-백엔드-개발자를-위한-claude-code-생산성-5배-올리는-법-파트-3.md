# 백엔드 개발자를 위한 Claude Code 생산성 올리는 법 — 파트 3

> **TL;DR**
> Extended Thinking으로 복잡한 아키텍처 결정을 깊게 처리하고, Subagent로 대규모 코드베이스를 병렬 탐색하며, Headless 모드와 --add-dir로 CI/CD와 멀티 레포지토리까지 Claude 워크플로우를 확장할 수 있다.

---

## 고급 기법들을 왜 배우는지 감 잡기

기본 Claude Code 사용에 익숙해지면 두 가지 한계를 만난다. 첫째, 복잡한 아키텍처 결정에서 Claude가 성급한 해결책을 내놓는다. 둘째, 대규모 코드베이스에서 단일 컨텍스트 윈도우가 부족해진다.

Extended Thinking과 Subagent는 이 두 한계를 직접 해소하기 위해 설계된 기능이다. 그 외 Headless 모드와 --add-dir 플래그는 Claude를 개발자 터미널 밖으로 꺼내 팀 인프라 전체에 통합하는 도구다.

초보자는 이렇게 이해하면 된다.

`핵심 흐름: 복잡한 문제 → Extended Thinking → 대규모 탐색 → Subagent 병렬 처리 → 자동화 → Headless/CI 통합`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| Extended Thinking | Claude가 응답 전에 더 오랜 시간 내부적으로 추론하게 하는 모드; 프롬프트에 "think", "think hard", "ultrathink" 키워드로 활성화 |
| Subagent | 메인 Claude가 생성하는 독립적인 경량 Claude 인스턴스; 각자 별도 컨텍스트 윈도우를 가짐 |
| 파이프 입력 | `cat logfile | claude` 형태로 대용량 파일을 Claude에게 스트림으로 넘기는 방식 |
| Headless 모드 | `-p` 플래그로 프롬프트를 직접 전달해 비대화형 환경(CI, pre-commit hook)에서 Claude를 실행하는 방식 |
| --add-dir | Claude 세션에 다른 디렉토리(또는 별도 레포지토리)를 추가로 포함시키는 플래그 |

## 예를 들어 설명하면

Subagent를 사용해 대규모 코드베이스를 병렬로 탐색하는 패턴:

```
프롬프트:
"4개의 병렬 태스크로 코드베이스를 탐색해줘.
각 에이전트는 다른 디렉토리를 담당:

Task 1: /src/api - REST API 엔드포인트 분석
Task 2: /src/services - 비즈니스 로직 서비스 분석
Task 3: /src/database - 데이터베이스 스키마와 쿼리 분석
Task 4: /tests - 테스트 커버리지 평가"
```

Extended Thinking 사용 기준의 예:

```
# 복잡한 문제 → ultrathink
"결제 시스템 아키텍처를 ultrathink 모드로 설계해줘.
초당 10만 건 동시 요청, 멱등성 보장, PCI-DSS 준수 포함."

# 중간 복잡도 → think hard
"이 캐시 무효화 로직을 think hard 모드로 검토해줘."

# 일반 작업 → 표준 모드
"API 엔드포인트 구현해줘."
```

## 이 단계에서 중요한 판단 기준

ultrathink는 비용이 크다 — 데이터베이스 샤딩 전략, 보안 아키텍처 설계처럼 실수가 큰 파급력을 갖는 결정에만 써야 투자 대비 가치가 있다.

## 한 줄 요약 — 이것만 기억하면 된다

**Extended Thinking은 복잡한 결정에, Subagent는 대규모 탐색에, Headless 모드는 반복 자동화에 — 각 도구를 적합한 문제에 매핑하는 것이 핵심이다.**

## 나중에 더 깊게 들어가면

- RAG 방식으로 수백만 라인 코드베이스에서 의미 기반 검색을 하는 방법
- 팀 전체가 공유하는 Slash Commands 작성과 Git 커밋 방법
- Claude Hooks로 코드 품질 게이트를 코드베이스에 영구 내장하는 법
