# Claude Skills vs MCP, 둘 다 확장 기능인데 뭐가 다를까?

> **TL;DR**
> MCP는 Claude가 외부 시스템에 "접근"하는 방법이고, Skills는 Claude가 반복 작업을 "수행"하는 방법이다. 경쟁 관계가 아니라 보완 관계다.

---

## Claude를 확장하는 방법이 두 가지인 이유

AI 에이전트를 만들 때 두 가지 문제가 동시에 생긴다. 첫째, 외부 데이터에 어떻게 접근할 것인가. 둘째, 어떤 방식으로 일관되게 작업할 것인가. Anthropic은 이 두 문제를 각각 다른 도구로 해결했다. MCP(Model Context Protocol)는 2024년 11월, Skills는 2025년 10월에 발표됐다.

초보자는 처음에 이렇게 이해하면 된다.

`핵심 흐름: 외부 데이터 필요 → MCP 서버로 연결 → Claude가 데이터 수신 → Skills 지침대로 작업 수행 → 결과 출력`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| MCP (Model Context Protocol) | AI가 외부 시스템과 표준화된 방식으로 통신하는 규격. USB-C처럼 한 번 만들면 여러 곳에서 재사용 가능하다. |
| MCP 서버 | 데이터베이스, API, 파일 시스템 등을 MCP 규격으로 노출하는 서버. Claude가 여기에 연결해 데이터를 가져온다. |
| Skills | Claude에게 작업 방법을 가르치는 마크다운 파일. "이런 상황에서는 이렇게 해라"는 지침서다. |
| SKILL.md | Skills의 실체. YAML 헤더와 마크다운 지침으로 이루어진 파일로, 팀 컨벤션이나 업무 프로세스를 담는다. |
| 점진적 로딩 (Progressive Loading) | Skills의 작동 방식. 관련성 높은 Skill만 그때그때 컨텍스트에 불러와 토큰을 아낀다. |

## 예를 들어 설명하면

고객 지원 AI 에이전트를 만든다고 가정하자.

- MCP로 해결하는 것: 티켓 시스템(Zendesk)에 접근해 고객 문의를 조회하고, CRM에서 고객 이력을 가져오고, 이메일 API를 호출한다. "무엇에 접근하는가"의 영역이다.
- Skills로 해결하는 것: 고객 응대 톤, 에스컬레이션 기준, 답변 템플릿, 환불 요청 체크리스트를 SKILL.md로 정의한다. "어떻게 행동하는가"의 영역이다.

MCP만 있으면 데이터는 가져오지만 답변 품질이 들쑥날쑥하다. Skills만 있으면 행동 방식은 정해져 있지만 실시간 데이터가 없다. 둘을 같이 쓸 때 완전한 에이전트가 된다.

## 이 단계에서 중요한 판단 기준

실시간으로 외부 시스템 데이터가 필요하면 MCP, 반복 작업의 형식과 품질을 고정하고 싶으면 Skills, 둘 다 필요하면 둘 다 쓴다.

## 한 줄 요약 — 이것만 기억하면 된다

**MCP는 AI의 신경계(무엇에 연결할지), Skills는 AI의 플레이북(어떻게 행동할지)이다.**

## 나중에 더 깊게 들어가면

- MCP 서버 직접 구현하기 (Python/TypeScript SDK)
- SKILL.md 파일 작성 규칙과 메타데이터 구조
- 여러 MCP를 동시에 연결할 때 발생하는 토큰 효율 문제 해결법
