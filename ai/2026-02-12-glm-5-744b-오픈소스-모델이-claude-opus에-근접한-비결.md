# GLM-5: 744B 오픈소스 모델이 Claude Opus에 근접한 비결

> **TL;DR**
> GLM-5는 MoE 구조에 DeepSeek의 희소 어텐션과 자체 비동기 강화학습 프레임워크 Slime을 결합해, 오픈소스 모델 최초로 프론티어급 에이전트 성능을 달성했다.

---

## 이 주제를 왜 쓰는지 감 잡기

"오픈소스 모델은 클로즈드 모델을 절대 못 따라간다"는 말이 2025년까지만 해도 상식처럼 통했다. 2026년 2월 11일, 중국 AI 스타트업 즈푸AI(Zhipu AI)가 공개한 GLM-5는 이 상식에 정면으로 도전한다. SWE-bench 코딩 벤치마크에서 Claude Opus 4.5와 3.1%p 차이, 에이전트 벤치마크 BrowseComp에서는 오히려 25%p 앞서는 결과를 보여줬다.

오픈소스이면서 MIT 라이선스로 상업적 사용까지 가능하다. 배포 비용도 낮다.

`핵심 흐름: 대규모 MoE 설계 → DeepSeek Sparse Attention으로 긴 컨텍스트 처리 → Slime 비동기 RL로 에이전트 능력 강화`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| MoE (Mixture of Experts) | 744B 파라미터 중 추론 시 40B만 활성화하는 구조. 지식 용량은 크되 실행 비용은 낮다 |
| 희소 어텐션 (Sparse Attention) | 긴 문서를 처리할 때 중요한 토큰만 선별해 계산하는 방식. 전체를 다 보지 않아도 된다 |
| Lightning Indexer | 각 토큰의 중요도를 빠르게 평가해 2,048개만 추려 어텐션을 수행하는 경량 모듈 |
| Slime | 즈푸AI가 자체 개발한 비동기 강화학습 프레임워크. 데이터 생성과 학습을 분리해 GPU 낭비를 줄인다 |
| 후훈련 (Post-training) | 사전학습으로 쌓은 지식을 실전 능력으로 바꾸는 단계. 강화학습이 주로 쓰인다 |

## 예를 들어 설명하면

MoE 구조를 회사에 비유하면 이렇다. 전체 직원이 744명인 회사에서 하나의 프로젝트에는 40명만 투입한다. 나머지 704명은 자기 전문 분야의 질문이 들어올 때만 활성화된다. 지식 용량은 크지만 실행 비용은 비교적 낮게 유지된다.

벤치마크에서 GLM-5의 위치를 확인하면 아래와 같다.

| 벤치마크 | GLM-5 | Claude Opus 4.5 |
|---|---|---|
| SWE-bench Verified (코딩) | 77.8% | 80.9% |
| BrowseComp (웹 에이전트) | 62.0% | 37.0% |
| AIME 2026 (수학) | 92.7% | 93.3% |
| MCP-Atlas (도구 호출) | 67.8% | 65.2% |

에이전트 영역에서는 오히려 Claude Opus를 넘어서는 결과가 나왔다.

## 이 단계에서 중요한 판단 기준

웹 브라우징이나 도구 호출 에이전트를 자체 배포해야 하고 비용이 제약 조건이라면 GLM-5가 현실적인 선택이다. 순수 코딩 정확도가 최우선이라면 Claude Opus 4.5가 여전히 앞선다.

| 사용 시나리오 | 추천 모델 |
|---|---|
| 웹 브라우징, 검색 에이전트 | GLM-5 (BrowseComp 1위) |
| 실무 코딩, 버그 수정 | Claude Opus 4.5 (SWE-bench 80.9%) |
| 오픈소스, 자체 배포 | GLM-5 (MIT, 비NVIDIA 칩 호환) |
| 수학, 과학 추론 | Gemini 3.0 Pro (GPQA-Diamond 91.9%) |

## 한 줄 요약 — 이것만 기억하면 된다

**오픈소스와 프론티어 모델의 성능 격차는 사실상 해소됐고, 이제 선택 기준은 성능 차이가 아니라 비용과 배포 방식이다.**

## 나중에 더 깊게 들어가면

- Slime 프레임워크를 다른 모델(Qwen3, DeepSeek V3)에 적용하는 방법
- GLM-5 로컬 배포: vLLM, SGLang, 화웨이 Ascend 칩 지원 설정
- GLM-5 API를 기존 OpenAI SDK 코드에 통합하는 방법
