# GSD(Get Shit Done) — AI 코딩의 '컨텍스트 부패' 문제를 해결

> **TL;DR**
> Claude Code로 긴 작업을 하다 보면 뒤로 갈수록 품질이 떨어진다. GSD는 작업을 독립된 서브에이전트에 분산해 이 '컨텍스트 부패'를 구조적으로 차단하는 경량 프레임워크다.

---

## 컨텍스트 부패를 왜 신경 써야 하는지 감 잡기

Claude Code로 프로젝트를 진행하다 보면 이상한 경험을 한다. 처음에는 정확하고 깔끔하던 코드가 대화가 길어질수록 점점 엉성해진다. 이전에 결정한 사항을 잊거나, 지시를 무시하거나, 스스로 "간결하게 하겠습니다"라며 코너를 깎기 시작한다.

이 현상을 '컨텍스트 부패(Context Rot)'라고 부른다. LLM의 컨텍스트 윈도우에 토큰이 쌓일수록 응답 품질이 점진적으로 저하되는 현상이다. Chroma Research 연구에 따르면 컨텍스트가 길어질수록 모든 모델에서 성능이 일관되게 하락한다. 중간에 묻힌 정보의 정확도는 최대 15~20%p까지 떨어진다.

Claude Code의 자동 Compaction(대화 압축)도 근본 해결책이 아니다. 이미 부패한 컨텍스트를 압축하는 것이라, 부패를 고정시키고 더 썩게 만드는 결과가 된다.

`핵심 흐름: 긴 대화 → 컨텍스트 70~80% 소진 → 품질 저하 → GSD 서브에이전트 분산으로 차단`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| 컨텍스트 부패 | 대화가 길어질수록 AI의 응답 품질이 떨어지는 현상. 메모 없이 긴 프로젝트를 혼자 처리하면 뒤로 갈수록 앞 내용을 잊는 것과 같다. |
| 서브에이전트 | 특정 태스크 하나만 담당하는 독립된 AI 인스턴스. 신선한 컨텍스트로 시작해서 부패가 없다. |
| 오케스트레이터 | 전체 작업 흐름만 관리하는 프로젝트 매니저 역할의 메인 에이전트. |
| XML 구조화 프롬프트 | 태스크 이름, 대상 파일, 행동 지침, 검증 방법을 명시적으로 기술해 AI가 추측할 여지를 없애는 프롬프트 형식. |
| 메타 프롬프팅 | AI에게 어떻게 행동할지를 명시적으로 지시하는 상위 수준의 프롬프팅 기법. |

## 예를 들어 설명하면

GSD가 태스크를 서브에이전트에 위임할 때 사용하는 XML 구조를 보면 원리가 명확해진다.

```xml
<task type="auto">
  <n>로그인 엔드포인트 생성</n>
  <files>src/app/api/auth/login/route.ts</files>
  <action>
    JWT에 jose 라이브러리 사용 (jsonwebtoken은 CommonJS 이슈).
    users 테이블 대비 자격 증명 검증.
    성공 시 httpOnly 쿠키 반환.
  </action>
  <verify>curl -X POST localhost:3000/api/auth/login → 200 + Set-Cookie</verify>
  <done>유효한 자격 증명은 쿠키 반환, 무효는 401 반환</done>
</task>
```

각 서브에이전트는 200K 토큰의 깨끗한 컨텍스트로 시작한다. 이전 작업의 찌꺼기가 없다. 메인 컨텍스트는 30~40% 수준을 유지해 세션이 빠르고 반응성이 좋다. 독립적인 태스크는 병렬로, 의존성 있는 것은 순차로 처리하며 각 태스크마다 개별 Git 커밋이 생성된다.

## 이 단계에서 중요한 판단 기준

GSD는 1인 개발자나 소규모 팀이 Claude Code로 복잡한 프로젝트를 진행할 때 선택한다. 엔터프라이즈급 프로세스(스프린트 세레모니, 스토리 포인트 등)가 필요 없는 규모에서 컨텍스트 부패가 실제 문제로 느껴진다면 도입을 고려할 시점이다.

## 한 줄 요약 — 이것만 기억하면 된다

**AI 코딩의 품질 저하는 모델 탓이 아니라 컨텍스트 과부하 탓이며, GSD는 작업을 서브에이전트로 분산해 각 에이전트가 신선한 컨텍스트에서 시작하도록 보장한다.**
