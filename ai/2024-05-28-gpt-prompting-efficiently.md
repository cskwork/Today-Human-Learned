# GPT 프롬프트 효율적으로 쓰기 — 질문을 잘 써야 답도 좋다

> **TL;DR**
> GPT에게 원하는 결과를 얻으려면 목적·맥락·형식을 구체적으로 명시한 프롬프트를 써야 한다.

---

## 프롬프트 설계를 왜 배워야 하는지 감 잡기

GPT는 입력받은 텍스트에 가장 그럴듯한 다음 텍스트를 생성하는 모델이다. 질문이 모호하면 그럴듯하지만 쓸모없는 답이 나온다. 질문을 잘 쓰면 같은 모델에서 전혀 다른 수준의 결과를 얻는다. 프롬프트 설계는 모델을 바꾸지 않고도 출력 품질을 높이는 가장 빠른 방법이다.

초보자는 처음에 이렇게 이해하면 된다.

`핵심 흐름: 목적 정의 → 맥락 제공 → 출력 형식 지정 → 복잡한 작업은 단계별로 분리`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| 프롬프트(Prompt) | GPT에게 전달하는 입력 텍스트 전체. 질문, 지시, 예시 모두 포함된다. |
| 맥락(Context) | 모델이 답을 좁힐 수 있도록 제공하는 배경 정보. 없으면 모델이 가장 일반적인 답을 낸다. |
| 구체성(Specificity) | 원하는 결과를 얼마나 명확하게 서술했는가. 구체적일수록 노이즈가 줄어든다. |
| 역할 부여(Role prompting) | "너는 시니어 백엔드 엔지니어다"처럼 모델에게 역할을 지정해 답변 스타일을 유도하는 기법. |
| 체인 오브 소트(Chain-of-thought) | "단계별로 생각해봐"라고 지시해 모델이 추론 과정을 드러내며 답하도록 유도하는 방식. |

## 예를 들어 설명하면

같은 주제라도 프롬프트 품질에 따라 결과가 달라진다.

나쁜 프롬프트:
```
블록체인 알려줘.
```

좋은 프롬프트:
```
블록체인 기술의 핵심 원리를 개발 경험이 없는 팀장에게 설명한다고 가정하고,
(1) 왜 기존 데이터베이스와 다른지, (2) 어떻게 데이터 무결성을 보장하는지,
(3) 실제 사용 사례 하나를 포함해 300자 이내로 요약해줘.
```

좋은 프롬프트의 구조를 분해하면:
- **대상 독자** 명시: "개발 경험이 없는 팀장"
- **출력 항목** 번호 지정: (1) (2) (3)
- **분량 제한**: "300자 이내"

## 이 단계에서 중요한 판단 기준

프롬프트를 수정해도 결과가 계속 나쁘다면, 작업을 더 작은 단위로 쪼개서 각각 별도 프롬프트로 처리하는 것이 낫다.

## 한 줄 요약 — 이것만 기억하면 된다

**목적·맥락·형식·분량을 명확히 담은 프롬프트가 모델을 바꾸는 것보다 결과 품질에 더 큰 영향을 준다.**

## 나중에 더 깊게 들어가면

- Few-shot prompting: 예시를 1~5개 넣어 출력 형식을 유도하는 기법
- System prompt와 User prompt의 역할 분리
- 프롬프트 버전 관리와 평가 지표 설정 방법
