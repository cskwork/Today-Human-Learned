# Claude Code Web 등장

> **TL;DR**
> Claude Code가 브라우저에서 실행된다 — 터미널 없이 GitHub 저장소를 연결하고, 클라우드 샌드박스에서 여러 작업을 병렬로 돌릴 수 있다.

---

## Claude Code Web을 왜 쓰는지 감 잡기

기존 Claude Code는 터미널에서 실행되는 로컬 도구였다. 개발 환경이 없는 상황, 즉 다른 기기, 이동 중, 빠른 검토가 필요할 때는 쓰기 어려웠다.

Claude Code Web은 브라우저를 인터페이스로, 클라우드를 실행 환경으로 쓴다. GitHub 저장소를 연결하고 작업을 설명하면 Claude가 클라우드 샌드박스에서 구현한다. 로컬 환경 설정이 필요 없고, 여러 저장소의 작업을 동시에 병렬로 실행할 수 있다는 점이 핵심 차이다.

`핵심 흐름: 브라우저 접속 → GitHub 저장소 연결 → 작업 설명 → 클라우드 샌드박스 실행 → PR 자동 생성`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| 클라우드 샌드박스 | Claude Code가 실행되는 격리된 클라우드 환경 — 파일시스템과 네트워크가 제한되어 안전하다 |
| 보안 프록시 | Claude의 git 요청을 중간에서 검증하는 서비스 — 승인된 저장소에만 접근하게 한다 |
| 병렬 실행 | 여러 저장소나 작업을 동시에 처리하는 것 — 클라우드 실행이기 때문에 가능하다 |
| 연구 프리뷰 | 아직 완성된 제품이 아닌 실험적 출시 단계 — 피드백을 바탕으로 빠르게 개선 중 |
| 커스텀 네트워크 구성 | 샌드박스에서 접근 가능한 도메인을 직접 설정하는 기능 (예: npm 패키지 다운로드 허용) |

## 예를 들어 설명하면

백엔드 버그 수정 시나리오:

1. claude.com/code 접속
2. 수정이 필요한 GitHub 저장소 연결
3. "결제 API에서 502 오류 발생, 원인 파악하고 수정해줘" 입력
4. Claude가 클라우드 샌드박스에서 코드 탐색 → 수정 → 테스트 실행
5. PR 자동 생성 및 변경 요약 제공

이 작업을 하는 동안 다른 저장소의 작업을 동시에 실행할 수 있다. 기다릴 필요가 없다.

## 이 단계에서 중요한 판단 기준

Claude Code Web이 특히 적합한 상황은 "명확하게 정의된 반복 작업, 버그 수정, 테스트 주도 개발로 검증 가능한 백엔드 변경"이다 — 탐색적 아키텍처 작업은 여전히 로컬 터미널 환경이 낫다.

## 한 줄 요약 — 이것만 기억하면 된다

**Claude Code Web은 터미널 없이 브라우저에서 Claude Code를 쓰는 방법이며, 클라우드 병렬 실행이 가장 큰 실용적 장점이다.**

## 나중에 더 깊게 들어가면

- 커스텀 네트워크 구성으로 허용 도메인을 관리하는 방법
- iOS 모바일 앱에서의 Claude Code 사용 경험 (연구 프리뷰 단계)
- 클라우드 샌드박스의 보안 모델 (프록시 검증 구조)
