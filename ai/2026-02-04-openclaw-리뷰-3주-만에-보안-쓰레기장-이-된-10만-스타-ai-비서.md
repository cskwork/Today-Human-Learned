# OpenClaw 리뷰: 3주 만에 보안 쓰레기장이 된 10만 스타 AI 비서

> **TL;DR**
> OpenClaw는 메시징 앱으로 컴퓨터를 원격 조종하는 AI 비서 개념을 제시했지만, 원클릭 원격 코드 실행 취약점과 400개 이상의 악성 스킬로 인해 현재 일반 사용자에게는 설치를 권장하기 어렵다.

---

## OpenClaw를 왜 쓰는지 감 잡기

기존 ChatGPT나 Claude는 대화만 한다. OpenClaw는 직접 행동한다. 텔레그램이나 왓츠앱으로 명령을 내리면 실제로 컴퓨터를 조작해서 파일 정리, 이메일 발송, 코드 실행까지 수행한다. 영화의 AI 비서처럼 "오늘 일정 정리해줘"라고 메시지를 보내면 알아서 처리한다.

2025년 11월 iOS 개발자가 주말 프로젝트로 시작한 이 오픈소스 도구는 3주 만에 GitHub 스타 10만 개를 돌파했고, 맥 미니가 품절되는 현상까지 일어났다. 그런데 폭발적인 인기만큼이나 빠르게 문제점이 드러났다.

초보자는 처음에 이렇게 이해하면 된다.

`핵심 흐름: 메시징 앱 명령 → OpenClaw 수신 → 컴퓨터 직접 조작 → 결과 반환`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| 자율 AI 에이전트 | 사람이 일일이 지시하지 않아도 스스로 판단하고 행동하는 AI 프로그램 |
| 원격 코드 실행(RCE) | 공격자가 피해자 컴퓨터에서 임의의 코드를 실행할 수 있는 취약점. CVSS 8.8이면 매우 심각한 수준 |
| 악성 스킬 | OpenClaw의 기능 확장 모듈인 '스킬'을 위장한 악성코드. 합법적으로 보이지만 비밀번호나 암호화폐 키를 탈취한다 |
| WebSocket origin 검증 | 외부에서 연결 요청이 올 때 출처가 신뢰할 수 있는지 확인하는 보안 절차. OpenClaw는 이를 누락했다 |
| 스캐머 도메인 선점 | 이름이 바뀌는 혼란 속에 공격자들이 관련 도메인과 계정을 먼저 등록해 악성 소프트웨어를 배포하는 수법 |

## 예를 들어 설명하면

OpenClaw는 세 번 이름이 바뀌었다. Clawdbot에서 상표권 문제로 Moltbot, 다시 OpenClaw로. 이름이 바뀌는 혼란 속에 공격자들은 VS Code 마켓플레이스에 "ClawdBot Agent"라는 가짜 확장 프로그램을 올렸다. 사실 OpenClaw에는 공식 VS Code 확장이 없다. 공격자들은 단지 인기와 공식 도구의 부재를 악용했다.

2026년 2월 기준 확인된 보안 이슈 목록이다.

| 취약점 | 심각도 | 상태 |
|---|---|---|
| CVE-2026-25253: 원클릭 원격 코드 실행 | CVSS 8.8 (높음) | 패치 완료 |
| ClawHub 악성 스킬 341개 발견 | 높음 | 대부분 미제거 |
| 커맨드 인젝션 취약점 2건 | 높음 | 패치 완료 |

원클릭 RCE 취약점은 악성 웹페이지를 한 번 방문하는 것만으로 밀리초 단위로 공격이 완료됐다. WebSocket 연결의 origin 헤더를 검증하지 않아 발생한 문제였다. 구글 클라우드 보안 부사장이 "AI 개인 비서로 위장한 악성코드"라고 공개 경고했을 만큼 심각했다.

## 이 단계에서 중요한 판단 기준

컴퓨터 전체에 접근 권한을 주는 소프트웨어는, 그 소프트웨어 자체가 신뢰할 수 있는지부터 확인해야 한다.

## 한 줄 요약 — 이것만 기억하면 된다

**개인 AI 비서의 미래를 보여준 아이디어였지만, 현재 OpenClaw는 보안 위험이 이점을 압도한다. 6개월 후 안정화된 버전을 확인하거나, Claude Code와 기존 자동화 도구의 조합을 먼저 시도하라.**

## 나중에 더 깊게 들어가면

- 자율 AI 에이전트에서 최소 권한 원칙(least privilege)을 적용하는 방법
- WebSocket 보안: origin 검증 및 인증 토큰 방식 비교
- NanoClaw처럼 컨테이너 격리 기반 AI 비서 아키텍처
