# 2025년 주목할 오픈소스 RAG 프레임워크

> **TL;DR**
> RAG는 LLM에 외부 지식을 연결하는 기술이며, 2025년 기준 용도별로 검증된 오픈소스 프레임워크가 여럿 존재한다.

---

## RAG를 왜 쓰는지 감 잡기

LLM은 학습 데이터 기준으로만 답변한다. 최신 뉴스나 사내 문서처럼 학습에 포함되지 않은 정보는 모른다. RAG(Retrieval-Augmented Generation)는 이 문제를 해결한다. 질문이 들어오면 관련 문서를 먼저 검색(retrieve)하고, 그 내용을 LLM에 함께 전달해 더 정확한 답을 생성하게 한다.

초보자는 이렇게 이해하면 된다.

`핵심 흐름: 질문 → 문서 검색 → 관련 문서 + 질문을 LLM에 전달 → 답변 생성`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| RAG | LLM이 답변하기 전에 외부 문서를 검색해서 참고하게 하는 방식 |
| 임베딩(Embedding) | 문서나 질문을 숫자 벡터로 변환해 의미 유사도를 계산할 수 있게 한 것 |
| 벡터 스토어(Vector Store) | 임베딩된 문서를 저장하고 유사한 문서를 빠르게 찾아주는 데이터베이스 |
| 청킹(Chunking) | 긴 문서를 LLM이 처리하기 적합한 크기로 쪼개는 작업 |
| 리랭킹(Reranking) | 검색된 문서를 질문과의 관련성 순서로 다시 정렬하는 후처리 단계 |

## 예를 들어 설명하면

2025년 기준 주요 프레임워크를 용도별로 정리하면 다음과 같다.

| 프레임워크 | 강점 | 적합한 상황 |
|---|---|---|
| LlamaIndex | 300개 이상 통합, 멀티모달 지원 | 범용 AI 지식 어시스턴트 |
| RAGFlow | 복잡한 PDF/DOCX 레이아웃 파싱, DeepDoc OCR | 문서 중심 애플리케이션 |
| LightRAG | 지식 그래프 + 벡터 검색 결합, 경량 | 제한된 하드웨어 환경 |
| STORM | 인터넷 검색 기반 리포트 자동 생성 | 리서치 자동화 |
| LLMWare | 소형 특화 모델 활용, 노트북에서 실행 가능 | 엔터프라이즈 온프레미스 |
| Haystack | 파이프라인 오케스트레이션, 프로덕션 검증 | 대규모 운영 환경 |

## 이 단계에서 중요한 판단 기준

프레임워크를 고를 때 가장 먼저 물어야 할 것은 "문서가 복잡한가, 하드웨어가 제한적인가, 프로덕션 규모인가" 이 세 가지다.

## 한 줄 요약 — 이것만 기억하면 된다

**RAG 프레임워크 선택은 데이터 복잡도와 하드웨어 제약에 따라 달라지며, 2025년에는 용도별로 검증된 오픈소스 선택지가 충분히 존재한다.**

## 나중에 더 깊게 들어가면

- RAGAs를 사용한 RAG 파이프라인 평가 지표(Groundedness, Context Relevance, Answer Relevance)
- 그래프 기반 RAG(GraphRAG, LightRAG)와 벡터 기반 RAG의 성능 차이
- 멀티모달 RAG — 이미지와 표가 포함된 문서 처리 전략
