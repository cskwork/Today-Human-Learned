# GPT-5 프롬프팅 가이드

> **TL;DR**
> GPT-5는 지시를 잘 따르고 도구 호출에 강하지만, 모호한 지시나 과도한 탐색 요구에는 비효율적으로 반응한다. 프롬프트로 적극성, 말수, 추론 강도를 세밀하게 조율할 수 있다.

---

## GPT-5 프롬프팅을 왜 따로 배워야 하는지 감 잡기

GPT-5는 에이전트형 작업, 코딩, 지시 준수 면에서 이전 모델보다 크게 향상됐다. 그런데 "그냥 쓰면" 문제가 생긴다. 어떤 상황에서는 필요 이상으로 많은 도구를 호출하고, 어떤 상황에서는 사용자 확인을 과도하게 요청한다. 지시가 모호하면 추론 토큰을 낭비하면서 시간이 늘어난다.

GPT-5는 "가장 잘 조종(steer)되는 모델"이라는 평가를 받는다. 프롬프트로 모델의 행동 방식을 직접 제어할 수 있다는 뜻이다. 이 가이드는 그 제어 방법을 정리한다.

초보자는 이렇게 이해하면 된다.

`핵심 흐름: 작업 성격 파악 → 적극성 수준 결정 → 프롬프트로 행동 조율 → Responses API로 효율화`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| reasoning_effort | 모델이 생각에 얼마나 깊이 투자할지 조절하는 파라미터 (low / medium / high) |
| Agentic eagerness | 모델이 스스로 도구를 호출하고 탐색을 이어가려는 적극성 정도 |
| Verbosity | API에서 모델 응답의 길이를 제어하는 파라미터 (텍스트 길이, 사고 깊이와는 별개) |
| Tool preamble | 도구 호출 전 모델이 의도와 계획을 짧게 설명하는 중간 업데이트 |
| Responses API | 이전 추론 흔적(previous_response_id)을 다음 요청으로 넘겨 컨텍스트를 재사용하는 API |

## 예를 들어 설명하면

도구 호출이 불필요하게 많아지는 문제를 프롬프트로 해결하는 예시다.

```xml
<context_gathering>
  Goal: Get enough context fast. Parallelize discovery and stop as soon as you can act.
  Early stop criteria:
  - You can name exact content to change.
  - Top hits converge (~70%) on one area/path.
  Search depth: very low — maximum 2 tool calls.
  If you need more time, update the user and wait for confirmation.
</context_gathering>
```

반대로, 모델이 끝까지 자율적으로 수행하길 원할 때는 persistence 프롬프트를 사용한다.

```xml
<persistence>
  Keep going until the user's query is completely resolved.
  Never stop when uncertain — deduce the most reasonable approach and continue.
  Do not ask for clarification; decide and document your assumptions after acting.
</persistence>
```

## 이 단계에서 중요한 판단 기준

프롬프트에 상충하는 지시가 있으면 GPT-5는 이를 해소하려고 추론 토큰을 낭비하므로, 시스템 프롬프트의 모순과 애매성을 정기적으로 점검해야 한다.

## 한 줄 요약 — 이것만 기억하면 된다

**GPT-5는 지시를 정밀하게 따르는 모델이므로, 적극성-말수-추론 강도를 프롬프트로 명시적으로 제어할수록 원하는 결과에 가까워진다.**

## 나중에 더 깊게 들어가면

- Responses API의 previous_response_id로 멀티턴 에이전트 비용 줄이기
- minimal reasoning effort 모드에서 계획 유도 프롬프트 설계
- 메타프롬프팅: GPT-5에게 자신의 프롬프트를 개선하게 하는 방법
