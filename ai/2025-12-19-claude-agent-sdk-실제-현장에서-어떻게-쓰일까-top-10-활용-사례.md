# Claude Agent SDK: 실제 현장에서 어떻게 쓰이나

> **TL;DR**
> Claude Agent SDK는 챗봇이 아닌 자율 에이전트를 만드는 프레임워크다. 파일 읽기, 코드 실행, 외부 API 연동을 결합해 고객 지원부터 보안 감사까지 실무 워크플로우를 자동화한다.

---

## Claude Agent SDK를 왜 쓰는지 감 잡기

일반 LLM API는 질문에 답하는 수준이다. 반면 Claude Agent SDK는 터미널에 접근하고, 파일을 생성하며, 외부 시스템과 직접 연동해 작업을 완료한다. Claude Code를 구동하는 것과 동일한 에이전트 하네스가 SDK 형태로 제공된 것이다.

2025년 9월 Anthropic은 Claude Code SDK를 Claude Agent SDK로 리브랜딩했다. 코딩 외에도 딥 리서치, 문서 분석, 데이터 변환 등 거의 모든 에이전트 루프를 구동하기 시작했기 때문이다. 기존 LLM API와의 결정적 차이는 자동 컨텍스트 관리(토큰 한계 도달 시 자동 요약), MCP를 통한 외부 서비스 연동, Hooks를 통한 도구 실행 전후 검증이다.

초보자는 처음에 이렇게 이해하면 된다.

`핵심 흐름: 도구 등록(MCP/커스텀) → 에이전트 실행 → Hooks로 안전망 적용 → 결과 저장`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| MCP | AI가 Slack, GitHub, DB 같은 외부 시스템과 연결할 때 쓰는 표준 프로토콜 |
| Hooks | 도구 실행 전후에 삽입하는 검증 로직. `rm -rf` 같은 위험 명령을 차단할 때 활용 |
| Files API | 문서나 정책 파일을 에이전트에 첨부해 참조하게 하는 기능 |
| 서브에이전트 | 메인 에이전트가 특정 역할(보안 리뷰어 등)을 별도 컨텍스트로 분리해 실행하는 구조 |
| 자동 컨텍스트 관리 | 대화가 길어져 토큰 한계에 도달하면 이전 내용을 자동으로 요약하는 기능 |

## 예를 들어 설명하면

고객 지원 에이전트(하루 300건 처리)는 이렇게 구성된다. MCP 커넥터로 CRM과 티켓 시스템에 연결하고, Files API로 응답 템플릿을 로드한다. 티켓이 들어오면 자동 분류 후 템플릿을 적용하거나, 복잡한 건은 사람에게 에스컬레이션한다.

보안 감사 에이전트는 서브에이전트 패턴을 쓴다.

```python
with agent.subagent(
    system="You are a code reviewer focused on security.",
    tools=[security_scan_tool]
) as reviewer:
    review = reviewer.run("Review this code for vulnerabilities")
```

보안 리뷰어를 격리된 컨텍스트에서 실행해 메인 에이전트의 편향 없이 분석한다.

대규모 코드 마이그레이션(수백 파일 리팩토링)에는 배치 스크립트 방식이 맞다. `claude -p "in /pathA change all refs from foo to bar"` 형태로 병렬 호출하면 인터랙티브 세션으로는 감당하기 어려운 작업을 처리할 수 있다.

## 이 단계에서 중요한 판단 기준

SRE 장애 대응처럼 시스템을 수정하는 에이전트는 반드시 인간 승인 단계를 포함해야 한다. `max-turns` 설정으로 무한 루프도 방지해야 한다.

## 한 줄 요약 — 이것만 기억하면 된다

**가장 단순한 단일 사용 사례로 프로토타입을 시작하고, 실제 데이터로 검증한 뒤 점진적으로 확장하는 것이 검증된 접근법이다.**

## 나중에 더 깊게 들어가면

- MCP 서버 인증과 OAuth 연동 설정
- 프롬프트 캐싱으로 반복 컨텍스트 비용 절감하기
- role-based 권한 설계와 에이전트 간 신뢰 경계 설정
