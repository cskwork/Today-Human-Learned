# 클로드 Agent 스킬 소개

> **TL;DR**
> Claude 스킬은 전문 지식을 파일로 패키징해 Claude 앱, API, Claude Code 어디서나 자동으로 불러 쓸 수 있는 재사용 가능한 지식 단위다.

---

## 스킬을 왜 쓰는지 감 잡기

Claude는 기본적으로 범용 어시스턴트다. 하지만 실무에서는 "우리 팀만 아는 방식", "특정 파일 형식", "반복되는 워크플로우"가 필요하다. 매번 긴 프롬프트로 이걸 설명하는 건 비효율적이다.

스킬은 이 문제를 해결한다. 전문 지식을 한 번 파일로 정리해두면, Claude가 관련 작업을 감지할 때 자동으로 그 파일을 불러온다. 신입 사원 온보딩 가이드를 만들어두면, 누가 와도 그 가이드대로 움직이는 것과 같다.

`핵심 흐름: 스킬 파일 작성 → Claude가 작업 감지 → 필요한 스킬만 자동 로드 → 작업 수행`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| 스킬(Skill) | 특정 작업에 필요한 지침, 스크립트, 리소스를 담은 폴더 단위 |
| SKILL.md | 스킬의 핵심 파일 — 이름, 설명, 지침을 담고 있으며 Claude가 이걸 읽어 스킬을 인식한다 |
| 점진적 공개 | Claude가 스킬 내용을 한꺼번에 읽지 않고, 필요한 부분만 단계적으로 불러오는 방식 |
| 이식성 | 한 번 만든 스킬을 Claude 앱, API, Claude Code 어디서나 동일하게 쓸 수 있다는 특성 |
| Code Execution Tool | 스킬 내 Python 스크립트 등을 Claude가 실행할 수 있게 해주는 보안 실행 환경 |

## 예를 들어 설명하면

팀에서 매주 주간 보고서를 특정 형식으로 작성한다고 하자. 이 형식을 SKILL.md에 적어두면:

```
my-skills/
  weekly-report/
    SKILL.md        ← "이 스킬은 주간 보고서 작성을 돕습니다"라는 설명 포함
    template.md     ← 실제 보고서 템플릿
    rules.md        ← 작성 규칙 (Claude가 보고서 작성 시에만 읽음)
```

Claude는 "주간 보고서 써줘"라는 요청을 받으면 weekly-report 스킬을 감지하고 SKILL.md → template.md → rules.md 순으로 필요한 파일만 순차적으로 읽는다. 컨텍스트 낭비 없이 정확히 필요한 정보만 쓴다.

## 이 단계에서 중요한 판단 기준

스킬을 쓸지 말지 고민된다면, "이 작업이 반복되고 전문적인 절차가 필요한가?"를 먼저 물어라 — 반복성과 절차성이 모두 있으면 스킬로 만들 가치가 있다.

## 한 줄 요약 — 이것만 기억하면 된다

**스킬은 "Claude를 위한 팀 온보딩 문서"다 — 한 번 잘 써두면 어디서나 자동으로 작동한다.**

## 나중에 더 깊게 들어가면

- SKILL.md의 YAML 프론트매터 구조와 메타데이터 작성법
- 스킬 안에 Python 스크립트를 넣어 결정론적 작업을 처리하는 방법
- 조직 전체에 스킬을 배포하는 Team/Enterprise 관리자 설정
