# GPT-5.3 Codex-Spark — AI 코딩의 병목은 '지능'이 아니라 '속도'였다

> **TL;DR**
> OpenAI가 Cerebras WSE-3 칩 위에서 동작하는 실시간 코딩 모델 Codex-Spark를 공개했다. 기존 Codex 대비 15배 빠른 생성 속도로, AI 코딩 도구의 경쟁 축이 '얼마나 똑똑한가'에서 '얼마나 빠른가'로 바뀌었다.

---

## Codex-Spark를 왜 만들었는지 감 잡기

AI 코딩 도구를 쓰다 보면 집중이 끊기는 순간이 있다. 변수 이름 하나 바꾸는 데 수 초를 기다리는 그 시간이다. 이 문제의 원인은 모델이 멍청해서가 아니다. 무거운 모델과 연결 방식이 짧은 작업에도 같은 파이프라인을 거치기 때문이다.

GPT-5.3-Codex 같은 최상위 모델은 수 시간 분량의 자율 작업이 가능할 만큼 강력하다. 그런데 "이 함수 이름 바꿔줘" 같은 요청에도 같은 시스템을 거쳐야 했다. 편의점 우유 하나 사러 대형 트레일러를 모는 격이다.

Codex-Spark는 이 불균형을 해결한다. 모델 자체를 실시간 상호작용에 맞게 경량화하고, 하드웨어도 근본적으로 교체했다.

`핵심 흐름: 경량화된 모델 → 웨이퍼 스케일 칩 → 초당 1,000+ 토큰 → 작업 흐름 유지`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| Cerebras WSE-3 | 반도체 웨이퍼 한 장 전체를 하나의 칩으로 만든 AI 전용 하드웨어. 일반 GPU보다 온칩 메모리가 압도적으로 크다. |
| 온칩 SRAM | 칩 안에 내장된 초고속 메모리. 외부 메모리(HBM)로 나갔다 오는 시간을 없애 응답 속도를 높인다. |
| TTFT (첫 토큰 출력 시간) | AI가 응답을 시작하기까지 걸리는 시간. 짧을수록 사용자 집중이 끊기지 않는다. |
| WebSocket | HTTP와 달리 한 번 연결하면 계속 데이터를 주고받는 연결 방식. 짧은 반복 작업에서 누적 지연을 줄인다. |
| SWE-Bench Pro | AI 모델이 실제 소프트웨어 엔지니어링 작업을 얼마나 잘 해결하는지 측정하는 벤치마크. |

## 예를 들어 설명하면

Codex-Spark가 빠른 이유는 하드웨어 구조에서 온다. 일반 GPU는 모델 가중치를 외부 HBM에 저장하고, 연산할 때마다 칩 밖으로 데이터를 가져온다. WSE-3는 모델의 작업 데이터 상당 부분을 칩 내부 44GB SRAM에 직접 보관한다.

| 항목 | Cerebras WSE-3 | NVIDIA B200 |
|---|---|---|
| 온칩 메모리 | 44GB (SRAM) | 수 GB (SRAM 기준) |
| 내부 메모리 대역폭 | 21 PB/s | 약 3 TB/s |
| 다이 면적 | 46,225 mm2 | 약 800 mm2 |

코딩 모델처럼 짧은 응답을 반복하는 워크로드에서 이 차이가 TTFT를 극적으로 줄인다. 인프라 측면에서도 HTTP 연결을 WebSocket으로 교체해 클라이언트-서버 왕복 오버헤드를 80% 줄였다.

벤치마크 결과를 보면, Codex-Spark는 Terminal-Bench 2.0에서 58.4%를 기록했다. 풀사이즈 GPT-5.3-Codex(77.3%)보다 낮지만, GPT-5.1-Codex-mini(46.1%)는 크게 앞선다. "충분히 똑똑하면서 극도로 빠른" 위치다.

## 이 단계에서 중요한 판단 기준

Codex-Spark는 변수명 수정, UI 빠른 프로토타이핑, 반복 리팩토링처럼 짧고 빈번한 작업에 쓰고, 리포지토리 전체 분석이나 복잡한 버그 추적은 GPT-5.3-Codex에 맡기는 것이 맞다.

## 한 줄 요약 — 이것만 기억하면 된다
