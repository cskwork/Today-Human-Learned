# AI 코딩이 매번 다르게 나온다면 — Archon 하네스 빌더

> **TL;DR**
> Archon은 AI 코딩 절차를 YAML 워크플로우로 고정해, 같은 작업을 같은 순서로 재현 가능하게 만들어 주는 오픈소스 하네스 빌더다.

---

## Archon을 왜 쓰는지 감 잡기

AI 어시스턴트에게 똑같은 지시를 내려도 어떤 날은 PR까지 올리고, 어떤 날은 중간에 멈춘다. 이른바 '비결정성'이다. 프로토타입에서는 무시할 수 있지만, 팀이 공통으로 반복하는 작업에서는 품질 저하의 원인이 된다. Archon은 AI 판단이 필요한 단계와 셸 명령처럼 고정된 단계를 YAML로 구분해 못 박아 두고, 매번 동일한 순서로 실행되도록 강제한다. 제작자는 "Dockerfile이 인프라에 해준 일을 AI 코딩 워크플로우에 한다"고 설명한다. TypeScript + Bun 기반으로 2026년 4월 완전 재작성됐으며, GitHub 스타 1.8만 개를 넘겼다.

초보자는 처음에 이렇게 이해하면 된다.

`핵심 흐름: YAML 작성 → 노드 순서 정의 → AI 판단 단계 + 결정적 명령 단계 배치 → 동일 실행 반복`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| 하네스 (Harness) | AI 모델 호출을 감싸 절차, 검증, 출력 형식을 강제하는 외부 골격이다. |
| 결정적 노드 | `bash:` 처럼 매번 동일하게 실행되는 고정 명령 단계다. |
| AI 노드 | `prompt:` 로 AI가 판단을 채워 넣는 단계다. 실행 순서는 고정이지만 내용은 AI가 생성한다. |
| 워크플로우 | 노드들의 의존 관계를 YAML로 기록한 실행 계획서다. `.archon/workflows/`에 커밋해 공유한다. |
| git worktree | 각 실행이 별도로 격리된 작업 디렉터리. 병렬 실행 시 서로 간섭하지 않는다. |

## 예를 들어 설명하면

아래는 Archon 공식 README의 가장 작은 예시다. `depends_on`으로 실행 순서를 잠그고, `loop + until`로 반복 종료를 명시하며, `bash:`로 검증 단계를 삽입한다.

```yaml
# .archon/workflows/sample.yaml
nodes:
  - id: plan
    prompt: "Explore the codebase and create an implementation plan"
  - id: implement
    depends_on: [plan]
    loop:
      prompt: "Read the plan. Implement the next task. Run validation."
      until: ALL_TASKS_COMPLETE
  - id: run-tests
    depends_on: [implement]
    bash: "bun run validate"
  - id: create-pr
    depends_on: [run-tests]
    prompt: "Push changes and create a pull request"
```

Claude Code 세션에서 `Use archon to add dark mode to the settings page`라고 말하면 라우터가 17개 기본 워크플로우 중 적합한 것을 자동 선택해 실행한다.

## 이 단계에서 중요한 판단 기준

탐색 단계에서는 자유 프롬프팅으로 방향을 잡고, 안정화된 반복 작업만 Archon 워크플로우로 고정하는 것이 자연스러운 분업이다.

## 한 줄 요약 — 이것만 기억하면 된다

**Archon은 AI 코딩의 "지능"은 그대로 두되, 실행 순서와 검증을 YAML로 고정해 팀 단위 재현성을 확보한다.**

## 나중에 더 깊게 들어가면

- 커스텀 워크플로우 작성 방법과 노드 타입 전체 목록
- Web 대시보드(`archon serve`)로 실행 상태를 실시간 모니터링하는 방법
- Slack, Telegram, GitHub에서 동일 워크플로우를 원격 트리거하는 설정
