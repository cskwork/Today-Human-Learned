# Aider 명령어 치트시트

> **TL;DR**
> Aider의 인-채팅 명령어는 파일 관리, git 연동, 모델 전환, 셸 실행을 모두 `/명령어` 형태로 처리한다. 가장 자주 쓰는 명령어 10개만 알면 실무에서 충분하다.

---

## Aider 명령어를 왜 알아야 하는지 감 잡기

Aider는 터미널 채팅 인터페이스다. 자연어 요청 외에도 `/add`, `/commit` 같은 슬래시 명령어로 파일을 컨텍스트에 올리거나 git 작업을 제어한다. 이 명령어를 모르면 Aider를 절반만 쓰는 셈이다.

핵심 흐름: `파일 추가(/add) → 자연어 요청 → 코드 수정 확인(/diff) → 커밋(/commit) → 문제 시 롤백(/undo)`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| 컨텍스트 (Context) | Aider가 현재 세션에서 알고 있는 파일 목록. /add로 추가, /drop으로 제거 |
| /add | 특정 파일을 컨텍스트에 포함시켜 모델이 읽고 수정할 수 있게 한다 |
| /commit | Aider 밖에서 직접 수정한 파일 변경사항을 git에 기록한다 |
| /undo | Aider가 마지막으로 만든 git commit을 되돌린다. 잘못된 수정의 탈출구 |
| 토큰 (Token) | LLM이 처리하는 텍스트 단위. /tokens로 현재 컨텍스트 소모량을 확인한다 |

## 예를 들어 설명하면

파일 하나를 수정하고 결과를 검토하는 일반적인 작업 흐름이다.

```
/add src/utils.py          # utils.py를 컨텍스트에 올림
> 이 파일의 calculate 함수를 최적화해줘
/diff                      # 변경된 내용을 줄 단위로 확인
/lint src/utils.py         # 린트 오류 자동 수정
/commit "refactor: optimize calculate function"
/undo                      # 결과가 마음에 안 들면 즉시 롤백
```

## 전체 명령어 한눈에 보기

| 명령어 | 기능 |
|---|---|
| /add | 파일을 컨텍스트에 추가 |
| /drop | 파일을 컨텍스트에서 제거 |
| /ls | 알고 있는 파일 목록과 컨텍스트 포함 여부 출력 |
| /clear | 채팅 히스토리 초기화 |
| /diff | 마지막 Aider 커밋의 변경사항 출력 |
| /commit | 채팅 밖 변경사항을 git에 기록 |
| /undo | 마지막 Aider 커밋 롤백 |
| /lint | 파일 린트 검사 및 자동 수정 |
| /run | 셸 명령 실행, 결과를 채팅에 추가 (! 단축키 사용 가능) |
| /test | 셸 명령 실행, 비정상 종료 시에만 결과를 채팅에 기록 |
| /tokens | 현재 컨텍스트의 토큰 사용량 보고 |
| /model | 다른 LLM으로 전환 |
| /models | 사용 가능한 모델 목록 검색 |
| /git | git 명령 직접 실행 |
| /voice | 음성 입력 녹음 및 텍스트 변환 |
| /web | headless Selenium으로 웹 페이지 내용을 컨텍스트에 추가 |
| /help | 전체 명령어 도움말 |
| /exit, /quit | Aider 종료 |

## 이 단계에서 중요한 판단 기준

컨텍스트가 커질수록 토큰 비용이 늘고 모델 성능이 저하될 수 있다. `/ls`로 현재 컨텍스트를 확인하고, 불필요한 파일은 `/drop`으로 정리하는 습관이 중요하다.

## 한 줄 요약 — 이것만 기억하면 된다

**Aider에서 /add → 요청 → /diff → /commit → /undo 흐름만 익히면 일상적인 코딩 작업의 80%를 커버한다.**

## 나중에 더 깊게 들어가면

- `/web` 명령으로 외부 문서를 컨텍스트에 실시간으로 포함하는 방법
- `.aider.conf.yml`로 자주 쓰는 설정과 파일 목록을 미리 지정하는 방법
- `/model` 명령으로 태스크별 최적 모델(GPT-4o vs Claude 3.5 Sonnet 등)을 선택하는 기준
