# 코딩 에이전트로 더 빠르게 배우고 더 잘 만드는 법

> **TL;DR**
> 에이전트 하나에 모든 것을 맡기지 말고, 계획 에이전트와 구현 에이전트를 분리해 작은 기능 단위로 반복하면 학습과 품질이 동시에 올라간다.

---

## 왜 이 방법이 필요한지 감 잡기

"앱 하나 만들어줘"라고 단일 에이전트에 던지면 수백 개의 파일과 무거운 아키텍처가 생성되고, 대부분 실패하거나 유지보수 불가 상태가 된다. 스펙을 미리 작성하면 성공률이 올라가지만, 에이전트가 모든 것을 혼자 처리하면 개발자가 실제로 배우는 것이 없다. 여기서 Plan → Implement → Verify 루프가 필요해진다.

초보자는 이렇게 이해하면 된다.

`핵심 흐름: 계획 에이전트와 대화 → 원자 기능 단위 분리 → 구현 에이전트 실행 → 계획 에이전트로 검증 → 반복`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| 원자 기능 (Atomic Feature) | 독립적으로 동작하고 몇 분 안에 테스트할 수 있는 최소 기능 단위 — API 엔드포인트 하나, UI 패널 하나 |
| 계획 에이전트 (Planning Agent) | 요구사항을 명확히 하고 구현 계획을 생성하는 에이전트 — 구현 에이전트와 반드시 분리한다 |
| 구현 에이전트 (Implementation Agent) | 계획을 받아 코드를 작성하는 에이전트 — Claude, Copilot 등이 해당한다 |
| 검증 단계 (Verification) | 각 기능을 구현한 뒤 원래 계획 기준으로 결과를 점검하는 단계 — 회귀(regression) 방지가 목적이다 |
| 파일 수준 계획 (File-level Plan) | 어떤 파일을 만들고 각 파일에 무엇이 들어가는지 미리 정의한 목록 |

## 예를 들어 설명하면

목표: HTML 프론트엔드 + Python 백엔드로 이미지 생성 앱 만들기.

1. 계획 에이전트에게 "Gemini 이미지 API를 Python으로 호출하는 앱을 만들 계획을 잡아줘"라고 요청한다. 에이전트가 되묻는 질문("백엔드 언어는?", "이미지 몇 장?")에 답하며 요구사항을 명확히 한다.
2. 에이전트가 파일 목록과 각 파일의 역할을 포함한 구현 계획을 내놓는다.
3. 구현 에이전트(Claude/Copilot)에 그 계획을 넘겨 코드를 생성한다.
4. API 단일 호출로 이미지 4장을 동시에 받으려 했지만 API가 지원하지 않아, 4개의 개별 호출로 전략을 바꿨다 — 이런 현실적 조정이 발생한다.
5. 계획 에이전트로 결과를 검증하고 다음 기능으로 넘어간다.

## 이 단계에서 중요한 판단 기준

기능 하나를 구현하기 전에 "이것을 독립적으로 테스트할 수 있는가"를 먼저 확인하라 — 그렇지 않으면 범위를 더 쪼개야 한다.

## 한 줄 요약 — 이것만 기억하면 된다

**계획 에이전트와 구현 에이전트를 분리하고, 한 번에 기능 하나씩 Plan → Implement → Verify 루프를 돌리는 것이 핵심이다.**

## 나중에 더 깊게 들어가면

- 계획 에이전트에 웹 검색을 붙여 최신 API 문서를 자동으로 반영하는 방법
- 여러 기능을 병렬로 구현할 때 회귀를 막는 통합 테스트 설계
- Tracer 같은 IDE 확장 도구로 Plan → Implement → Verify 루프를 자동화하는 방법
