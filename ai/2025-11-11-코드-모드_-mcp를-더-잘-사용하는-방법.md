# 코드 모드: MCP를 더 잘 사용하는 방법

> **TL;DR**
> AI 에이전트에게 MCP 도구를 직접 주는 것보다, 그 도구를 호출하는 코드를 작성하게 하면 더 정확하고 효율적이다.

---

## 코드 모드를 왜 쓰는지 감 잡기

MCP(Model Context Protocol)는 AI 에이전트가 외부 시스템(검색, 파일, API 등)에 접근하는 표준 방식이다. 지금까지 대부분의 에이전트는 이 도구를 LLM에 직접 노출했다. AI가 "get_weather 함수를 호출해줘"라는 식으로 특수 토큰을 사용해 도구를 직접 실행하는 방식이다.

문제는 LLM이 이 "도구 호출" 방식에 익숙하지 않다는 것이다. 학습 데이터에 실제 TypeScript나 Python 코드는 수백만 건이지만, 도구 호출 형식의 예시는 상대적으로 적다. 결과적으로 도구가 복잡해지거나 개수가 늘어날수록 에이전트의 정확도가 떨어진다.

코드 모드는 방향을 바꾼다. MCP 도구를 TypeScript API로 변환한 뒤, AI에게 이 API를 호출하는 코드를 작성하도록 한다. 코드 작성은 LLM이 이미 잘하는 일이다.

초보자는 처음에 이렇게 이해하면 된다.

`핵심 흐름: MCP 도구 → TypeScript API 변환 → AI가 코드 작성 → 샌드박스 실행 → 결과 반환`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| MCP (Model Context Protocol) | AI 에이전트가 외부 도구와 대화하는 표준 규약 — API 연결, 문서, 인증을 통합 제공 |
| 도구 호출 (Tool Call) | AI가 특수 토큰을 써서 외부 함수를 직접 실행하는 방식 |
| 코드 모드 (Code Mode) | MCP 도구를 TypeScript API로 변환해, AI가 코드로 도구를 오케스트레이션하는 방식 |
| 아이솔레이트 (Isolate) | V8 엔진 기반의 초경량 샌드박스 — 컨테이너보다 빠르고, 수 밀리초 안에 시작 |
| 바인딩 (Binding) | Workers 환경에서 API 키 없이 인증된 리소스에 직접 접근하는 객체 |

## 예를 들어 설명하면

기존 방식에서는 날씨 정보를 얻기 위해 AI가 아래와 같은 특수 토큰을 생성한다.

```
<|tool_call|>
{ "name": "get_current_weather", "arguments": { "location": "Austin, TX" } }
<|end_tool_call|>
```

코드 모드에서는 `codemode` 헬퍼를 사용해 같은 흐름을 코드로 바꾼다.

```typescript
import { codemode } from "agents/codemode/ai";

const { system, tools } = codemode({
  system: "You are a helpful assistant",
  tools: { /* MCP 도구 정의 */ }
});

const stream = streamText({ model: openai("gpt-5"), system, tools, messages });
```

이 변경 하나로, 에이전트는 도구를 직접 호출하는 대신 도구를 호출하는 코드를 생성하고 실행하기 시작한다. 여러 도구를 연결할 때는 중간 결과가 LLM을 거치지 않고 코드 안에서 바로 처리된다.

## 이 단계에서 중요한 판단 기준

도구 호출을 여러 번 연결해야 하는 에이전트라면, 직접 도구 호출 대신 코드 모드로 전환하는 것이 토큰과 정확도 양쪽에서 유리하다.

## 한 줄 요약 — 이것만 기억하면 된다

**AI는 도구를 직접 호출하는 것보다 도구를 호출하는 코드를 작성하는 데 더 능숙하다.**

## 나중에 더 깊게 들어가면

- Worker Loader API — 온디맨드로 아이솔레이트를 동적으로 로드하는 방식
- 바인딩을 통한 API 키 유출 방지 메커니즘
- MCP 스키마를 TypeScript 인터페이스로 자동 변환하는 방법
