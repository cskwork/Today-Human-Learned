# Claude의 'Think' 도구 - AI의 복잡한 문제 해결 능력 강화하기

> **TL;DR**
> Think 도구는 Claude가 행동하기 전에 중간 생각을 기록할 수 있는 전용 메모 공간이며, 다단계 추론이 필요한 복잡한 작업에서 오류를 줄인다.

---

## Think 도구를 왜 쓰는지 감 잡기

AI 모델은 도구를 연속으로 호출할 때 이전 결과를 잘못 해석하거나, 정책을 빠뜨리거나, 앞선 판단과 모순되는 결정을 내리는 실수를 한다. Think 도구는 이 문제를 정면으로 해결한다. Claude가 다음 행동을 결정하기 전에 생각을 글로 정리할 수 있는 공간을 제공하는 것이다.

Extended Thinking(응답 생성 이전의 내부 사전 계획)과는 다르다. Think 도구는 도구 호출 결과를 받은 직후, 즉 실행 중간에 삽입된다. 수학 풀이를 할 때 계산 과정을 종이에 적으면서 다음 단계를 결정하는 것과 같은 원리다.

`핵심 흐름: 도구 결과 수신 → Think로 중간 검증 → 다음 행동 결정`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| Think 도구 | Claude가 내부 메모를 남기기 위해 호출하는 특수 함수. 외부 상태를 바꾸지 않는다. |
| Extended Thinking | 응답 생성 전 심층 계획 단계. Think 도구와 달리 실행 흐름 밖에서 작동한다. |
| Agentic 루프 | Claude가 도구를 반복적으로 호출하면서 목표를 달성해 나가는 실행 구조. |
| 시스템 프롬프트 | Claude에게 역할과 규칙을 알려주는 사전 지시문. Think 활용 예시를 여기에 담는다. |
| tau-bench | 고객 서비스 시나리오 기반 벤치마크. Think 도구의 효과를 측정하는 데 사용됐다. |

## 예를 들어 설명하면

항공권 취소를 처리하는 AI 에이전트 시나리오다.

```python
def process_cancellation(request):
    # Think 도구 없이: 바로 취소 실행 -> 규칙 누락 가능
    # Think 도구 활용:
    think("취소 요청 수신. 체크 사항: "
          "1) 예약 후 24시간 이내인지 "
          "2) 티켓 등급 및 보험 여부 "
          "3) 이미 탑승한 구간 존재 여부")
    # 검증 완료 후 실제 취소 처리
```

tau-bench 결과에서 항공사 도메인 기준, 기본 Claude 대비 Think + 최적화 프롬프트 조합이 54% 성능 향상을 보였다.

## 이 단계에서 중요한 판단 기준

Think 도구는 단일 도구 호출이나 간단한 지시만 있는 작업에는 효과가 없다. 순차적 도구 체인, 복잡한 정책 준수, 여러 조건을 동시에 검증해야 하는 상황에서만 투입하라.

## 한 줄 요약 - 이것만 기억하면 된다
