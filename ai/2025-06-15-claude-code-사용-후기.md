# Claude Code 사용 후기 — 강력하지만 검증이 필수인 도구

> **TL;DR**
> Claude Code는 확률적 텍스트 생성기다 — 명확한 명세, 단위 테스트, 그리고 반드시 직접 실행해보는 검증 루프 없이는 안전하게 쓸 수 없다.

---

## Claude Code의 한계를 왜 알아야 하는지 감 잡기

Claude Code를 처음 쓰면 인상적인 결과에 감탄한다. 그런데 쓰다 보면 "Claude가 테스트 통과했다고 했는데 실제로 돌려보니 오류가 난다"는 경험을 하게 된다.

이 도구의 본질을 이해하면 이런 실수를 피할 수 있다. Claude는 학습 데이터 기반으로 다음에 올 텍스트를 예측하는 생성기다. 같은 프롬프트라도 결과가 매번 조금씩 달라지고, 버그가 섞인 코드를 자신감 있게 내놓을 수 있다. 명세를 검증하는 형식적 합성 도구와는 근본적으로 다르다.

초보자는 이렇게 이해하면 된다.

`핵심 흐름: 명확한 명세 작성 → 단위 테스트 먼저 정의 → Claude가 테스트 통과하도록 코드 생성 → 개발자가 직접 실행 검증`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| 확률적 생성 | 같은 입력에도 출력이 매번 조금씩 달라질 수 있는 AI의 특성 |
| 환각(Hallucination) | AI가 존재하지 않는 함수나 잘못된 정보를 자신감 있게 출력하는 현상 |
| TDD (테스트 주도 개발) | 구현 전에 테스트를 먼저 작성하고, 그 테스트를 통과하도록 코드를 만드는 방식 |
| 프롬프트 = 명세 | Claude에게 주는 지시가 곧 기능 명세다 — 모호하면 모호한 코드가 나온다 |
| 세분화 요청 | 큰 작업 하나보다 작은 단위로 쪼개 요청할수록 정확도가 높아진다 |

## 예를 들어 설명하면

"멋진 로그인 기능 만들어줘"는 나쁜 프롬프트다. Claude가 무엇이든 생성하겠지만, 그게 맞는지 확인할 기준이 없다.

올바른 접근은 이렇다.

1. 먼저 단위 테스트로 원하는 동작을 정의한다.
2. Claude에게 "이 테스트를 통과하는 코드를 작성해줘"라고 요청한다.
3. Claude가 완료했다고 해도 반드시 직접 `pytest` 또는 `npm test`를 실행한다.
4. 실패하면 오류 메시지를 Claude에게 다시 주고 수정을 요청한다.

Claude를 알고리즘 후보 비교, 코드 리뷰, 문서화 같은 보조 작업에 쓸 때도 기준과 예시를 구체적으로 제공할수록 결과가 정확해진다.

## 이 단계에서 중요한 판단 기준

Claude가 "완료했다", "테스트 통과했다"고 말해도 항상 직접 실행해서 확인해야 한다 — Claude의 확인은 다음 텍스트 예측일 뿐, 실제 실행 결과가 아니다.

## 한 줄 요약 — 이것만 기억하면 된다

**Claude Code는 강력하지만 신뢰할 수 없는 생성기다 — 명확한 명세와 촘촘한 테스트, 그리고 반드시 직접 실행하는 검증이 세트로 따라와야 한다.**

## 나중에 더 깊게 들어가면

- TDD 루프를 Claude Code와 결합하는 구체적인 워크플로우
- 프롬프트 명세 품질을 높이는 기법 (기능, 제약, 성능 요구 구분)
- Claude 출력을 여러 번 생성하고 가장 나은 결과만 채택하는 전략
