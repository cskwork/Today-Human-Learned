# 에이전트형 LLM 코드 생성 활용 가이드

> **TL;DR**
> AI 코딩 도구는 단순 자동완성을 넘어 계획·실행·검증을 스스로 하는 에이전트로 진화했다. 잘 쓰려면 명확한 지시와 반드시 따르는 검증이 필요하다.

---

## 에이전트형 LLM을 왜 쓰는지 감 잡기

기존 IDE 자동완성은 현재 커서 위치 근처만 본다. 에이전트형 LLM은 전체 코드베이스를 이해하고, 테스트를 실행하고, 오류를 스스로 수정하려 시도한다. GitHub Copilot Agent, Claude Code 같은 도구가 이 범주에 속한다. 이 도구들이 강한 분야가 있고 약한 분야가 있다. 어디에 쓰고 어디에 쓰지 말아야 할지를 모르면, 시간을 절약하는 게 아니라 버그를 빠르게 양산하게 된다.

초보자는 처음에 이렇게 이해하면 된다.

`핵심 흐름: 지시 작성 → AI 코드 생성 → 사람이 검토 → 테스트 통과 확인`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| 에이전트형 LLM | 작업을 스스로 계획하고 실행하는 AI 코딩 도우미 |
| 프롬프트(Prompt) | AI에게 원하는 작업을 지시하는 입력 문장 |
| 보일러플레이트 | 반복적으로 쓰이는 표준 코드 패턴 (getter, 설정 파일 등) |
| 엣지 케이스(Edge Case) | 입력이 비정상적일 때 발생하는 예외 상황. AI가 자주 빠뜨린다. |
| 독스트링(Docstring) | 함수 목적과 입출력을 설명하는 코드 내 주석. AI 지시에 효과적. |

## 예를 들어 설명하면

잘못된 지시와 올바른 지시의 차이는 구체성에 있다.

```
# 나쁜 지시
"빠른 코드 작성해줘"

# 좋은 지시
"O(N) 시간복잡도로 동작, 빈 리스트 입력 시 0 반환, 숫자 아닌 값 입력 시 ValueError 발생"
```

Python 함수라면 독스트링에 입력·출력·예시를 명시하면 AI가 훨씬 정확한 구현을 만든다.

```python
def calculate_average(data_list):
    """리스트의 평균값을 계산한다.

    Args:
        data_list: 숫자 리스트
    Returns:
        float 평균값. 빈 리스트면 0.0 반환.

    Example:
        >>> calculate_average([1, 2, 3])
        2.0
    """
```

## AI 코드 검토 시 반드시 확인할 것

- 보안 취약점: 오래된 라이브러리 사용, SQL 인젝션 가능성
- 예외 처리 누락: 빈 입력, None, 타입 불일치
- 성능: 루프 안에 DB 쿼리가 있는지 (N+1 문제)
- 언어 관용구: AI가 다른 언어 스타일로 코드를 쓰는 경우가 있다

## 이 단계에서 중요한 판단 기준

AI 코드는 반드시 테스트를 통과해야만 완료로 본다. 코드가 그럴듯해 보여도 실행 전까지는 신뢰하지 않는다.

## 한 줄 요약 — 이것만 기억하면 된다

**에이전트형 LLM은 반복 작업에서 강력하지만, 검증 없이 쓰는 순간 버그 생성기가 된다.**

## 나중에 더 깊게 들어가면

- 언어별 AI 활용 패턴: Java는 JavaDoc, Python은 독스트링, JS는 JSDoc
- AI가 생성한 테스트 코드의 신뢰도 평가 방법
- 에이전트 모드 활성화 시 컨텍스트 관리 전략
