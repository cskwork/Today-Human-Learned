# LLM 프롬프트 엔지니어링 — 실험으로 검증된 기법들

> **TL;DR**
> Chain-of-thought와 few-shot prompting이 가장 확실히 검증된 기법이며, 모델 크기와 작업 복잡도에 맞춰 선택하는 것이 핵심이다.

---

## 프롬프트 엔지니어링을 왜 쓰는지 감 잡기

LLM은 질문 방식에 따라 결과가 크게 달라진다. 같은 모델이라도 "답을 알려줘"보다 "단계별로 생각한 뒤 답을 알려줘"라고 하면 정확도가 수십 퍼센트 오른다. 이 차이를 체계적으로 연구한 분야가 프롬프트 엔지니어링이다.

1,565편의 논문을 메타 분석한 The Prompt Report(2024)는 58가지 기법을 분류하고 표준 용어 33개를 정의했다. 이 중 현장에서 즉시 쓸 수 있는 기법만 추린다.

초보자는 처음에 이렇게 이해하면 된다.

`핵심 흐름: 기법 선택 → 프롬프트 작성 → 결과 평가 → 반복 개선`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| Chain-of-Thought (CoT) | "단계별로 생각해봐"라고 시키는 방식. 모델이 중간 과정을 적으면서 추론한다. |
| Few-shot prompting | 질문 전에 예시를 2~5개 보여주는 방식. 원하는 출력 형태를 모델이 파악한다. |
| Tree-of-Thoughts (ToT) | CoT를 여러 경로로 동시에 탐색하는 방식. 계산 비용이 크다. |
| Self-consistency | 같은 질문을 여러 번 물어보고 가장 자주 나온 답을 선택하는 방식. |
| PAL (Program-Aided Language) | 자연어 대신 실행 가능한 코드를 생성하게 해서 계산 오류를 줄이는 방식. |

## 예를 들어 설명하면

수학 문제를 풀 때 CoT와 few-shot을 조합하면 효과가 크다.

```
# Zero-shot CoT: 트리거 문장 한 줄이면 충분
질문: 사과 3개가 있다. 2개를 먹으면 몇 개 남는가?
"단계별로 생각한 뒤 답하세요."

# Few-shot CoT: 예시를 먼저 보여준다
예시) 사과 5개, 3개 먹음 → 5-3=2개 남음
질문: 사과 3개, 2개 먹음 → ?
```

GSM8K 수학 벤치마크에서 CoT는 기존 방식 대비 58% 정확도를 달성했다. 단, 100B 파라미터 미만 모델에서는 효과가 거의 없다.

## 이 단계에서 중요한 판단 기준

모델 크기가 100B 미만이면 CoT는 효과가 없으니 few-shot부터 먼저 시도하고, 그래도 부족하면 모델 교체를 검토한다.

## 한 줄 요약 — 이것만 기억하면 된다

**복잡한 추론 작업에는 CoT, 정형화된 분류 작업에는 few-shot을 쓰되, 항상 A/B 테스트로 검증한다.**

## 나중에 더 깊게 들어가면

- Tree-of-Thoughts의 탐색 알고리즘(BFS, DFS, beam search) 차이
- 자동 프롬프트 최적화(APO) — 사람 대신 AI가 프롬프트를 개선하는 방식
- Constitutional AI와 self-critique 기반 안전성 향상 기법
