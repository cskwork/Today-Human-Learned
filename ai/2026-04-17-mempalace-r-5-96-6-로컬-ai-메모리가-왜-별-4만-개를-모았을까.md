# MemPalace — R@5 96.6%, 로컬 AI 메모리가 왜 별 4만 개를 모았을까

> **TL;DR**
> 요약하지 않고, 밖으로 내보내지 않고, 공간으로 나눈다. 이 세 원칙으로 AI 장기 기억을 로컬에서 돌리는 오픈소스 엔진이 MemPalace다.

---

## MemPalace를 왜 쓰는지 감 잡기

Claude나 ChatGPT를 반복해서 쓰다 보면 매번 같은 맥락을 다시 붙여 넣게 된다. 기존 해법은 대부분 요약 기반이라 디테일이 증발하거나, 클라우드 API에 대화 전문을 보내야 했다. MemPalace는 이 두 문제를 동시에 피하기 위해 만들어졌다. 대화를 원문 그대로 로컬에 저장하고, 3계층 공간 구조로 검색 범위를 좁혀 관련 내용만 꺼낸다. API 키가 없어도 동작하고, 임베딩과 검색 모두 내 머신에서 실행된다.

초보자는 처음에 이렇게 이해하면 된다.

`핵심 흐름: 원문 저장(mine) → 3계층 분류(Wing/Room/Drawer) → 의미 검색(search)`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| Wing | 프로젝트나 인물처럼 가장 큰 구분 단위. 폴더라면 최상위 폴더. |
| Room | Wing 안의 주제 묶음. 같은 프로젝트 안에서도 '설계'와 '버그'를 나누고 싶을 때 쓴다. |
| Drawer | 실제 원문이 저장되는 최소 단위. 요약 없이 텍스트가 그대로 들어간다. |
| Verbatim 저장 | 내용을 바꾸지 않고 원문 그대로 보관하는 방식. 나중에 "그때 정확히 뭐라고 했더라"를 찾을 수 있다. |
| MCP 서버 | Claude Code나 Cursor 같은 도구에 MemPalace를 꽂아 주는 연결 규격. 명령어 한 줄로 노출된다. |

## 예를 들어 설명하면

프로젝트 파일과 대화 기록을 채굴(mine)한 뒤, 자연어로 검색하는 기본 흐름이다.

```python
# Python 3.9+ / mempalace 3.3.0
from mempalace import Palace

palace = Palace.open("~/projects/myapp")
palace.search("왜 GraphQL로 바꿨더라")
# Drawer 원문 + Wing/Room 경로 + 유사도 점수가 함께 반환된다
```

터미널에서 바로 쓰고 싶다면 아래 순서로 충분하다.

```bash
pip install mempalace          # ~300MB, Python 3.9+ 필요
mempalace init ~/projects/myapp
mempalace mine ~/projects/myapp          # 파일 채굴
mempalace mine ~/chats/ --mode convos   # 대화 채굴
mempalace search "왜 GraphQL로 바꿨더라"
mempalace mcp                           # Claude Code용 MCP 서버 기동
```

Claude Code에서는 MCP 설정에 `mempalace mcp`를 등록하면 29종의 도구가 자동으로 노출된다. 외부 네트워크 호출 없이 로컬 파이프로만 통신한다.

## 이 단계에서 중요한 판단 기준

Verbatim 저장은 디스크를 더 쓰지만, 사후 재질의에 강하다. 민감 정보는 채굴 대상에서 미리 제외해야 한다.

| 패턴 | 장점 | 주의점 |
|---|---|---|
| Verbatim 저장 (MemPalace 기본) | 원문 손실 없음, 세부 정보 재질의에 강함 | 디스크 사용 증가, 민감 정보 선별 필요 |
| 요약 기반 메모리 | 용량 절약, 빠른 문맥 주입 | 세부 정보 소실, 재요약 시 누락 누적 |
| 클라우드 메모리 SaaS | 초기 셋업 간단, 기기 간 동기화 | API 비용, 대화 전문이 외부로 전송됨 |

벤치마크는 LongMemEval R@5 Raw 96.6% / Hybrid held-out 98.4%가 공식 기준이다. "100%"는 테스트 암기에 가깝다고 저자들 스스로 경계하므로, 실운영 기대치는 Raw 96.6%로 잡는 것이 정직하다.

설치 전 주소 확인: 공식 저장소는 `github.com/MemPalace/mempalace` 하나뿐이며, `mempalace.tech` 같은 유사 도메인은 README에 사칭으로 명시되어 있다.

## 한 줄 요약 — 이것만 기억하면 된다

**원문을 요약하지 않고, 공간(Wing/Room/Drawer)으로 나눠 로컬에서 검색하는 것이 MemPalace의 핵심이다.**

## 나중에 더 깊게 들어가면

- ChromaDB 외 다른 벡터 백엔드로 교체하는 방법 (`mempalace/backends/base.py` 인터페이스)
- LongMemEval·LoCoMo·ConvoMem·MemBench 벤치마크 방법론 직접 재현
- 지식 그래프(SQLite 기반)를 활용한 크로스 윙 탐색 패턴
