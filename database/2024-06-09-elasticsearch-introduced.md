# Elasticsearch — 수백만 건 문서에서 단어를 순식간에 찾는 방법

> **TL;DR**
> Elasticsearch는 역색인(inverted index)을 기반으로 대규모 텍스트 데이터를 빠르게 전문 검색(full-text search)하는 분산 검색 엔진이다.

---

## Elasticsearch를 왜 쓰는지 감 잡기

관계형 DB에서 `LIKE '%검색어%'`로 전체 텍스트를 뒤지면 데이터가 수백만 건일 때 수십 초가 걸린다. Elasticsearch는 처음부터 "단어 단위로 미리 인덱스를 만들어두겠다"는 구조로 설계됐다. 덕분에 어떤 단어가 어떤 문서에 있는지를 미리 정리해두고, 검색 시에는 그 목록만 꺼내면 된다.

Apache Lucene 검색 라이브러리 위에 분산 처리를 얹어 만든 것이 Elasticsearch다. 로그 분석, 전자상거래 상품 검색, 뉴스 기사 검색 등 텍스트 검색이 핵심인 서비스에 광범위하게 쓰인다.

초보자는 처음에 이렇게 이해하면 된다.

`핵심 흐름: 문서 저장 → 단어 단위 토큰화 → 역색인 생성 → 검색 쿼리 → 역색인 조회 → 결과 반환`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| 인덱스(Index) | 관계형 DB의 데이터베이스에 해당. 문서들을 담는 논리적 단위다. |
| 문서(Document) | 관계형 DB의 행(row)에 해당. JSON 형태의 데이터 한 건이다. |
| 샤드(Shard) | 인덱스를 여러 조각으로 나눈 것. 여러 서버에 분산 저장해 처리 속도를 높인다. |
| 역색인(Inverted Index) | 단어를 키, 그 단어가 등장하는 문서 목록을 값으로 저장하는 구조. 검색 속도의 핵심이다. |
| 레플리카(Replica) | 샤드의 복사본. 노드 하나가 죽어도 데이터가 유지되도록 보장한다. |

## 예를 들어 설명하면

논문 데이터베이스에서 "dark matter"가 제목에 포함되고 2015년 이후에 출판된 논문을 찾는다고 하자.

```json
{
  "query": {
    "bool": {
      "must": [
        { "match": { "title": "dark matter" } },
        { "range": { "publication_date": { "gt": "2015-01-01" } } }
      ]
    }
  }
}
```

Elasticsearch는 역색인에서 "dark"와 "matter"가 동시에 등장하는 문서를 즉시 찾아내고, 날짜 조건으로 한 번 더 걸러 결과를 돌려준다. 전체 문서를 순차 스캔하지 않는다.

## 이 단계에서 중요한 판단 기준

전문 검색이 핵심 기능이거나 로그 분석이 필요하다면 Elasticsearch가 적합하다. 단, 데이터 변경이 잦고 트랜잭션 정합성이 중요한 서비스라면 관계형 DB를 주 저장소로 두고 Elasticsearch를 검색 전용으로 보조 운용하는 것이 일반적이다.

## 한 줄 요약 — 이것만 기억하면 된다

**Elasticsearch는 역색인 덕분에 수백만 건의 텍스트에서도 원하는 단어를 밀리초 안에 찾아낸다.**

## 나중에 더 깊게 들어가면

- 역색인이 내부적으로 어떻게 구성되는지 (토큰화, 분석기)
- 샤드 개수 설계와 성능 트레이드오프
- Kibana와 연동해 로그 시각화하기
