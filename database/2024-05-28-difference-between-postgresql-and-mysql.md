# PostgreSQL vs MySQL — 어떤 상황에서 무엇을 고를까

> **TL;DR**
> PostgreSQL은 복잡한 쿼리와 데이터 무결성에 강하고, MySQL은 읽기 위주의 단순한 웹 애플리케이션에서 빠르다.

---

## 두 DB를 왜 비교하는지 감 잡기

PostgreSQL과 MySQL은 둘 다 오픈소스 관계형 데이터베이스다. 겉보기에는 비슷하지만 설계 철학이 다르다. PostgreSQL은 SQL 표준 준수와 기능 확장성을 최우선으로 삼았고, MySQL은 설치와 운영의 단순함, 읽기 성능을 앞세웠다. 프로젝트 성격에 맞게 고르지 않으면 나중에 한계에 부딪힌다.

`핵심 흐름: 요구사항 파악 → 쿼리 복잡도/트래픽 패턴 확인 → DB 선택`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| ACID | 트랜잭션의 4가지 보장: 원자성, 일관성, 격리성, 지속성. 데이터가 중간 상태로 남지 않음을 뜻한다 |
| MVCC | 여러 사용자가 동시에 읽고 쓸 때 서로 잠금 없이 처리하는 동시성 제어 방식 |
| 스토리지 엔진 | MySQL이 데이터를 실제로 저장하는 방식. InnoDB(기본값)와 MyISAM이 대표적이다 |
| 확장 타입 | PostgreSQL이 지원하는 JSON, 배열, 지리 좌표 같은 비정형 데이터 타입들 |
| 인덱스 종류 | PostgreSQL은 GiST, GIN 등 특수 인덱스를 제공해 전문 검색이나 JSON 검색을 빠르게 한다 |

## 예를 들어 설명하면

두 가지 상황으로 비교한다.

**상황 1 — 쇼핑몰 상품 목록 서비스**
수백만 명이 상품을 검색하고 열람하는, 읽기가 압도적으로 많은 서비스다. 쿼리는 단순한 `SELECT`가 대부분이다. MySQL이 이런 환경에서 낮은 오버헤드로 빠른 응답을 제공한다.

**상황 2 — 과학 데이터 분석 플랫폼**
측정값, 좌표, 중첩된 메타데이터를 저장해야 하고, 집계 쿼리가 복잡하다. 커스텀 데이터 타입이 필요할 수도 있다. PostgreSQL의 배열 타입, JSON 인덱스, 윈도우 함수가 이 요구에 잘 맞는다.

핵심 차이를 표로 정리하면 다음과 같다.

| 기준 | PostgreSQL | MySQL |
|---|---|---|
| SQL 표준 준수 | 높음 | 보통 |
| ACID 기본 보장 | 항상 | InnoDB 엔진에서만 |
| 복잡한 쿼리 성능 | 강함 | 단순 쿼리에 최적화 |
| 확장 데이터 타입 | JSON, 배열, 지리 등 풍부 | 기본 타입 위주 |
| 설정 난이도 | 상대적으로 복잡 | 간단 |
| 주요 사용처 | 금융, 분석, 복잡한 웹앱 | WordPress, 소규모 웹 서비스 |

## 이 단계에서 중요한 판단 기준

"JOIN이 복잡하거나 쓰기 트랜잭션 무결성이 중요하다"면 PostgreSQL, "빠른 읽기와 간단한 운영이 우선"이라면 MySQL부터 검토한다.

## 한 줄 요약 — 이것만 기억하면 된다

**PostgreSQL은 기능과 정확성, MySQL은 단순성과 읽기 속도가 강점이다. 프로젝트의 쿼리 복잡도와 트래픽 패턴으로 결정한다.**
