# Oracle DBMS — 엔터프라이즈 데이터베이스의 구조 이해하기

> **TL;DR**
> Oracle DBMS는 대용량 데이터와 복잡한 트랜잭션을 안정적으로 처리하도록 설계된 상용 관계형 데이터베이스 시스템이다.

---

## Oracle DBMS를 왜 쓰는지 감 잡기

규모가 작은 프로젝트는 오픈소스 DB로 충분하지만, 은행 거래나 대기업 ERP처럼 수천만 건의 데이터가 동시에 읽히고 쓰이는 환경에서는 성능과 안정성 요구 수준이 다르다. Oracle은 이런 엔터프라이즈 환경을 위해 수십 년간 다듬어진 시스템이다. 유료이지만 그만큼 고가용성, 보안, 복구 도구가 잘 갖춰져 있다.

Oracle을 처음 접하면 용어가 많아서 복잡하게 느껴진다. 하지만 핵심 구조는 단순하다.

`핵심 흐름: 데이터 파일(디스크) → 인스턴스(메모리+프로세스) → 사용자 쿼리`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| 인스턴스(Instance) | Oracle이 실행 중일 때 메모리와 백그라운드 프로세스의 묶음. DB가 살아있는 상태 |
| SGA (System Global Area) | 모든 사용자가 공유하는 메모리 영역. 캐시, 로그 버퍼 등이 여기에 있다 |
| 스키마(Schema) | 한 사용자에 속한 테이블, 뷰, 인덱스 등 객체의 집합 |
| PL/SQL | Oracle 전용 절차형 언어. SQL에 IF, LOOP 같은 프로그래밍 요소를 더한 것 |
| RMAN | 데이터베이스 백업과 복구를 담당하는 Oracle 내장 도구 |

## 예를 들어 설명하면

재고 관리 시스템을 운영한다고 하자. 하루에도 수만 건의 입출고 거래가 발생하고, 그 결과가 즉시 재고 수량에 반영되어야 한다.

- SQL로 입출고 내역을 `INSERT`하고, 재고 테이블을 `UPDATE`한다.
- 두 작업은 하나의 트랜잭션으로 묶어야 한다. 입고 기록은 됐는데 재고 수량은 안 바뀌면 데이터가 망가진다.
- Oracle은 ACID 속성(원자성, 일관성, 격리성, 지속성)을 기본으로 보장한다. `COMMIT`하면 영구 저장, `ROLLBACK`하면 완전 취소다.
- 야간 배치로 PL/SQL 프로시저를 실행해 월간 재고 리포트를 자동 생성한다.
- RMAN으로 매일 백업을 받아두면, 장애 시 특정 시점으로 데이터를 복구할 수 있다.

## 이 단계에서 중요한 판단 기준

Oracle을 선택할 때 가장 먼저 확인해야 할 것은 "트랜잭션 규모와 가용성 요구사항이 오픈소스 DB로 감당이 안 되는가"다. 라이선스 비용이 크기 때문에, 그 비용을 정당화할 만한 부하와 안정성 요구가 있어야 한다.

## 한 줄 요약 — 이것만 기억하면 된다

**Oracle DBMS는 인스턴스(메모리), 데이터 파일(디스크), PL/SQL(자동화), RMAN(복구)으로 구성된 엔터프라이즈급 관계형 데이터베이스다.**

## 나중에 더 깊게 들어가면

- 테이블스페이스(Tablespace)와 데이터 파일의 관계
- RAC(Real Application Clusters): 여러 서버가 하나의 DB를 공유하는 고가용성 구성
- 실행 계획(Execution Plan): Oracle이 쿼리를 어떻게 처리하는지 분석하고 튜닝하는 방법
