# EC2 요금 정책 — 인스턴스 비용을 결정하는 네 가지 축

> **TL;DR**
> EC2 비용은 인스턴스 타입, 구매 모델(온디맨드/예약/스팟), 스토리지, 데이터 전송 네 가지로 구성된다.

---

## EC2 요금을 왜 알아야 하는가

EC2는 클라우드에서 빌리는 가상 서버다. 서버를 빌릴 때 단순히 "시간당 얼마"가 아니라, 얼마나 강력한 서버인지(인스턴스 타입), 어떤 방식으로 계약하는지(구매 모델), 어떤 디스크를 붙이는지(스토리지), 얼마나 많은 데이터를 외부로 내보내는지(데이터 전송)가 모두 요금에 영향을 준다.

초보자는 처음에 이렇게 이해하면 된다.

`핵심 흐름: 인스턴스 요금(타입 x 구매 모델) + 스토리지 요금 + 데이터 전송 요금`

---

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| 온디맨드(On-Demand) | 계약 없이 사용한 시간만큼 내는 방식. 비싸지만 언제든 켜고 끌 수 있다. |
| 예약 인스턴스(Reserved) | 1년 또는 3년 약정을 맺는 대신 온디맨드 대비 최대 72% 할인을 받는다. |
| 스팟 인스턴스(Spot) | AWS의 남는 용량을 경매처럼 낮은 가격에 사용하는 방식. 언제든 중단될 수 있다. |
| Savings Plans | 특정 인스턴스가 아닌 시간당 사용량 단위로 약정해 할인을 받는 유연한 모델. |
| EBS (Elastic Block Store) | EC2에 붙이는 영구 블록 스토리지. 인스턴스를 꺼도 데이터가 유지된다. |

---

## 예를 들어 설명하면

웹 애플리케이션을 운영하는 시나리오다.

- **초기 단계**: 트래픽이 불규칙하므로 온디맨드로 시작해 유연하게 운영한다.
- **안정 단계**: 트래픽 패턴이 예측 가능해지면 예약 인스턴스로 전환해 비용을 낮춘다.
- **배치 작업**: 야간 데이터 처리처럼 중단돼도 괜찮은 작업은 스팟 인스턴스로 실행해 추가 절감한다.
- **스토리지**: 데이터베이스 파일은 EBS에, 정적 이미지는 S3에 나눠 저장해 비용을 최적화한다.
- **데이터 전송**: 같은 리전 내 AWS 서비스 간 전송은 무료 또는 소액이지만, 인터넷으로 내보내는 트래픽은 유료다.

---

## 이 단계에서 중요한 판단 기준

워크로드가 예측 가능하고 지속적이면 예약 인스턴스나 Savings Plans를, 불규칙하거나 단기 테스트라면 온디맨드를, 중단을 허용할 수 있는 배치 작업이라면 스팟을 선택한다.

---

## 한 줄 요약 — 이것만 기억하면 된다

**EC2 비용의 핵심은 구매 모델 선택이며, 워크로드 패턴에 맞게 온디맨드·예약·스팟을 조합하면 비용을 크게 낮출 수 있다.**
