# S3 요금 정책 — 무엇에 돈을 내는가

> **TL;DR**
> S3는 저장 공간, 데이터 이동, API 호출, 세 축으로 요금이 나뉘며 스토리지 클래스를 잘 고르면 비용을 크게 줄일 수 있다.

---

## S3 요금을 왜 알아야 하는가

AWS S3는 파일을 올려두는 창고다. 창고를 빌릴 때 임대료(저장 공간)만 내는 게 아니라, 물건을 꺼내거나 옮길 때마다 추가 요금이 붙는다. S3도 마찬가지다. 저장만 하고 꺼내지 않으면 저장 요금만 내지만, 외부로 자주 내보내거나 API를 많이 호출하면 그만큼 비용이 올라간다.

초보자는 처음에 이렇게 이해하면 된다.

`핵심 흐름: 저장 비용 + 데이터 전송 비용 + API 요청 비용`

---

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| Standard | 자주 꺼내 쓰는 데이터용 기본 클래스. 가장 빠르고 가장 비싸다. |
| Infrequent Access (IA) | 가끔만 꺼내는 데이터용. 저장 단가는 낮지만 꺼낼 때 추가 요금이 붙는다. |
| Glacier | 거의 안 꺼내는 장기 보관용. 저장 단가가 가장 낮고, 꺼내는 데 수분~수 시간 걸린다. |
| Data Transfer Out | S3에서 인터넷이나 다른 리전으로 데이터를 내보낼 때 발생하는 비용. S3로 넣는 건 무료다. |
| PUT / GET 요청 | 파일을 올릴 때(PUT)와 내려받을 때(GET)마다 건당 소액이 청구된다. |

---

## 예를 들어 설명하면

사진 100 GB를 Standard 클래스에 저장한다고 가정한다.

- 저장 요금: 약 $0.023/GB x 100 GB = **월 $2.30**
- 사진을 자주 외부 사용자에게 제공하면 Data Transfer Out 요금이 추가된다.
- 새 사진을 업로드할 때마다 PUT 요청 요금, 조회할 때마다 GET 요청 요금이 붙는다.
- 이 사진들을 다른 리전에 복제(Cross-Region Replication)하면 복제 전송 요금과 두 번째 리전 저장 요금이 이중으로 발생한다.

자주 접근하지 않는 아카이브라면 Glacier로 옮기면 저장 단가를 10분의 1 수준으로 낮출 수 있다.

---

## 이 단계에서 중요한 판단 기준

데이터에 얼마나 자주 접근하는지를 먼저 파악하고, 접근 빈도에 맞는 스토리지 클래스를 선택하는 것이 S3 비용 최적화의 핵심이다.

---

## 한 줄 요약 — 이것만 기억하면 된다

**S3 요금은 저장 + 꺼낼 때 + API 호출, 이 세 가지이며 스토리지 클래스 선택이 비용을 가른다.**

---

## 나중에 더 깊게 들어가면

- S3 Intelligent-Tiering: 접근 패턴을 자동 분석해 클래스를 자동 전환하는 기능
- S3 Lifecycle Policy: 일정 기간 후 자동으로 저렴한 클래스로 이동시키는 규칙
- Cross-Region Replication 비용 구조와 재해 복구 설계
