# 쿠버네티스 인그레스(Ingress) — 클러스터 외부 트래픽 관리의 핵심

> **TL;DR**
> 인그레스는 하나의 IP와 80/443 포트로 들어온 외부 요청을 호스트명·경로에 따라 내부 여러 서비스로 나눠주는 L7 라우터다.

---

## 인그레스를 왜 쓰는지 감 잡기

NodePort는 노드마다 비표준 포트를 열어야 하고, 클라우드 LoadBalancer는 서비스 수만큼 로드밸런서를 만들어 비용이 직선으로 늘어난다. 서비스가 5개면 로드밸런서도 5개다.

인그레스는 로드밸런서를 하나만 두고, 그 앞에 "경로 안내판"을 세우는 방식이다. `mysite.com/login`은 로그인 서비스로, `api.mysite.com`은 API 서버로 보내는 규칙을 YAML 한 파일에 모아서 관리한다. SSL 인증서도 인그레스 컨트롤러에서 한 번에 처리하므로 각 서비스는 HTTP 내부 통신만 신경 쓰면 된다.

`핵심 흐름: 인터넷 → 로드밸런서(클라우드) → 인그레스 컨트롤러 → 규칙 매칭 → 서비스 A / B / C`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| 인그레스 리소스 | 요청을 어느 서비스로 보낼지 규칙을 적은 쿠버네티스 오브젝트(YAML 파일) |
| 인그레스 컨트롤러 | 그 규칙을 읽어서 실제 트래픽을 처리하는 프록시 (Nginx, Traefik 등, 별도 설치) |
| 경로 기반 라우팅 | URL 경로(`/login`, `/api`)를 보고 목적지 서비스를 결정하는 방식 |
| 호스트 기반 라우팅 | 도메인 이름(`api.mysite.com`, `blog.mysite.com`)을 보고 분기하는 방식 |
| SSL/TLS 종료 | HTTPS 요청을 인그레스에서 복호화하고 내부는 HTTP로 전달하는 구조 |

## 예를 들어 설명하면

`mysite.com` 하나의 도메인으로 두 서비스를 운영한다고 가정한다.

```
외부 요청                   인그레스 규칙               내부 서비스
mysite.com/login   -->  path: /login   -->  login-service:80
mysite.com/products --> path: /products --> product-service:80
```

비교로 정리하면 아래와 같다.

| 특징 | NodePort | LoadBalancer | Ingress |
|---|---|---|---|
| OSI 계층 | L4 | L4 | L7 |
| 진입점 | 노드 IP + 임의 포트 | 서비스별 외부 IP | 컨트롤러 IP 하나 |
| 경로/호스트 라우팅 | 불가 | 불가 | 가능 |
| SSL 처리 | 서비스 직접 | 로드밸런서 레벨 | 인그레스 레벨 |
| 비용 | 낮음 | 서비스 수에 비례 | 컨트롤러 1개 공유 |

## 이 단계에서 중요한 판단 기준

인그레스 리소스만 배포해서는 아무 일도 일어나지 않는다. 반드시 인그레스 컨트롤러가 클러스터에 실행 중이어야 규칙이 적용된다.

## 한 줄 요약 — 이것만 기억하면 된다

**인그레스는 여러 서비스를 하나의 외부 IP 아래에서 URL 규칙으로 분기하는 L7 라우터이며, 컨트롤러 없이는 동작하지 않는다.**

## 나중에 더 깊게 들어가면

- 어노테이션으로 제어하는 컨트롤러별 고급 기능 (CORS, 리다이렉션, 타임아웃)
- 와일드카드 호스트(`*.example.com`)와 와일드카드 인증서 조합
- cert-manager를 이용한 TLS 인증서 자동 갱신
