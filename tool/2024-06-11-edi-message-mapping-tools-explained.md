# EDI 메시지 매핑 도구 — 포맷이 다른 시스템끼리 데이터를 주고받는 방법

> **TL;DR**
> EDI 매핑 도구는 서로 다른 전자 문서 표준을 변환하는 번역기다. 규칙을 정의하면 도구가 자동으로 변환·검증한다.

---

## EDI 메시지 매핑을 왜 쓰는지 감 잡기

기업 간 데이터를 자동으로 교환하는 표준이 EDI(Electronic Data Interchange)다. 문제는 표준이 하나가 아니라는 점이다. 미국 유통사는 ANSI X12를, 유럽 파트너사는 EDIFACT를, 영국 유통망은 TRADACOMS를 쓴다. 같은 발주서를 보내더라도 형식이 달라 상대방 시스템이 읽지 못한다.

EDI 메시지 매핑 도구는 이 변환을 자동화한다. 사람이 일일이 재입력하는 대신, 변환 규칙을 한 번 정의해두면 이후로는 자동으로 처리된다. 대형 유통·물류·금융 업계에서 하루 수만 건의 주문서, 청구서, 출고 통보를 이 방식으로 교환한다.

초보자는 처음에 이렇게 이해하면 된다.

`핵심 흐름: 원본 EDI 수신 → 매핑 규칙 적용 → 변환된 EDI 출력 → 상대 시스템 전달`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| EDI | 기업 간에 구조화된 전자 문서를 자동으로 교환하는 표준 방식 |
| 세그먼트(Segment) | EDI 메시지 안의 한 줄짜리 데이터 단위. 예: 주문 항목 한 개 |
| 엘리먼트(Element) | 세그먼트를 구성하는 개별 값. 예: 상품코드, 수량, 단가 |
| 매핑 규칙 | "원본의 A 필드를 대상 포맷의 B 필드로 옮겨라"는 변환 명세 |
| 스키마(Schema) | 각 EDI 포맷이 어떤 세그먼트와 엘리먼트를 어떤 순서로 요구하는지 정의한 설계도 |

## 예를 들어 설명하면

A사는 ANSI X12로 발주서를 보내고, B사 시스템은 EDIFACT만 이해한다. 매핑 도구가 없으면 중간에 사람이 직접 변환해야 한다.

```
ANSI X12:  PO1*1*100*EA*9.99**BP*12345*VP*67890
           (발주 항목 1번, 수량 100, 단위 EA, 단가 9.99, 상품코드 12345)

EDIFACT:   LIN+1++12345:BP+67890:VP
           (같은 정보, EDIFACT 방식으로 재구성)
```

매핑 도구는 X12의 `PO1` 세그먼트를 EDIFACT의 `LIN` 세그먼트로, 필드 하나하나를 대응되는 위치로 이동시킨다. 변환 후 검증 엔진이 EDIFACT 스키마 규칙을 충족하는지 자동으로 점검한다.

## 이 단계에서 중요한 판단 기준

매핑 규칙을 처음 설계할 때 "필수 필드가 원본에 없으면 어떻게 처리할 것인가"를 먼저 결정해야 에러 루프를 막을 수 있다.

## 한 줄 요약 — 이것만 기억하면 된다

**EDI 매핑 도구는 포맷 변환 규칙을 한 번만 정의하면 이후 모든 메시지를 자동 번역하는 번역기다.**

## 나중에 더 깊게 들어가면

- ANSI X12, EDIFACT, TRADACOMS 각 표준의 세그먼트 구조 차이
- 매핑 도구별 비교: MuleSoft DataWeave, IBM Sterling, Boomi
- 변환 오류 처리와 재전송(idempotency) 전략
