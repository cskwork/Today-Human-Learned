# 트리 탐색: BFS와 DFS의 차이

> **TL;DR**
> BFS는 같은 깊이의 노드를 모두 방문한 뒤 다음 층으로 내려가고, DFS는 한 경로를 끝까지 파고든 다음 되돌아온다. BFS는 큐, DFS는 스택(또는 재귀)을 쓴다.

---

## 트리 탐색을 왜 쓰는지 감 잡기

트리는 계층 구조를 표현하는 자료구조다. 파일 시스템, 조직도, HTML DOM, 결정 트리 등 어디서나 등장한다. 트리에서 원하는 노드를 찾거나, 모든 노드를 처리하려면 탐색 순서를 정해야 한다. 그 선택이 BFS와 DFS다.

BFS(너비 우선 탐색)는 "최단 경로"가 필요할 때 유리하다. 뿌리에서 목적지까지 가장 적은 단계로 도달하는 경로를 보장한다. DFS(깊이 우선 탐색)는 "존재 여부 확인"이나 "모든 경우의 수 탐색"에 어울린다.

`BFS 흐름: 루트 → 같은 층 전부 방문 → 한 층 내려감 → 반복`

`DFS 흐름: 루트 → 한 방향으로 끝까지 → 막히면 되돌아옴 → 다음 방향`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| 노드(node) | 트리를 구성하는 각 점. 값을 가지며 자식 노드와 연결된다. |
| 큐(queue) | 먼저 들어온 것이 먼저 나오는 구조(FIFO). BFS에서 방문 순서를 유지한다. |
| 스택(stack) | 나중에 들어온 것이 먼저 나오는 구조(LIFO). DFS에서 깊이를 추적한다. |
| 재귀(recursion) | 함수가 자기 자신을 호출하는 방식. DFS를 스택 없이 구현할 때 쓴다. |
| 전위/중위/후위 순회 | DFS의 세 가지 변형. 노드를 방문하는 시점(왼쪽 전, 중간, 후)이 다르다. |

## 예를 들어 설명하면

아래 트리를 두 방식으로 탐색해 보자.

```
      A
     / \
    B   C
   / \   \
  D   E   F
```

BFS 결과 (큐 사용):
- A 방문 → B, C를 큐에 추가
- B 방문 → D, E를 큐에 추가
- C 방문 → F를 큐에 추가
- 방문 순서: A → B → C → D → E → F

DFS 전위 순회 결과 (재귀 사용):
- A 방문 → 왼쪽(B)으로 내려감 → D까지 파고든 뒤 되돌아옴
- 방문 순서: A → B → D → E → C → F

두 방식 모두 시간 복잡도는 O(V + E)로 같다. V는 노드 수, E는 간선 수다.

## 이 단계에서 중요한 판단 기준

최단 거리나 레벨별 처리가 필요하면 BFS를 선택하고, 모든 경로 탐색이나 백트래킹이 필요하면 DFS를 선택한다.

## 한 줄 요약 — 이것만 기억하면 된다

**BFS는 층별로 퍼지고(큐), DFS는 깊이 파고든다(스택/재귀). 최단 경로는 BFS, 전체 경로 탐색은 DFS가 맞다.**

## 나중에 더 깊게 들어가면

- 그래프(cycle이 있는 구조)에서 BFS/DFS를 쓸 때 방문 여부 체크가 왜 필요한지
- DFS 중위 순회가 이진 탐색 트리에서 정렬된 순서를 내뱉는 이유
- BFS를 활용한 다익스트라 최단 경로 알고리즘의 연결 관계
