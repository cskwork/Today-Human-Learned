# K-way 병합: 여러 정렬 리스트를 하나로 합치기

> **TL;DR**
> K개의 정렬된 리스트를 하나로 합칠 때, 최소 힙을 사용해 매 단계마다 가장 작은 원소를 꺼내면 O(N log K) 시간에 처리할 수 있다.

---

## K-way 병합을 왜 쓰는지 감 잡기

데이터베이스가 대용량 정렬을 할 때, 파일 전체를 메모리에 올릴 수 없어서 여러 조각으로 나눠 각각 정렬한 뒤 합친다. 이때 조각이 K개라면 K-way 병합이 필요하다. 검색 엔진의 역색인 병합, 분산 시스템의 로그 합산 등에도 같은 패턴이 등장한다.

두 리스트를 합치는 2-way 병합은 익숙한 개념이다. K-way 병합은 그것을 K개로 확장한 것인데, "지금 K개의 리스트 중 가장 작은 원소가 무엇인가?"를 효율적으로 찾는 것이 핵심 문제다. 매번 K개를 전부 비교하면 느리다. 최소 힙을 쓰면 이 비교를 O(log K)로 줄일 수 있다.

`핵심 흐름: 각 리스트의 첫 원소를 힙에 삽입 → 힙에서 최솟값 추출 → 같은 리스트의 다음 원소를 힙에 삽입 → 힙이 빌 때까지 반복`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| 최소 힙(min-heap) | 가장 작은 값이 항상 맨 위에 있는 자료구조. 삽입과 추출 모두 O(log n)이다. |
| heapify | 원소들을 힙의 규칙에 맞게 배열하는 초기화 작업 |
| 추출(extract) | 힙에서 최솟값을 꺼내는 연산. 꺼내면 힙이 자동으로 다시 정렬된다. |
| K | 병합할 정렬 리스트의 개수 |
| N | 전체 원소의 합산 개수. 시간 복잡도를 O(N log K)로 표현할 때 쓴다. |

## 예를 들어 설명하면

세 리스트 `[1,4,7]`, `[2,5,8]`, `[3,6,9]`를 병합하는 과정이다.

초기 힙: `(1, 리스트0)`, `(2, 리스트1)`, `(3, 리스트2)`

| 단계 | 추출 | 결과 리스트 | 힙 상태 |
|------|------|------------|---------|
| 1 | 1 (리스트0) | [1] | (2,1), (3,2), (4,0) |
| 2 | 2 (리스트1) | [1,2] | (3,2), (4,0), (5,1) |
| 3 | 3 (리스트2) | [1,2,3] | (4,0), (5,1), (6,2) |
| ... | ... | ... | ... |
| 9 | 9 (리스트2) | [1,2,3,4,5,6,7,8,9] | (비어있음) |

매 단계에서 힙은 K개의 원소만 유지하므로 삽입/추출 비용은 O(log K)다. 전체 N개의 원소를 처리하면 총 O(N log K)다.

## 이 단계에서 중요한 판단 기준

K가 크고 리스트가 이미 정렬된 상황이라면, 단순 정렬(O(N log N))보다 K-way 병합(O(N log K))이 항상 빠르거나 같다.

## 한 줄 요약 — 이것만 기억하면 된다

**K개의 정렬 리스트를 합칠 때는 최소 힙으로 "지금 가장 작은 것"을 관리하면 O(N log K)에 끝난다.**

## 나중에 더 깊게 들어가면

- Python `heapq.merge()`를 사용한 실제 구현 방법
- 외부 정렬(external sort)에서 K-way 병합이 쓰이는 방식
- 시간 복잡도 O(N log K) vs 단순 정렬 O(N log N)의 교차점
