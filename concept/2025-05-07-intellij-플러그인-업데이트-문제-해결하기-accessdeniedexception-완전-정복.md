# IntelliJ 플러그인 업데이트 AccessDeniedException 해결

> **TL;DR**
> 플러그인 업데이트 중 AccessDeniedException은 백그라운드 프로세스가 파일을 잠갔기 때문이며, IDE와 관련 프로세스를 모두 종료한 뒤 반쯤 설치된 폴더를 삭제하면 대부분 해결된다.

---

## 이 오류가 왜 생기는지 감 잡기

IntelliJ는 플러그인을 업데이트할 때 기존 파일을 삭제하고 새 파일로 교체한다. Windows에서는 다른 프로세스가 파일을 열고 있으면 그 파일을 삭제하거나 덮어쓸 수 없다. 이때 `java.nio.file.AccessDeniedException`이 발생한다.

주요 원인은 세 가지다. 첫째, IDE가 완전히 종료되지 않아 언어 서버 같은 백그라운드 프로세스가 파일을 붙잡고 있는 경우. 둘째, 안티바이러스 소프트웨어가 새로 다운로드된 파일을 실시간으로 스캔하면서 잠금을 거는 경우. 셋째, 사용자 계정에 플러그인 폴더 쓰기 권한이 없는 경우.

`핵심 흐름: IDE 종료 → 백그라운드 프로세스 종료 → 불완전 폴더 삭제 → IDE 재시작 후 재설치`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| AccessDeniedException | 파일에 접근하려 했으나 운영체제가 권한을 거부했다는 Java 예외 |
| 파일 잠금 (File Lock) | 한 프로세스가 파일을 사용 중일 때 다른 프로세스의 수정을 막는 OS 메커니즘 |
| 백그라운드 프로세스 | IDE를 닫아도 메모리에 남아 실행 중인 보조 프로세스 (예: 언어 서버) |
| 플러그인 폴더 | `AppData\Roaming\JetBrains\<IDE버전>\plugins` — 플러그인 파일이 저장되는 위치 |
| 실시간 보호 | 안티바이러스가 파일 생성/수정 시점에 즉시 스캔하는 기능 |

## 예를 들어 설명하면

업데이트 도중 오류가 났다면 아래 순서로 처리한다.

1. IntelliJ를 포함한 모든 JetBrains IDE를 닫는다.
2. 작업 관리자(Win+X) 세부 정보 탭에서 `language_server_windows_x64.exe` 같은 IDE 관련 프로세스를 찾아 종료한다.
3. 아래 경로에서 문제가 된 플러그인 폴더를 삭제한다.
   ```
   C:\Users\사용자이름\AppData\Roaming\JetBrains\IntelliJIdea버전\plugins\플러그인이름
   ```
4. IDE를 다시 시작하고 설정 > 플러그인 > 마켓플레이스에서 해당 플러그인을 재설치한다.

위 방법으로 안 풀리면 아래 표를 참고한다.

| 원인 | 해결책 |
|---|---|
| 안티바이러스 간섭 | 플러그인 경로를 예외 목록에 추가하거나 재설치 동안 실시간 보호 일시 중지 |
| 권한 부족 | IntelliJ를 관리자 권한으로 실행하거나 plugins 폴더에 쓰기 권한 부여 |
| 기업 프록시 차단 | 플러그인 GitHub 페이지에서 zip 파일을 수동으로 내려받아 오프라인 설치 |

## 이 단계에서 중요한 판단 기준

오류가 반복된다면 안티바이러스 예외 등록을 가장 먼저 확인하라 — 보안 소프트웨어가 원인인 경우가 권한 문제보다 훨씬 많다.

## 한 줄 요약 — 이것만 기억하면 된다

**IDE와 관련 백그라운드 프로세스를 모두 종료한 뒤 불완전하게 설치된 플러그인 폴더를 삭제하면 대부분의 AccessDeniedException이 해결된다.**

## 나중에 더 깊게 들어가면

- Windows 파일 잠금 분석 도구(Process Explorer, Handle)로 잠금 보유자 특정하기
- IntelliJ 플러그인을 오프라인(zip) 방식으로 설치하는 방법
- 기업 환경에서 그룹 정책으로 플러그인 경로 권한 일괄 설정하기
