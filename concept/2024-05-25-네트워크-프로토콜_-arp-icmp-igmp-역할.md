# 네트워크 프로토콜: ARP, ICMP, IGMP 역할

> **TL;DR**
> IP 주소만으로는 실제 데이터를 전달할 수 없다. ARP는 IP를 MAC 주소로 바꾸고, ICMP는 전달 실패를 알리며, IGMP는 그룹 통신을 관리한다.

---

## 이 프로토콜들을 왜 쓰는지 감 잡기

인터넷에서 데이터를 보낼 때 IP 주소는 "어디로 보낼지"를 알려주는 논리적 주소다. 그런데 실제 케이블이나 와이파이 수준에서는 MAC 주소라는 물리적 주소가 필요하다. IP만 알고 MAC을 모르면 패킷을 전달할 수 없다. 또한 IP는 신뢰성을 보장하지 않기 때문에, 패킷이 도달하지 못했을 때 이를 알릴 별도 수단이 필요하다. 그리고 같은 영상 스트림을 여러 수신자에게 동시에 보낼 때는 일대일 전송을 반복하는 것보다 그룹 전송이 훨씬 효율적이다. ARP, ICMP, IGMP는 각각 이 세 가지 문제를 해결하기 위해 만들어졌다.

초보자는 처음에 이렇게 이해하면 된다.

`IP 주소 확인 → ARP로 MAC 주소 획득 → 실제 프레임 전송 → 실패 시 ICMP 오류 반환 / 그룹 대상이면 IGMP 관리`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| ARP (Address Resolution Protocol) | IP 주소를 MAC 주소로 변환해 주는 프로토콜. "이 IP를 쓰는 장비의 물리 주소가 뭐야?"라고 네트워크에 물어보는 행위다. |
| MAC 주소 | 네트워크 카드에 고정된 물리적 식별자. IP는 바뀔 수 있지만 MAC은 하드웨어에 부여된다. |
| ICMP (Internet Control Message Protocol) | 네트워크 오류나 상태를 알리는 제어 메시지 프로토콜. `ping`이 이것을 사용한다. |
| IGMP (Internet Group Management Protocol) | 멀티캐스트 그룹 구성원을 관리하는 프로토콜. 라우터가 "이 그룹에 참여한 장비가 있나?"를 파악하는 데 쓴다. |
| 멀티캐스트 | 1대다 전송에서 "특정 그룹"에만 보내는 방식. 브로드캐스트처럼 모두에게 뿌리지 않고 관심 있는 수신자에게만 전달한다. |

## 예를 들어 설명하면

내 컴퓨터(IP: 192.168.1.10)가 같은 네트워크의 서버(IP: 192.168.1.20)에 데이터를 보내려 한다.

1. ARP Request를 브로드캐스트로 날린다: "192.168.1.20을 쓰는 장비, MAC 주소 알려줘."
2. 해당 서버가 ARP Reply로 자신의 MAC 주소를 응답한다.
3. 이제 이더넷 프레임에 목적지 MAC 주소를 넣어 데이터를 전송한다.

`ping 192.168.1.20`을 실행하면 ICMP Echo Request가 전송되고, 서버가 살아 있으면 ICMP Echo Reply가 돌아온다. 응답이 없으면 "Request timed out"이 표시되어 연결 이상임을 알 수 있다.

## 이 단계에서 중요한 판단 기준

네트워크 통신이 안 될 때 ARP 테이블과 ICMP 응답을 먼저 확인하면 문제가 물리 계층(MAC 해결 실패)인지 라우팅 계층(ICMP 오류)인지 빠르게 구분할 수 있다.

## 한 줄 요약 — 이것만 기억하면 된다

**ARP는 IP-MAC 주소 변환, ICMP는 네트워크 오류 알림, IGMP는 멀티캐스트 그룹 관리 — 세 프로토콜은 IP 자체가 해결하지 못하는 빈틈을 메운다.**

## 나중에 더 깊게 들어가면

- ARP 캐시 포이즈닝(ARP Spoofing) 공격과 방어 방법
- ICMP 메시지 타입 전체 목록과 TTL 초과 메시지가 `traceroute`에 어떻게 활용되는지
- IGMPv2 vs IGMPv3 차이와 Source-Specific Multicast
