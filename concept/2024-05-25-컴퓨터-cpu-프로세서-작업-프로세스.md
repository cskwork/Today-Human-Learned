# 컴퓨터 CPU(프로세서) 작업 프로세스

> **TL;DR**
> 프로세스는 실행 중인 프로그램의 단위이며, CPU를 할당받기 위해 제출 → 준비 → 실행 → 대기 → 종료 순으로 상태가 바뀐다.

---

## 프로세스를 왜 이해해야 하는지 감 잡기

컴퓨터에서 동시에 여러 프로그램이 실행되는 것처럼 보이지만, CPU는 한 번에 하나의 작업만 처리한다. 운영체제는 각 프로그램을 "프로세스"라는 단위로 관리하면서, 누가 CPU를 쓸 차례인지 스케줄링한다. 프로세스의 상태 변화를 이해하면 왜 어떤 프로그램이 멈추거나, 자원을 독점하거나, 비정상 종료되는지 파악할 수 있다.

초보자는 처음에 이렇게 이해하면 된다.

`프로그램 실행 요청 → 준비 큐 대기 → CPU 할당 받아 실행 → I/O 발생 시 대기 → 완료 후 종료`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| 프로세스 | 실행 중이거나 실행 대기 중인 프로그램의 인스턴스. 파일로 저장된 프로그램과 달리 메모리에 올라와 있는 상태다. |
| PCB (Process Control Block) | 운영체제가 프로세스를 관리하기 위해 유지하는 데이터 구조. 프로세스 ID, 상태, 메모리 주소, 실행 시간 등을 저장한다. |
| 준비(Ready) 상태 | CPU를 할당받으면 바로 실행될 수 있지만, 아직 차례를 기다리는 상태. 잡 스케줄러가 이 상태로 전이시킨다. |
| 대기(Waiting) 상태 | 입출력(I/O)이 끝나기를 기다리는 상태. 디스크 읽기나 네트워크 응답 중에 CPU를 반납하고 여기서 기다린다. |
| 컨텍스트 스위칭 | CPU가 한 프로세스에서 다른 프로세스로 전환할 때 현재 프로세스 상태를 PCB에 저장하고 다음 프로세스 상태를 복원하는 작업. |

## 예를 들어 설명하면

Linux에서 프로세스를 직접 확인하는 방법은 다음과 같다.

```bash
# 현재 실행 중인 프로세스 목록 확인
ps aux

# CPU/메모리 사용률 실시간 모니터링
top

# PID 1234인 프로세스 강제 종료
kill 1234
```

프로세스 상태 전이 흐름:

1. 제출: 사용자가 프로그램을 실행 요청
2. 접수: 디스크에 작업이 저장됨
3. 준비: 메모리에 올라와 CPU 대기 중
4. 실행: CPU를 받아 명령어 처리
5. 대기: 파일 읽기 등 I/O 발생, CPU 반납
6. 종료: 모든 처리 완료, 메모리 해제

## 이 단계에서 중요한 판단 기준

프로그램이 느리거나 멈춘 것 같을 때 `top`으로 CPU 점유율과 상태(R=실행, S=수면, D=디스크 대기)를 먼저 확인하면 병목이 CPU 부족인지 I/O 대기인지 빠르게 구분할 수 있다.

## 한 줄 요약 — 이것만 기억하면 된다

**프로세스는 운영체제가 PCB로 관리하는 실행 단위이며, CPU 자원을 놓고 준비-실행-대기 사이를 오가며 경쟁한다.**
