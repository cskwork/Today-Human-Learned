# DB 관계형 데이터 모델의 구성 요소

> **TL;DR**
> 관계형 DB는 테이블 구조(릴레이션)와 그 위에서 동작하는 두 종류의 언어 — 절차적인 관계 대수와 선언적인 관계 해석 — 으로 설명된다.

---

## 관계형 데이터 모델을 왜 쓰는지 감 잡기

데이터를 저장할 때 그냥 파일에 쌓으면 "어떤 고객이 어떤 주문을 했는지" 같은 연결 관계를 표현하기 어렵다. 관계형 모델은 데이터를 표(테이블) 형태로 저장하고, 표와 표 사이의 관계를 수학적으로 정의해서 원하는 데이터를 정확하게 끄집어낼 수 있게 한다. SQL이 이 모델을 기반으로 만들어졌다.

초보자는 처음에 이렇게 이해하면 된다.

`테이블(릴레이션) 정의 → 연산으로 원하는 행/열 추출 → 결과도 테이블`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| 릴레이션(Relation) | 관계형 DB에서 테이블을 부르는 이론적 이름. 행(튜플)과 열(어트리뷰트)로 구성된다. |
| 튜플(Tuple) | 테이블의 한 행. 실제 데이터 한 건을 뜻한다. |
| 어트리뷰트(Attribute) | 테이블의 한 열. 데이터의 속성(이름, 나이, 이메일 등)을 나타낸다. |
| 관계 대수(Relational Algebra) | "무엇을 어떻게 가져올지" 절차를 기술하는 연산 체계. SELECT, PROJECT, JOIN 등이 여기에 속한다. |
| 관계 해석(Relational Calculus) | "무엇을 원하는지"만 선언하는 방식. 절차 없이 조건만 명시한다. SQL의 WHERE 절이 이 개념에 가깝다. |

## 예를 들어 설명하면

관계 대수의 주요 연산을 한 줄씩 정리하면 다음과 같다.

| 연산 | 설명 | SQL 대응 |
|---|---|---|
| 셀렉션 (σ) | 조건에 맞는 행 추출 (수평 부분집합) | `WHERE` |
| 프로젝션 (π) | 원하는 열만 추출 (수직 부분집합) | `SELECT 컬럼명` |
| 조인 (⨝) | 두 테이블을 조건으로 합침 | `JOIN` |
| 합집합 (∪) | 두 테이블의 모든 행 합치기 | `UNION` |
| 차집합 (-) | 한 테이블에서 다른 테이블과 겹치는 행 제거 | `EXCEPT` |

관계 해석은 "나이가 30 이상인 모든 사용자가 존재한다(∃)"처럼 논리 기호로 조건을 표현한다. 관계 대수가 "어떻게"라면, 관계 해석은 "무엇을"에 해당한다.

## 이 단계에서 중요한 판단 기준

SQL 쿼리를 작성할 때 관계 대수 연산(SELECT-PROJECT-JOIN)을 머릿속에서 순서대로 떠올리면, 불필요한 카티션 프로덕트를 피하고 올바른 JOIN 조건을 잡는 데 도움이 된다.

## 한 줄 요약 — 이것만 기억하면 된다

**관계형 모델은 테이블로 데이터를 표현하고, 관계 대수(절차)와 관계 해석(선언)이라는 두 방식으로 데이터를 다룬다 — SQL은 이 둘을 실용적으로 결합한 언어다.**

## 나중에 더 깊게 들어가면

- 카티션 프로덕트와 자연 조인(Natural Join)의 차이
- 정규화(1NF~BCNF)와 릴레이션 설계 원칙
- 관계 해석의 전칭 정량자(∀)와 존재 정량자(∃)를 SQL 서브쿼리로 변환하는 방법
