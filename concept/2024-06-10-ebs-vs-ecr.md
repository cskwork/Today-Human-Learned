# EBS vs ECR — AWS 스토리지 두 가지, 무엇이 다른가

> **TL;DR**
> EBS는 서버에 붙이는 하드디스크고, ECR은 컨테이너 이미지를 보관하는 창고다. 이름이 비슷해서 혼동하기 쉽지만 쓰임새가 완전히 다르다.

---

## EBS vs ECR를 왜 구분해야 하는지 감 잡기

AWS를 처음 접하면 "EBS", "ECR" 두 이름이 비슷하게 느껴진다. 둘 다 스토리지 서비스이고 약자도 비슷하지만, 역할은 전혀 다르다.

EBS(Elastic Block Store)는 EC2 가상 서버에 장착하는 블록 스토리지다. 노트북 안에 들어가는 SSD와 같다고 보면 된다. 서버가 꺼져도 데이터는 남는다.

ECR(Elastic Container Registry)은 Docker 이미지를 저장하고 관리하는 레지스트리다. 개발자가 만든 컨테이너 이미지를 올려두면, ECS나 EKS 같은 컨테이너 실행 환경이 그 이미지를 내려받아 실행한다.

초보자는 이렇게 이해하면 된다.

`핵심 흐름: 코드 작성 → Docker 이미지 빌드 → ECR에 Push → ECS가 Pull → EC2(EBS) 위에서 실행`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| EBS (Elastic Block Store) | EC2 서버에 붙이는 가상 하드디스크. 데이터를 영구 저장한다. |
| ECR (Elastic Container Registry) | Docker 이미지를 올리고 내려받는 저장소. GitHub 같은 역할인데 이미지 전용이다. |
| 블록 스토리지 | 데이터를 고정 크기 블록 단위로 저장하는 방식. 빠르고 직접 마운트할 수 있다. |
| 스냅샷 | EBS 볼륨의 현재 상태를 사진 찍듯 백업하는 기능. 복구나 복제에 쓴다. |
| IAM 정책 | ECR 이미지에 누가 접근할 수 있는지 제어하는 권한 설정. |

## 예를 들어 설명하면

웹 애플리케이션을 Docker로 패키징해서 배포하는 시나리오다.

```bash
# 1. Docker 이미지를 ECR에 올리기
aws ecr get-login-password --region us-east-1 \
  | docker login --username AWS --password-stdin \
    <account_id>.dkr.ecr.us-east-1.amazonaws.com

docker tag my-app:latest <account_id>.dkr.ecr.us-east-1.amazonaws.com/my-app:latest
docker push <account_id>.dkr.ecr.us-east-1.amazonaws.com/my-app:latest

# 2. EC2에 EBS 볼륨 붙이기 (DB 데이터 영구 저장용)
aws ec2 create-volume --size 20 --availability-zone us-east-1a --volume-type gp2
aws ec2 attach-volume --volume-id vol-xxxx --instance-id i-xxxx --device /dev/sdf
```

이미지 배포는 ECR, 데이터 저장은 EBS. 두 가지가 함께 쓰인다.

## 이 단계에서 중요한 판단 기준

"실행 중인 서버의 데이터를 저장해야 하면 EBS, 컨테이너 이미지를 팀 혹은 배포 파이프라인과 공유해야 하면 ECR을 선택한다."

## 한 줄 요약 — 이것만 기억하면 된다

**EBS는 서버의 디스크, ECR은 이미지의 창고다.**

## 나중에 더 깊게 들어가면

- EBS 볼륨 타입 비교 (gp2 vs gp3 vs io1) 및 성능 튜닝
- ECR 라이프사이클 정책으로 오래된 이미지 자동 삭제하기
- ECS/EKS에서 ECR 이미지를 자동으로 Pull하는 배포 파이프라인 구성
