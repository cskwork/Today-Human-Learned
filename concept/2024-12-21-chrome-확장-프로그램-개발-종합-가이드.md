# Chrome 확장 프로그램 개발 — 구조부터 배포까지

> **TL;DR**
> Chrome 확장 프로그램은 manifest.json 하나로 시작하는 미니 웹앱이며, 백그라운드 서비스 워커와 콘텐츠 스크립트가 역할을 분담해 브라우저와 웹페이지를 제어한다.

---

## Chrome 확장 프로그램을 왜 쓰는지 감 잡기

Chrome 확장 프로그램은 브라우저 위에 얹히는 작은 프로그램이다. 광고 차단, 번역, 비밀번호 관리처럼 브라우저 자체 기능을 넘어서는 동작을 HTML·CSS·JavaScript만으로 구현할 수 있다. 별도의 빌드 시스템 없이 텍스트 에디터와 Chrome만 있으면 개발을 시작할 수 있다.

초보자는 이렇게 이해하면 된다. 확장 프로그램은 브라우저가 실행하는 웹사이트와 구조가 거의 같다. 다만 일반 웹페이지가 접근할 수 없는 브라우저 내부 API(탭, 북마크, 알림 등)를 추가로 사용할 수 있다.

`핵심 흐름: manifest.json 선언 → 권한 부여 → 서비스 워커(백그라운드) + 콘텐츠 스크립트(페이지) 실행`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| manifest.json | 확장 프로그램의 신분증. 이름, 버전, 권한, 어떤 스크립트를 쓸지 Chrome에 알린다. |
| 서비스 워커 (background.js) | 브라우저 뒤에서 조용히 대기하다가 이벤트가 발생하면 반응하는 엔진. |
| 콘텐츠 스크립트 | 특정 웹페이지에 주입되어 그 페이지의 HTML을 읽고 수정한다. |
| 팝업 (popup.html) | 툴바 아이콘을 클릭했을 때 나오는 작은 UI 창. 일반 HTML 파일이다. |
| 권한 (permissions) | 확장 프로그램이 탭, 저장소, 알림 등 민감한 기능에 접근하려면 미리 선언해야 한다. |

## 예를 들어 설명하면

가장 단순한 확장 프로그램의 파일 구조와 manifest.json 예시다.

```json
{
  "manifest_version": 3,
  "name": "나의 첫 확장 프로그램",
  "version": "1.0",
  "action": {
    "default_popup": "popup.html"
  },
  "permissions": ["activeTab"],
  "background": {
    "service_worker": "background.js"
  }
}
```

- `manifest_version: 3`은 현재 표준이다. 2는 지원 중단 예정.
- `activeTab` 권한은 사용자가 현재 보고 있는 탭에만 접근할 수 있는 최소 권한이다.
- popup.html은 평범한 HTML 파일. 여기에 버튼을 만들고 popup.js에서 클릭 이벤트를 처리한다.

로드 방법: `chrome://extensions` → 개발자 모드 켜기 → "압축 해제된 확장 프로그램 로드" → 폴더 선택.

## 이 단계에서 중요한 판단 기준

필요 이상의 권한을 요청하지 않는다 — 권한이 많을수록 Chrome 웹 스토어 심사가 까다롭고 사용자 신뢰를 잃기 쉽다.

## 한 줄 요약 — 이것만 기억하면 된다

**manifest.json이 전체 설계도이고, 서비스 워커는 브라우저 이벤트를, 콘텐츠 스크립트는 웹페이지 DOM을 담당한다.**

## 나중에 더 깊게 들어가면

- `chrome.runtime.sendMessage`를 이용한 서비스 워커 ↔ 콘텐츠 스크립트 메시지 전달
- `chrome.storage.sync`로 여러 기기 간 설정 동기화
- `chrome.declarativeNetRequest`로 네트워크 요청 선언적 차단 (광고 차단기 핵심 API)
