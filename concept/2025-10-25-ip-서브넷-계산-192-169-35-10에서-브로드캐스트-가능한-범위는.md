# IP 서브넷 계산 — 192.169.35.10에서 브로드캐스트 가능한 범위는?

> **TL;DR**
> IP 주소와 서브넷 마스크를 AND 연산하면 네트워크 주소가, 호스트 비트를 모두 1로 채우면 브로드캐스트 주소가 나온다.

---

## 서브넷을 왜 쓰는지 감 잡기

큰 회사 네트워크에 수천 대 PC가 하나의 대역에 몰려 있다면, 누군가 브로드캐스트 패킷을 보낼 때 전 장비가 처리를 멈추고 응답해야 한다. 이를 막기 위해 네트워크를 더 작은 단위인 서브넷으로 나눈다. 서브넷을 나누면 브로드캐스트 범위가 제한되고, 보안 정책도 그룹별로 적용할 수 있다.

계산의 핵심 흐름은 이렇다.

`IP AND 서브넷 마스크 → 네트워크 주소 → 호스트 비트를 모두 1로 → 브로드캐스트 주소`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| IP 주소 | 네트워크에서 장치를 구별하는 고유 번호 (예: 192.169.35.10) |
| 서브넷 마스크 | IP에서 "네트워크 영역"과 "장치 영역"을 구분하는 필터 |
| 네트워크 주소 | 서브넷의 시작 주소, 장치에 직접 할당할 수 없음 |
| 브로드캐스트 주소 | 서브넷 안 모든 장치에 동시에 보낼 때 쓰는 끝 주소 |
| 호스트 범위 | 실제 장치에 할당 가능한 IP 구간 (네트워크+1 ~ 브로드캐스트-1) |

## 예를 들어 설명하면

주어진 정보: IP `192.169.35.10`, 서브넷 마스크 `255.255.252.0`

핵심은 3번째 옥텟(35와 252)을 2진수로 AND 연산하는 것이다.

```
IP 3번째 옥텟   35: 0010 0011
서브넷 마스크  252: 1111 1100
AND 결과        32: 0010 0000  ← 네트워크 주소의 3번째 옥텟
```

네트워크 주소: `192.169.32.0`

브로드캐스트 주소는 호스트 비트(하위 10비트)를 전부 1로 바꾼다.

- 3번째 옥텟: `0010 0000` → `0010 0011` = 35
- 4번째 옥텟: `0000 0000` → `1111 1111` = 255

브로드캐스트 주소: `192.169.35.255`

사용 가능한 IP 범위: `192.169.32.1` ~ `192.169.35.254` (총 1022개)

검증: 192.169.32.1 <= **192.169.35.10** <= 192.169.35.254 — 정상 범위 안에 있음.

## 이 단계에서 중요한 판단 기준

서브넷 마스크에서 0이 연속되는 비트 수가 호스트 비트 수이고, 2^(호스트 비트) - 2가 사용 가능한 IP 개수다.

## 한 줄 요약 — 이것만 기억하면 된다

**IP AND 서브넷 마스크 = 네트워크 주소, 호스트 비트 전부 1 = 브로드캐스트 주소.**

## 나중에 더 깊게 들어가면

- CIDR 표기법 (/22, /24)과 서브넷 마스크의 관계
- VLSM(가변 길이 서브넷 마스크)으로 주소 공간 최적화하기
- 방화벽 ACL에서 네트워크 주소 범위를 활용하는 방법
