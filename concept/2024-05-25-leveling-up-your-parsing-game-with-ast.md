# AST — 코드를 기계가 읽는 방식

> **TL;DR**
> 코드는 텍스트가 아니라 트리 구조로 변환돼야 컴퓨터가 이해할 수 있고, AST는 그 트리에서 불필요한 문법 껍데기를 제거한 핵심 구조다.

---

## AST를 왜 쓰는지 감 잡기

사람은 "2 + 3 * 4"를 보면 곱셈이 먼저라는 걸 자연스럽게 안다. 컴퓨터는 그렇지 않다. 그냥 문자열일 뿐이다. 컴파일러나 인터프리터가 코드를 실행하려면 먼저 그 텍스트를 의미 있는 구조로 바꿔야 한다. 이 구조가 트리(Tree) 형태이고, 파싱(Parsing)이 그 변환 작업이다.

처음에는 Parse Tree(파스 트리)라는 완전한 문법 구조를 만든다. 그런데 실제 분석에는 괄호나 세미콜론 같은 문법 껍데기가 필요 없다. 그래서 필요한 정보만 남긴 것이 AST(Abstract Syntax Tree, 추상 구문 트리)다.

초보자는 처음에 이렇게 이해하면 된다.

`핵심 흐름: 소스 코드(텍스트) → 파싱 → Parse Tree → 불필요 제거 → AST → 분석/실행`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| 파싱(Parsing) | 텍스트를 읽어서 문법 구조로 해석하는 과정 |
| Parse Tree | 소스 코드의 문법 구조를 완전하게 담은 트리. 괄호, 세미콜론도 모두 포함 |
| AST | Parse Tree에서 실행과 분석에 불필요한 부분을 제거한 간결한 트리 |
| 노드(Node) | 트리를 구성하는 각각의 요소. 예: 연산자, 변수, 리터럴 |
| 추상화(Abstraction) | 세부 구현을 숨기고 핵심만 드러내는 것. AST에서 "Abstract"가 이 뜻 |

## 예를 들어 설명하면

`2 + 3 * 4` 라는 표현식을 파싱하면 다음과 같은 AST가 만들어진다.

```
    +
   / \
  2   *
     / \
    3   4
```

루트 노드가 `+`이고, 오른쪽 자식이 `*`다. 이 구조 덕분에 컴퓨터는 곱셈을 먼저 계산해야 한다는 걸 트리 순회만으로 알 수 있다. 괄호 같은 문법 기호는 이 트리에 없다. 이미 구조 자체에 우선순위가 반영됐기 때문이다.

## 이 단계에서 중요한 판단 기준

코드를 분석하거나 변환하는 도구(린터, 컴파일러, 코드 포매터 등)를 만들 때는 텍스트를 직접 다루지 말고 AST를 다뤄야 정확하고 안전하다.

## 한 줄 요약 — 이것만 기억하면 된다

**AST는 소스 코드의 의미 구조만 뽑아낸 트리이며, 컴파일러와 개발 도구 대부분이 이것을 기반으로 작동한다.**

## 나중에 더 깊게 들어가면

- 컴파일러의 전체 파이프라인: 렉싱(Lexing) → 파싱 → AST → 코드 생성
- Babel, ESLint, Prettier 같은 JS 도구가 AST를 어떻게 조작하는지
- 방문자 패턴(Visitor Pattern)으로 AST 노드를 순회하는 방법
