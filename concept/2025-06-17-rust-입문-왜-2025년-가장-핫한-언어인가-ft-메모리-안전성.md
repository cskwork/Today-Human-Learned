# Rust 입문 — 왜 2025년 가장 핫한 언어인가 (ft. 메모리 안전성)

> **TL;DR**
> Rust는 GC(가비지 컬렉터) 없이도 메모리 안전성을 컴파일 타임에 보장하는 시스템 프로그래밍 언어다.

---

## Rust를 왜 쓰는지 감 잡기

C와 C++는 빠르지만 메모리 관련 버그가 전체 보안 취약점의 70%를 차지한다. Java나 C#은 메모리를 GC가 자동으로 정리해주지만, 그 비용으로 예측 불가능한 성능 저하가 생긴다. Python은 편리하지만 느리다.

Rust는 이 트레이드오프를 정면으로 해결한다. GC 없이도 컴파일러가 메모리 오류를 아예 막는다. 프로그램이 실행되기 전에 잘못된 메모리 접근을 코드 오류로 내보내기 때문에, 런타임에서 죽는 일이 구조적으로 줄어든다.

초보자는 처음에 이렇게 이해하면 된다.

`핵심 흐름: 소유권 규칙 → 컴파일러 검증 → 런타임 안전`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| 소유권(Ownership) | 모든 값은 딱 하나의 변수만 "주인"으로 가진다. 주인이 없어지면 값도 사라진다. |
| 이동(Move) | 값을 다른 변수에 대입하면 소유권이 넘어간다. 이전 변수는 더 이상 사용할 수 없다. |
| 빌림(Borrowing) | `&`를 붙이면 소유권을 넘기지 않고 값을 잠깐 빌려 쓸 수 있다. |
| 생명주기(Lifetime) | 빌린 참조가 원본보다 오래 살아있으면 안 된다는 컴파일러의 유효기간 추적 시스템. |
| Zero-cost Abstraction | 반복자, 클로저 같은 고수준 기능을 써도 C와 동일한 성능이 나온다는 Rust의 보장. |

## 예를 들어 설명하면

소유권 이동과 빌림의 차이를 코드로 보면 바로 이해된다.

```rust
fn main() {
    let s1 = String::from("hello");
    let s2 = s1;              // 소유권이 s2로 이동
    // println!("{}", s1);   // 컴파일 에러: s1은 더 이상 유효하지 않음

    let s3 = String::from("world");
    let len = calculate_length(&s3); // s3를 빌려줌, 소유권 유지
    println!("{}의 길이: {}", s3, len); // s3 여전히 사용 가능
}

fn calculate_length(s: &String) -> usize {
    s.len()
}
```

빌림(`&`)을 쓰면 함수가 값을 사용하되 소유권을 가져가지 않는다. 이 규칙 하나가 use-after-free, double-free 같은 고전적 메모리 버그를 컴파일 단계에서 원천 차단한다.

## 이 단계에서 중요한 판단 기준

Rust를 선택할 때 핵심 질문은 "런타임 성능과 메모리 안전성을 동시에 포기할 수 없는가?"이다. 그렇다면 Rust가 정답이고, 개발 속도가 최우선이라면 Go나 Python이 나을 수 있다.

## 한 줄 요약 — 이것만 기억하면 된다

**소유권 시스템은 GC 없이 메모리 안전을 보장하는 Rust의 핵심 아이디어이고, 이 규칙은 컴파일러가 자동으로 검사한다.**

## 나중에 더 깊게 들어가면

- 생명주기 어노테이션(`'a`)과 컴파일러가 추론하는 방식
- `Result<T, E>`와 `?` 연산자를 이용한 에러 처리 패턴
- Trait 기반 다형성과 제네릭 프로그래밍
