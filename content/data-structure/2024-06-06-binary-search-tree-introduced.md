> **TL;DR**
> BST는 모든 노드가 "왼쪽 자식 < 나 < 오른쪽 자식" 규칙을 지켜, 매 단계마다 탐색 범위를 절반씩 줄인다.

---

## BST를 왜 쓰는지 감 잡기

배열에서 값을 찾으려면 처음부터 하나씩 비교해야 하므로 최악 N번이 걸린다. BST는 노드를 삽입할 때 규칙을 지키면, 나중에 검색할 때 매 단계에서 절반을 건너뛸 수 있다. 도서관 서가를 가나다 순으로 정리하면 책을 찾을 때 왼쪽·오른쪽 구역으로 나눠 빠르게 찾는 것과 같다.

BST는 데이터베이스 인덱스, 파일 시스템, 자동완성 기능 등 "정렬된 데이터에서 빠른 검색·삽입·삭제"가 필요한 곳에 쓰인다.

`핵심 흐름: 루트에서 시작 → 값 비교 → 작으면 왼쪽, 크면 오른쪽 → 목표 노드 도달`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| 노드(Node) | 트리의 기본 단위. 값 하나와 왼쪽·오른쪽 자식을 가리키는 두 포인터를 갖는다. |
| 루트(Root) | 트리의 최상단 노드. 검색은 항상 여기서 시작한다. |
| 리프(Leaf) | 자식이 없는 말단 노드. |
| 왼쪽 서브트리 | 어떤 노드의 왼쪽에 달린 모든 노드. 해당 노드보다 값이 작다. |
| 오른쪽 서브트리 | 어떤 노드의 오른쪽에 달린 모든 노드. 해당 노드보다 값이 크다. |

## 예를 들어 설명하면

`[50, 30, 70, 20, 40, 60, 80]`을 순서대로 삽입하면 아래 구조가 된다.

```
        50
       /  \
      30   70
     / \   / \
    20  40 60  80
```

값 60을 검색하는 과정:

1. 루트 50 확인: 60 > 50 → 오른쪽으로 이동
2. 노드 70 확인: 60 < 70 → 왼쪽으로 이동
3. 노드 60 확인: 일치 → 탐색 완료

7개 노드에서 3단계만에 찾았다. 배열이었다면 최악 7단계였을 것이다.

삭제는 세 가지 경우를 처리해야 한다: 자식이 없으면 바로 제거, 자식이 하나면 그 자식으로 대체, 자식이 둘이면 오른쪽 서브트리에서 가장 작은 값(후계자)으로 대체한다.

## 이 단계에서 중요한 판단 기준

"BST의 성능은 트리의 균형에 달려 있다. 이미 정렬된 데이터를 순서대로 삽입하면 트리가 한쪽으로 쏠려 최악 O(N)이 된다."

## 한 줄 요약 — 이것만 기억하면 된다

**BST는 왼쪽-작음, 오른쪽-큼 규칙 하나로 매 단계마다 탐색 범위를 절반씩 줄여 평균 O(log N) 검색을 달성한다.**

## 나중에 더 깊게 들어가면

- 균형 이진 탐색 트리: AVL 트리, 레드-블랙 트리가 편향 문제를 어떻게 해결하는가
- 중위 순회(In-order Traversal): BST를 오름차순으로 출력하는 방법
- BST vs 해시맵: 검색 속도와 정렬 지원 면에서 어떤 상황에 무엇을 쓸지
