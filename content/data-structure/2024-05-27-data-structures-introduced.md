## 자료구조를 왜 쓰는지 감 잡기

같은 데이터라도 어떻게 저장하느냐에 따라 "찾는 데 1초" vs "찾는 데 1분"의 차이가 생긴다. 도서관에서 책을 그냥 바닥에 쌓아 두면 찾기 힘들지만, 장르별·가나다 순으로 꽂으면 금방 찾는다. 자료구조는 바로 그 "정리 방식"이다.

자료구조는 크게 두 종류로 나뉜다. 데이터를 일렬로 늘어놓는 선형 구조와, 계층이나 망처럼 연결하는 비선형 구조다.

`핵심 흐름: 문제 분석 → 필요한 연산 파악 → 적합한 자료구조 선택 → 구현`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| 배열(Array) | 번호가 매겨진 칸이 일렬로 붙어 있는 구조. 인덱스로 어느 칸이든 즉시 접근 가능하다. |
| 스택(Stack) | 접시를 쌓는 구조. 마지막에 올린 것을 가장 먼저 꺼낸다(LIFO). |
| 큐(Queue) | 줄 서기 구조. 먼저 들어온 것이 먼저 나간다(FIFO). |
| 트리(Tree) | 하나의 뿌리에서 가지가 뻗어 나가는 계층 구조. 부모-자식 관계로 표현한다. |
| 그래프(Graph) | 점(노드)과 선(엣지)으로 연결 관계를 표현하는 구조. 도로망이나 SNS 친구 관계가 대표 예다. |

## 예를 들어 설명하면

스택은 함수 호출 순서를 추적하는 데 쓰인다. 함수 A가 B를 호출하고 B가 C를 호출하면, C가 끝나야 B가 끝나고 B가 끝나야 A가 끝난다. 이 "마지막에 호출된 것이 가장 먼저 반환" 구조가 정확히 LIFO다.

```python
stack = []
stack.append("A")   # A 호출
stack.append("B")   # B 호출
stack.append("C")   # C 호출
print(stack.pop())  # C 반환 → "C"
print(stack.pop())  # B 반환 → "B"
print(stack.pop())  # A 반환 → "A"
```

큐는 반대로 먼저 들어온 것이 먼저 나간다. 프린터 출력 대기열, 서버 요청 처리 등에 쓰인다.

## 이 단계에서 중요한 판단 기준

"어떤 연산이 가장 자주 일어나는가"를 먼저 파악하면 자료구조 선택의 절반은 끝난다. 검색이 잦으면 트리, 순서가 중요하면 큐나 스택, 임의 접근이 필요하면 배열이 우선순위다.

## 한 줄 요약 — 이것만 기억하면 된다

**자료구조는 데이터를 어떻게 담느냐의 문제이며, 어떤 연산을 자주 쓰느냐에 따라 선택이 달라진다.**

## 나중에 더 깊게 들어가면

- 각 자료구조의 시간 복잡도(Big-O) 비교표
- 링크드 리스트: 배열과 어떻게 다르고 어떤 상황에 유리한가
- 이진 탐색 트리(BST): 트리에서 빠른 검색이 어떻게 가능한가
