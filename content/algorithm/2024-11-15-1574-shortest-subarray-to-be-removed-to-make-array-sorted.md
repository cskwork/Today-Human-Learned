> **TL;DR**
> 양쪽에서 이미 정렬된 구간을 먼저 확보하고, 투 포인터로 두 구간을 이어 붙일 최소 제거 길이를 찾는다.

---

## 이 문제를 왜 푸는지 감 잡기

정수 배열이 있을 때, 연속된 부분 배열 하나를 잘라내어 남은 배열 전체가 비감소(non-decreasing) 순서가 되도록 만들어야 한다. 이때 잘라내야 할 부분의 길이를 최소화하는 것이 목표다.

실무에서도 로그 데이터나 센서 스트림에서 "망가진 구간"을 제거하고 나머지를 유효하게 유지해야 하는 상황과 비슷한 구조를 가진다.

초보자는 처음에 이렇게 이해하면 된다.

`핵심 흐름: 왼쪽 정렬 구간 확보 → 오른쪽 정렬 구간 확보 → 두 구간을 이어 붙일 경우 탐색 → 최솟값 반환`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| 비감소 수열 | 앞 원소가 뒤 원소보다 크지 않으면 된다. 같아도 OK |
| 부분 배열(subarray) | 배열 안에서 연속된 원소들의 묶음 |
| 투 포인터 | 두 개의 인덱스를 양쪽에서 좁혀가며 비교하는 탐색 기법 |
| left / right 포인터 | 왼쪽 정렬 구간의 끝, 오른쪽 정렬 구간의 시작 인덱스 |
| O(n) 시간 복잡도 | 배열을 최대 두 번 순회하므로 선형 시간으로 풀린다 |

## 예를 들어 설명하면

입력 `[1, 2, 3, 10, 4, 2, 3, 5]`를 기준으로 단계별로 보면:

```java
// 1단계: 왼쪽에서 비감소 구간 끝 찾기
// [1, 2, 3, 10] → left = 3

// 2단계: 오른쪽에서 비감소 구간 시작 찾기
// [2, 3, 5] → right = 5

// 3단계: 기본 후보 두 가지
// - 왼쪽만 남기면 오른쪽 4개 제거
// - 오른쪽만 남기면 왼쪽 5개 제거
// result = min(4, 5) = 4

// 4단계: 두 구간을 이어 붙이는 경우 탐색
// i=0..3, j=5..7 에서 arr[i] <= arr[j] 이면 j-i-1 계산
// arr[3]=10 > arr[5]=2 → j++
// arr[3]=10 > arr[6]=3 → j++
// arr[3]=10 > arr[7]=5 → j++
// i=0, j=5: 1<=2 → j-i-1=3 → result=3
// 최종 결과: 3
```

## 이 단계에서 중요한 판단 기준

배열 양 끝의 정렬된 구간을 먼저 고정하고, 그 사이를 채울 수 있는지 투 포인터로 확인하는 것이 핵심이다. 전체를 브루트포스로 탐색하면 O(n²)이 되지만, 이 접근법은 O(n)에 해결한다.

## 한 줄 요약 — 이것만 기억하면 된다

**왼쪽-오른쪽 정렬 구간을 미리 확보하고, 두 구간을 연결할 최소 제거 길이를 투 포인터로 좁힌다.**

## 나중에 더 깊게 들어가면

- 투 포인터가 O(n²)을 O(n)으로 줄이는 일반 원리
- 이진 탐색을 활용한 유사 문제 풀이 방식
- 슬라이딩 윈도우와 투 포인터의 차이점
