> **TL;DR**
> 재귀는 큰 문제를 같은 구조의 더 작은 문제로 쪼개어, 함수가 자기 자신을 호출해 해결하는 기법이며, 반드시 멈추는 조건(기저 사례)이 있어야 한다.

---

## 재귀를 왜 쓰는지 감 잡기

어떤 문제는 "전체를 한꺼번에 풀기"보다 "같은 형태의 더 작은 문제로 쪼개기"가 훨씬 자연스럽다. 폴더 안에 폴더가 있고, 그 안에 또 폴더가 있는 파일 시스템을 탐색하거나, 수식 트리를 계산하거나, 분할 정복 알고리즘을 구현할 때가 그렇다.

재귀를 쓰면 반복문으로 직접 관리해야 할 복잡한 상태(스택, 인덱스)를 함수 호출 스택이 대신 처리해준다. 코드가 짧고 문제의 구조를 그대로 표현한다는 게 가장 큰 장점이다.

초보자는 처음에 이렇게 이해하면 된다.

`핵심 흐름: 기저 사례 확인 → 해당하면 즉시 반환 → 아니면 더 작은 입력으로 자기 자신 호출 → 결과 합산`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| 기저 사례(Base Case) | 재귀가 멈추는 조건. 이게 없으면 함수가 끝없이 자기 자신을 부른다 |
| 재귀 사례(Recursive Case) | 함수가 자기 자신을 더 작은 입력으로 호출하는 부분 |
| 호출 스택(Call Stack) | 함수 호출이 쌓이는 메모리 공간. 재귀가 깊을수록 이 스택이 커진다 |
| 스택 오버플로(Stack Overflow) | 기저 사례 없이 너무 깊이 재귀하면 호출 스택이 꽉 차서 프로그램이 멈추는 현상 |
| 분할 정복(Divide and Conquer) | 재귀를 이용해 문제를 반복적으로 절반으로 쪼개어 해결하는 전략 |

## 예를 들어 설명하면

팩토리얼(n!)을 재귀로 구현하면 문제의 구조가 코드에 그대로 드러난다.

```python
def factorial(n):
    if n == 1:            # 기저 사례: 멈추는 조건
        return 1
    return n * factorial(n - 1)  # 재귀 사례: 더 작은 문제로 위임
```

`factorial(4)` 호출 흐름:

```
factorial(4) → 4 * factorial(3)
                     → 3 * factorial(2)
                                → 2 * factorial(1)
                                           → 1   (기저 사례, 반환 시작)
                                → 2 * 1 = 2
                     → 3 * 2 = 6
factorial(4) → 4 * 6 = 24
```

각 호출은 자신보다 작은 문제를 아래에 맡기고 기다린다. 기저 사례에서 반환이 시작되면 쌓였던 호출이 역순으로 결과를 돌려준다.

## 이 단계에서 중요한 판단 기준

재귀를 쓸 때는 항상 "기저 사례가 반드시 도달 가능한가?"를 먼저 확인한다. 도달 불가능한 기저 사례는 스택 오버플로로 직결된다.

## 한 줄 요약 — 이것만 기억하면 된다

**기저 사례(멈추는 조건)와 재귀 사례(더 작은 입력으로 자기 자신 호출) 두 가지가 갖춰져야 재귀가 올바르게 동작한다.**

## 나중에 더 깊게 들어가면

- 꼬리 재귀(Tail Recursion)와 컴파일러 최적화: 스택을 쌓지 않고 재귀하는 방법
- 메모이제이션(Memoization): 피보나치처럼 중복 계산이 많은 재귀의 성능을 개선하는 기법
- 재귀를 반복문으로 변환: 명시적 스택을 이용한 동등한 반복 구현
