> **TL;DR**
> 삽입 정렬은 데이터가 늘어날수록 비교와 이동 횟수가 제곱으로 불어나기 때문에, 수천 개 이상의 데이터에서는 쓰지 않는 것이 낫다.

---

## 삽입 정렬을 왜 쓰는지 감 잡기

삽입 정렬은 손에 쥔 카드를 하나씩 제자리에 끼워넣는 방식으로 작동한다. 처음에는 직관적이고 구현이 쉬워서 작은 배열이나 거의 정렬된 배열에 자주 쓰인다. 실제로 많은 표준 라이브러리가 배열 크기가 작을 때 내부적으로 삽입 정렬을 쓴다.

문제는 배열이 커질수록 "제자리 찾기" 비용이 급격히 늘어난다는 점이다. 새 원소를 삽입할 때 이미 정렬된 부분의 원소들을 한 칸씩 밀어야 하는데, 최악의 경우(역순 배열) 원소 하나당 n번 이동이 발생한다.

초보자는 처음에 이렇게 이해하면 된다.

`핵심 흐름: 새 원소 선택 → 정렬된 부분과 비교 → 오른쪽으로 밀면서 빈자리 확보 → 삽입`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| 시간 복잡도 | 데이터 수(n)가 늘 때 연산 횟수가 얼마나 빨리 느는지를 나타내는 척도 |
| O(n²) | n이 두 배가 되면 연산이 네 배로 느는 "제곱 성장" 패턴 |
| 비교(comparison) | 두 원소의 크기를 따지는 연산 — 정렬의 기본 단위 |
| 이동(shift) | 새 원소 자리를 만들기 위해 기존 원소를 한 칸 옆으로 옮기는 작업 |
| 최선/최악 케이스 | 이미 정렬된 배열이면 O(n)으로 빠르지만, 역순이면 O(n²)으로 가장 느리다 |

## 예를 들어 설명하면

배열 `[5, 3, 4, 1, 2]`를 삽입 정렬로 처리하면:

```
단계 1: 3을 삽입 → 5를 오른쪽으로 밀기 → [3, 5, 4, 1, 2]
단계 2: 4를 삽입 → 5를 밀기           → [3, 4, 5, 1, 2]
단계 3: 1을 삽입 → 5, 4, 3을 밀기     → [1, 3, 4, 5, 2]
단계 4: 2를 삽입 → 5, 4, 3을 밀기     → [1, 2, 3, 4, 5]
```

원소 1을 삽입할 때 이미 정렬된 세 원소를 전부 밀었다. n개 원소가 있을 때 이 과정이 반복되면 총 이동 횟수가 n × n에 수렴한다.

## 이 단계에서 중요한 판단 기준

데이터가 100개 미만이거나 "거의 정렬된" 상태라면 삽입 정렬을 써도 무방하지만, 그 이상이면 퀵 정렬이나 병합 정렬처럼 O(n log n) 알고리즘을 선택해야 한다.

## 한 줄 요약 — 이것만 기억하면 된다

**삽입 정렬의 느림은 "이동"이 문제다. 데이터가 클수록 밀어야 할 원소가 많아져 O(n²)이 된다.**

## 나중에 더 깊게 들어가면

- 퀵 정렬과 병합 정렬이 O(n log n)을 달성하는 원리 (분할 정복)
- 팀 정렬(Timsort): 삽입 정렬과 병합 정렬을 혼합한 현실 최적화 알고리즘
- 정렬 알고리즘의 하한선 — 비교 기반 정렬은 O(n log n)보다 빨라질 수 없는 이유
