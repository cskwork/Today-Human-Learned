> **TL;DR**
> 대칭키는 같은 키로 잠그고 풀어서 빠르지만 키 공유가 위험하고, 비대칭키는 공개키로 잠그고 비밀키로 풀어서 느리지만 키를 직접 전달할 필요가 없다.

---

## 암호화를 왜 쓰는지 감 잡기

네트워크를 통해 데이터를 주고받을 때, 중간에서 누군가가 패킷을 가로채도 내용을 읽지 못하게 하는 것이 암호화의 목적이다. 웹사이트 주소 앞에 붙는 HTTPS, 이메일 보안, VPN, 전자 서명이 모두 이 기술 위에서 동작한다.

두 방식은 "열쇠를 몇 개 쓰느냐"로 구분된다. 같은 열쇠 하나를 공유하면 대칭키, 잠그는 열쇠와 여는 열쇠를 따로 두면 비대칭키다.

초보자는 처음에 이렇게 이해하면 된다.

`핵심 흐름(대칭키): 키 공유 → 암호화 → 전송 → 같은 키로 복호화`

`핵심 흐름(비대칭키): 공개키 배포 → 공개키로 암호화 → 전송 → 비밀키로 복호화`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| 암호화(encryption) | 원문을 알아볼 수 없는 형태로 변환하는 과정 |
| 복호화(decryption) | 암호화된 데이터를 다시 원문으로 되돌리는 과정 |
| 공개키(public key) | 누구에게나 줘도 되는 잠금용 열쇠 |
| 비밀키(private key) | 본인만 보관하는 해제용 열쇠. 절대 외부에 노출하면 안 된다 |
| AES / RSA | AES는 대칭키의 현재 표준, RSA는 비대칭키의 가장 널리 쓰이는 방식 |

## 예를 들어 설명하면

현실에서 두 방식을 나란히 비교하면:

| 상황 | 대칭키 (AES) | 비대칭키 (RSA) |
|---|---|---|
| 비유 | 서로 같은 자물쇠 복사본을 가진 친구들 | 우체통(공개)과 열쇠(나만 보유) |
| 키 전달 | 키를 안전하게 먼저 공유해야 함 | 공개키는 누구에게나 공개 가능 |
| 속도 | 빠름 — 대용량 파일 암호화에 적합 | 느림 — 짧은 데이터나 키 교환에 사용 |
| 주요 사용처 | 파일 암호화, DB 보안, VPN | HTTPS 핸드셰이크, 디지털 서명, 이메일 |

실제 HTTPS는 두 방식을 조합한다. 비대칭키로 세션 키를 안전하게 교환한 뒤, 이후 통신은 대칭키(AES)로 빠르게 처리한다.

## 이 단계에서 중요한 판단 기준

키를 상대방과 안전하게 사전 공유할 수 있다면 대칭키를, 그렇지 않거나 신원 검증이 필요하다면 비대칭키를 선택한다. 대부분의 실제 시스템은 둘을 혼합해서 쓴다.

## 한 줄 요약 — 이것만 기억하면 된다

**대칭키는 빠르지만 키 공유가 약점이고, 비대칭키는 키 공유 문제를 없애지만 느리다. 실전에서는 둘을 함께 쓴다.**

## 나중에 더 깊게 들어가면

- TLS 핸드셰이크 — 비대칭키와 대칭키가 어떤 순서로 협력하는지
- 디지털 서명 — 비밀키로 서명하고 공개키로 검증하는 역방향 사용법
- ECC(타원 곡선 암호화) — RSA보다 짧은 키로 같은 보안 수준을 달성하는 방법
