> 출발점에서 모든 노드까지의 최단 거리를 한 번의 탐색으로 구하는 알고리즘으로, 현재까지 가장 짧은 경로를 가진 노드부터 차례로 확장한다.

---

## 다익스트라 알고리즘을 왜 쓰는지 감 잡기

지도 앱이 "지금 출발하면 가장 빠른 경로는 이쪽입니다"라고 알려줄 때, 내부에서 비슷한 원리가 동작한다. 도시(노드)와 도로(엣지), 그리고 각 도로에 붙은 거리(가중치)가 있을 때, 출발지에서 목적지까지 비용이 가장 적게 드는 경로를 찾는 것이 문제다.

단순히 모든 경우의 수를 따지면 너무 오래 걸린다. 다익스트라는 "지금까지 가장 가까운 곳부터 먼저 확인한다"는 탐욕적(greedy) 전략으로 이 탐색 범위를 크게 줄인다.

초보자는 처음에 이렇게 이해하면 된다.

`핵심 흐름: 출발 노드 거리 = 0 → 가장 가까운 미방문 노드 선택 → 이웃 노드 거리 갱신 → 반복`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| 노드(Node) | 지도의 도시처럼, 그래프 안의 각 지점 |
| 엣지(Edge) | 두 노드를 잇는 길. 여기서는 방향과 비용(가중치)이 있다 |
| 가중치(Weight) | 두 노드 사이를 이동하는 비용. 거리, 시간, 요금 등 무엇이든 될 수 있다 |
| 우선순위 큐(Priority Queue) | "가장 짧은 거리" 노드를 빠르게 꺼낼 수 있는 자료구조. 일반 큐와 달리 값이 작은 것을 먼저 뱉는다 |
| 완화(Relaxation) | 더 짧은 경로를 발견했을 때 기존 거리 값을 업데이트하는 동작 |

## 예를 들어 설명하면

노드 A, B, C, D, E와 아래 가중치가 있다고 하자.

```
A-B: 4   A-C: 2
B-C: 5   B-D: 10
C-E: 3   D-E: 4
```

A에서 E까지 최단 경로를 구하는 과정:

1. A=0, 나머지=무한대로 초기화
2. A에서 이웃 탐색 → B=4, C=2
3. 가장 짧은 C(2) 선택 → C에서 E 탐색 → E=2+3=5
4. 다음으로 짧은 B(4) 선택 → B에서 D 탐색 → D=4+10=14
5. E(5)가 D(14)보다 짧으므로 E 선택 → 도착

최단 경로: A → C → E, 총 비용 5

## 이 단계에서 중요한 판단 기준

다익스트라는 가중치가 모두 0 이상인 그래프에서만 올바르게 동작한다. 음수 가중치가 있으면 벨만-포드 알고리즘을 써야 한다.

## 한 줄 요약 — 이것만 기억하면 된다

**현재까지 가장 짧은 거리의 노드부터 차례로 확장하면, 출발점에서 모든 노드까지의 최단 경로가 보장된다.**

## 나중에 더 깊게 들어가면

- 음수 가중치 처리: 벨만-포드 알고리즘
- 더 빠른 우선순위 큐 구현: 피보나치 힙 적용
- 실제 경로 추적: 이전 노드(predecessor)를 기록하는 방법
