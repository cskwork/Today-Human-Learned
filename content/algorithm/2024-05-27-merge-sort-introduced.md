> **TL;DR**
> 배열을 반씩 재귀적으로 쪼갠 뒤, 두 정렬된 조각을 순서대로 합치는 분할 정복 정렬 알고리즘으로, 항상 O(n log n)을 보장한다.

---

## 병합 정렬을 왜 쓰는지 감 잡기

책 더미를 정리한다고 하자. 전체를 한 번에 정리하려면 막막하다. 대신 절반으로 나누고, 각 절반을 또 나누기를 반복해 한 권짜리 더미까지 쪼갠다. 한 권짜리는 이미 정렬된 상태다. 이제 두 더미를 크기 순서로 비교하며 합치면, 합쳐진 더미도 정렬된 상태가 된다. 이 합치기를 반복하면 전체가 정렬된다.

병합 정렬은 데이터 크기에 관계없이 항상 O(n log n) 시간이 걸리고, 같은 값의 순서가 바뀌지 않는 안정 정렬(stable sort)이다. 연결 리스트 정렬이나 외부 정렬(디스크에 있는 대용량 데이터 정렬)에서 특히 유리하다.

초보자는 처음에 이렇게 이해하면 된다.

`핵심 흐름: 배열을 절반으로 분할 → 각 절반을 재귀 정렬 → 두 정렬된 절반을 병합 → 완성`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| 분할(Divide) | 배열을 두 절반으로 나누는 단계. 원소가 하나가 될 때까지 계속 나눈다 |
| 정복(Conquer) | 나눠진 각 절반을 재귀적으로 정렬하는 단계 |
| 병합(Merge) | 정렬된 두 배열을 비교하며 하나의 정렬된 배열로 합치는 핵심 단계 |
| 안정 정렬(Stable Sort) | 같은 값이 두 개 있을 때 원래 순서가 유지되는 성질 |
| 재귀(Recursion) | 함수가 자기 자신을 호출해 더 작은 문제를 해결하는 기법 |

## 예를 들어 설명하면

`[38, 27, 43, 3]`을 정렬한다.

```
분할:
  [38, 27, 43, 3]
  → [38, 27]  [43, 3]
  → [38] [27]  [43] [3]

병합 (한 원소짜리는 이미 정렬됨):
  [38] + [27] → [27, 38]
  [43] + [3]  → [3, 43]

최종 병합:
  [27, 38] + [3, 43]
  → 27 vs 3:  3
  → 27 vs 43: 27
  → 38 vs 43: 38
  → 남은 43
  → [3, 27, 38, 43]
```

병합 단계에서는 두 배열의 맨 앞 원소만 비교하면 되므로, 한 번의 병합은 O(n) 시간이면 충분하다.

## 이 단계에서 중요한 판단 기준

병합 정렬은 추가 메모리(O(n))가 필요하다. 메모리 제약이 심하면 퀵 정렬(in-place)이 더 적합하고, 안정성이나 최악 성능 보장이 중요하면 병합 정렬이 낫다.

## 한 줄 요약 — 이것만 기억하면 된다

**배열을 원소 하나까지 쪼갠 뒤, 두 정렬된 조각을 순서대로 합치기를 반복하면 전체가 정렬된다.**

## 나중에 더 깊게 들어가면
