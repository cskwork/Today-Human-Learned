> **TL;DR**
> DAG는 방향이 있고 순환이 없는 그래프다. 작업 간 "이것이 끝나야 저것을 할 수 있다"는 의존성을 표현하고, 위상 정렬로 올바른 실행 순서를 자동으로 구한다.

---

## DAG를 왜 쓰는지 감 잡기

여러 작업이 얽혀 있을 때 순서를 잘못 잡으면 시스템이 멈추거나 결과가 틀린다. 예를 들어 데이터 파이프라인에서 정제 단계가 수집보다 먼저 돌면 처리할 데이터가 없다. 단순한 리스트로는 이런 의존성을 표현하기 어렵다.

DAG(Directed Acyclic Graph, 유향 비순환 그래프)는 이 문제를 해결한다. 노드(작업)와 화살표(의존성)로 그래프를 그리면, 어떤 작업이 어떤 작업보다 먼저 실행되어야 하는지 명확해진다. Apache Airflow, Apache Spark, Git 커밋 히스토리 모두 내부적으로 DAG를 사용한다.

초보자는 처음에 이렇게 이해하면 된다.

`핵심 흐름: 노드(작업) 정의 → 의존성 화살표 연결 → 위상 정렬로 실행 순서 확정`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| 노드(Node) | 그래프에서 하나의 작업 단위를 나타내는 점 |
| 엣지(Edge) | 노드 사이의 화살표. "A가 끝나야 B를 시작할 수 있다"는 의존성을 표현 |
| 방향(Directed) | 화살표에 방향이 있어 A→B는 있지만 B→A는 없음 |
| 비순환(Acyclic) | 어느 노드에서 출발해도 자기 자신으로 돌아오는 경로가 없음 |
| 위상 정렬(Topological Sort) | DAG에서 모든 노드를 의존성 순서에 맞게 일렬로 나열하는 알고리즘 |

## 예를 들어 설명하면

데이터 파이프라인 예시다.

```
서버 구축 → DB 설치 → 백엔드 개발 → 프론트엔드 개발
```

노드 연결 관계:

| 노드 | 연결 (의존)하는 다음 노드 |
|---|---|
| 서버 구축 | DB 설치 |
| DB 설치 | 백엔드 개발 |
| 백엔드 개발 | 프론트엔드 개발 |
| 프론트엔드 개발 | 없음 |

위상 정렬 결과: 서버 구축 → DB 설치 → 백엔드 개발 → 프론트엔드 개발. 이 순서를 벗어나면 실행이 실패한다. DAG가 이 순서를 자동으로 계산한다.

## 이 단계에서 중요한 판단 기준

DAG를 설계할 때 순환이 생기면 전체 시스템이 교착 상태에 빠진다. DFS(깊이 우선 탐색)나 Kahn's Algorithm으로 순환 여부를 먼저 검증하는 것이 필수다.

## 한 줄 요약 — 이것만 기억하면 된다

**DAG는 "방향 있고 순환 없는" 두 규칙으로 복잡한 작업 의존성을 안전하게 표현하는 자료구조다.**

## 나중에 더 깊게 들어가면

- Kahn's Algorithm과 DFS 기반 위상 정렬 구현 차이
- Apache Airflow에서 DAG를 Python 코드로 정의하는 방법
- DAG 기반 블록체인(IOTA)이 기존 체인 구조와 다른 점
