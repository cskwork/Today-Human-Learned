> Pencil.dev는 .pen 디자인 파일을 Git 레포에 넣고 MCP로 AI 에이전트와 연결해, Figma와 코드 편집기 사이의 핸드오프 과정 자체를 없애는 도구다.

---

## Pencil.dev를 왜 쓰는지 감 잡기

디자이너가 Figma에서 완성한 시안을 개발자에게 넘기는 순간 문제가 시작된다. 색상값이 다르고, 간격이 어긋나고, "이 버튼은 원래 이런 의도가 아니었는데"라는 확인 메시지가 오간다. 이 "디자인 핸드오프" 과정이 중간 규모 팀 프로젝트 타임라인의 15~20%를 잡아먹는다는 분석도 있다.

근본 원인은 구조적이다. Figma 파일은 Figma 서버에 살고, 코드는 Git 레포에 산다. 두 세계 사이에 공식 통로가 없으니 사람이 수동으로 번역한다.

Pencil.dev는 이 구조를 바꾼다. 디자인 파일을 코드 레포 안에 두고, IDE에서 직접 디자인하며, AI 에이전트가 캔버스를 읽고 쓰게 만든다.

초보자는 이렇게 이해하면 된다.

`핵심 흐름: .pen 파일 생성 → IDE 캔버스에서 디자인 → AI에게 자연어 지시 → 코드 자동 생성 → Git 커밋`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| .pen 파일 | Pencil의 디자인 파일 형식. 내부는 JSON 텍스트이므로 Git으로 버전 관리할 수 있다. |
| MCP (Model Context Protocol) | AI 에이전트가 외부 도구와 표준 방식으로 통신하는 프로토콜. Pencil 캔버스가 MCP 서버 역할을 한다. |
| 양방향 동기화 | 캔버스에서 디자인을 수정하면 코드에 반영되고, 코드를 바꾸면 캔버스에도 반영되는 구조. |
| 핸드오프(Handoff) | 디자이너가 완성한 시안을 개발자에게 인계하는 과정. Pencil은 이 과정을 제거하는 것이 목표다. |
| 무한 캔버스 | .pen 파일을 열면 나타나는 벡터 편집 공간. AI에게 자연어로 지시하거나 직접 그릴 수 있다. |

## 예를 들어 설명하면

신규 프로젝트에서 Pencil을 처음 적용하는 과정이다.

```bash
# 1. 프로젝트 디렉토리에 디자인 파일 생성
mkdir my-app && cd my-app
touch design.pen

# 2. Cursor나 VS Code에서 파일 열기 → 캔버스 표시됨
# 3. AI에게 프롬프트
# "파란 그라디언트 배경에 흰색 텍스트로 Get Started 버튼을 만들어줘"
# → 캔버스에 즉시 반영

# 4. 프레임 선택 후 AI에게 코드 요청
# "이 디자인으로 React 컴포넌트를 생성해줘"
# → 같은 디렉토리에 실행 가능한 코드 파일 생성
```

기존 Figma 시안이 있다면 Figma에서 요소를 복사(Ctrl+C)해 Pencil 캔버스에 붙여넣기(Ctrl+V)하면 벡터, 텍스트, 스타일이 보존된다.

## 이 단계에서 중요한 판단 기준

| 상황 | Pencil 적합 여부 |
|---|---|
| 빠른 UI 프로토타입, 랜딩 페이지, SaaS 대시보드 | 적합 |
| Claude Code 또는 Cursor를 이미 주 개발 도구로 사용 중 | 적합 |
| 세밀한 수작업 UI 조정이 핵심인 작업 | Figma가 여전히 우위 |
| 백엔드 로직, API 통합, DB 설계 중심 프로젝트 | 직접적 효용 제한적 |

현재 얼리 액세스(무료)이지만, a16z 투자를 받은 스타트업으로 향후 가격 정책 변화 가능성을 고려해야 한다. AI 기능에는 Claude Code 구독(월 $20~)이 별도로 필요하다.

## 한 줄 요약 — 이것만 기억하면 된다

**Pencil.dev는 디자인 파일을 Git 레포에 넣고 AI가 캔버스를 직접 제어하게 함으로써, 디자인-개발 사이의 수동 번역 비용을 구조적으로 없앤다.**

## 나중에 더 깊게 들어가면

- MCP 서버로서 Pencil이 노출하는 읽기/쓰기 API 구조 이해하기
- 디자인 토큰을 CSS 변수로 자동 변환하는 양방향 동기화 설정하기
- Wayland Linux 환경에서의 알려진 UI 이슈와 회피 방법
