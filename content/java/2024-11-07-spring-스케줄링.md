> **TL;DR**
> `@EnableScheduling`을 설정하고 메서드에 `@Scheduled`를 붙이면 Spring이 지정한 시간마다 그 메서드를 자동으로 호출한다. 추가 인프라 없이 JVM 내에서 동작하는 가장 단순한 예약 실행 방법이다.

---

## Spring 스케줄링을 왜 쓰는지 감 잡기

서비스를 운영하다 보면 "매일 자정에 통계를 집계하라", "10분마다 캐시를 갱신하라" 같은 요구가 생긴다. 이를 별도 cron 서버나 운영체제 스케줄러로 처리하면 배포와 모니터링이 분리되어 복잡해진다. Spring Scheduling은 애플리케이션 코드 안에서 이 역할을 담당한다. 설정 파일 하나, 애노테이션 하나로 끝난다.

초보자는 처음에 이렇게 이해하면 된다.

`핵심 흐름: @EnableScheduling 활성화 → @Scheduled 메서드 선언 → Spring이 스레드 풀로 주기적 실행`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| `@EnableScheduling` | 스케줄링 기능을 켜는 스위치. `@Configuration` 클래스에 붙인다 |
| `@Scheduled` | 메서드가 언제, 얼마나 자주 실행될지 지정하는 애노테이션 |
| cron 표현식 | "초 분 시 일 월 요일" 6자리 형식으로 실행 시점을 정밀하게 지정하는 문자열 |
| `fixedRate` | 이전 실행 시작 기준으로 N밀리초마다 실행. 이전 작업이 끝나지 않아도 시작됨 |
| `fixedDelay` | 이전 실행 종료 기준으로 N밀리초 후 실행. 이전 작업이 끝난 뒤에 시작됨 |

## 예를 들어 설명하면

일일 리포트 생성과 캐시 갱신을 같은 애플리케이션 안에서 처리하는 예시다.

```java
@Configuration
@EnableScheduling
public class TaskConfig {
    @Bean
    public TaskScheduler taskScheduler() {
        ThreadPoolTaskScheduler scheduler = new ThreadPoolTaskScheduler();
        scheduler.setPoolSize(5);  // 동시 실행 가능한 스케줄 수
        scheduler.setThreadNamePrefix("scheduler-");
        return scheduler;
    }
}

@Component
@Slf4j
public class ScheduledTasks {

    // 매일 새벽 1시 — cron 표현식: 초(0) 분(0) 시(1) 일(*) 월(*) 요일(?)
    @Scheduled(cron = "0 0 1 * * ?")
    public void generateDailyReport() {
        log.info("일일 리포트 생성 시작");
        try {
            // 리포트 생성 로직
        } catch (Exception e) {
            log.error("리포트 생성 실패", e);
        }
    }

    // 10분마다 캐시 갱신 (600,000ms)
    @Scheduled(fixedRate = 600_000)
    public void refreshCache() {
        // 캐시 갱신 로직
    }
}
```

`fixedRate`와 `fixedDelay`의 차이는 실행 시간이 긴 작업에서 중요하다. 작업이 8분 걸리는데 `fixedRate = 600_000`이면 2분 뒤에 다음 실행이 겹친다. 겹침을 막으려면 `fixedDelay`를 쓴다.

## 이 단계에서 중요한 판단 기준

단일 인스턴스 애플리케이션이면 `@Scheduled`로 충분하다. 서버가 여러 대로 확장되면 중복 실행을 막기 위해 분산 락(ShedLock 등)이나 Quartz 같은 별도 스케줄러가 필요하다.

## 한 줄 요약 — 이것만 기억하면 된다

**`@EnableScheduling` + `@Scheduled`면 Spring 내에서 예약 실행이 완성되고, 클러스터 환경에서는 중복 실행 방지 대책이 추가로 필요하다.**

## 나중에 더 깊게 들어가면

- ShedLock — 분산 환경에서 스케줄 중복 실행을 막는 경량 라이브러리
- Quartz Scheduler — 영속성과 클러스터링이 필요한 엔터프라이즈 수준 스케줄링
- `@Async` + `@Scheduled` 조합 — 스케줄된 작업이 다음 주기에 영향을 주지 않도록 비동기로 실행하는 방법
