> **TL;DR**
> 서브넷은 하나의 큰 IP 네트워크를 더 작은 논리 단위로 나눠 트래픽을 격리하고, 보안과 성능을 동시에 개선하는 네트워크 설계 기법이다.

---

## 서브넷을 왜 쓰는지 감 잡기

수백 대의 컴퓨터가 하나의 네트워크에 연결되어 있다고 상상해보자. 한 컴퓨터가 브로드캐스트(전체 동시 전송)를 날리면 나머지 전부가 그 신호를 받아야 한다. 불필요한 트래픽이 쌓이고 속도가 느려진다. 서브넷은 이 큰 네트워크를 HR·영업·IT 같은 부서별 구역으로 나눠, 각 구역 내부에서만 브로드캐스트가 퍼지도록 제한한다. 부서 간 통신은 라우터를 거쳐야 한다. 이 구조 하나로 성능과 보안이 모두 좋아진다.

`핵심 흐름: 큰 네트워크 → 서브넷 마스크로 구역 분할 → 같은 서브넷은 직접 통신, 다른 서브넷은 라우터 경유`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| 서브넷 마스크 | IP 주소에서 "네트워크 부분"과 "호스트(기기) 부분"을 구분하는 숫자. `/24`는 앞 24비트가 네트워크 식별자 |
| CIDR 표기 | `192.168.1.0/24`처럼 IP 뒤에 슬래시와 숫자로 서브넷 크기를 나타내는 방식 |
| 브로드캐스트 도메인 | 브로드캐스트가 도달하는 범위. 서브넷이 이 범위를 제한한다 |
| 라우터 | 서로 다른 서브넷 사이에서 패킷을 전달하는 장치 |
| NACL | Network Access Control List. 서브넷 경계에서 트래픽을 허용하거나 차단하는 규칙 목록 |

## 예를 들어 설명하면

회사 네트워크를 세 부서로 나누는 예시다.

| 부서 | 서브넷 | IP 범위 |
|---|---|---|
| HR | `192.168.1.0/24` | 192.168.1.1 ~ 192.168.1.254 |
| 영업 | `192.168.2.0/24` | 192.168.2.1 ~ 192.168.2.254 |
| IT | `192.168.3.0/24` | 192.168.3.1 ~ 192.168.3.254 |

HR 직원의 컴퓨터(192.168.1.5)가 영업팀 서버(192.168.2.10)에 접근하려면 라우터를 거쳐야 한다. 라우터에서 NACL로 "HR은 영업팀 서버에 접근 불가" 규칙을 추가하면 민감한 데이터를 격리할 수 있다.

## 이 단계에서 중요한 판단 기준

서브넷을 설계할 때 가장 먼저 결정해야 할 것은 "어떤 기기 그룹이 서로 직접 통신해야 하고, 어떤 그룹 간에는 통제가 필요한가"다. 통제가 필요한 경계가 서브넷 경계가 된다.

## 한 줄 요약 — 이것만 기억하면 된다

**서브넷은 큰 네트워크를 논리적 구역으로 나눠 브로드캐스트 범위를 줄이고, 서브넷 경계에서 접근 제어를 적용하는 기법이다.**

## 나중에 더 깊게 들어가면

- CIDR 비트 계산 실습 (`/24`, `/28`, `/30` 각각 몇 개의 호스트를 수용하는지)
- 퍼블릭 서브넷 vs 프라이빗 서브넷 (AWS VPC 설계 패턴)
- 라우팅 테이블이 서브넷 간 트래픽을 어떻게 결정하는지
