> **TL;DR**
> RSA는 공개 키와 비밀 키 쌍을 이용해 누구나 암호화할 수 있지만 수신자만 복호화할 수 있도록 보장하는 비대칭 암호 알고리즘이다.

---

## RSA를 왜 쓰는지 감 잡기

두 사람이 처음 만나서 비밀 대화를 시작하려면, 먼저 암호화 키를 안전하게 교환해야 한다. 그런데 키를 주고받는 통신 자체가 도청되면 어떻게 할까? RSA는 이 역설을 해결한다. 자물쇠(공개 키)를 미리 세상에 공개해 두고, 아무나 메시지를 잠가서 보내게 한다. 열쇠(비밀 키)는 수신자 혼자 가진다.

이 방식 덕분에 HTTPS, 이메일 서명, 코드 서명 등 인터넷 보안의 기반이 가능해졌다.

초보자는 처음에 이렇게 이해하면 된다.

`핵심 흐름: 두 소수 선택 → n·e·d 계산 → 공개 키(e, n) 배포 → 암호화(m^e mod n) → 복호화(c^d mod n)`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| 공개 키 (e, n) | 모든 사람이 가질 수 있는 잠금 도구 |
| 비밀 키 (d, n) | 수신자만 보관하는 해제 도구 |
| 소인수분해 | n을 p·q로 쪼개는 작업 — 이게 어렵기 때문에 RSA가 안전하다 |
| 모듈러 역원 (d) | e와 쌍을 이루는 비밀 값 — d×e ≡ 1 (mod φ(n)) 관계로 계산된다 |
| 오일러 φ (phi) | (p-1)×(q-1) — 키 생성에서 e와 d를 고를 때 쓰는 중간 값 |

## 예를 들어 설명하면

p=61, q=53으로 시작하면:

```
n = 61 × 53 = 3233
φ(n) = 60 × 52 = 3120
e = 17  →  공개 키: (17, 3233)
d = 2753  →  비밀 키: (2753, 3233)

암호화: c = 65^17  mod 3233 = 2790
복호화: m = 2790^2753 mod 3233 = 65
```

공격자는 n=3233과 e=17만 알고 있다. d를 구하려면 3233=61×53을 알아야 하는데, 실전에서 n은 2048비트짜리 수라 현존하는 컴퓨터로는 분해가 불가능에 가깝다.

## 이 단계에서 중요한 판단 기준

RSA는 작은 데이터(키, 서명)에만 써야 한다 — 대용량 파일 암호화에 RSA를 직접 쓰면 느리고 안전하지 않으며, 실제로는 AES 키를 RSA로 암호화하는 하이브리드 방식이 표준이다.

## 한 줄 요약 — 이것만 기억하면 된다

**RSA의 안전성은 "큰 수를 소인수분해하기가 현실적으로 불가능하다"는 수학적 사실 하나에 달려 있다.**

## 나중에 더 깊게 들어가면

- RSA-OAEP: 패딩 없는 교과서 RSA가 왜 취약한지
- 디지털 서명에서의 RSA 활용 — 암호화와 방향이 반대임을 이해하기
- 타원곡선 암호(ECC) — RSA보다 짧은 키로 동등한 보안 강도를 내는 이유
