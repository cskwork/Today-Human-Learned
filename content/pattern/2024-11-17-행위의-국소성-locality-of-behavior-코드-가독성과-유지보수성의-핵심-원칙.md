> **TL;DR**
> 코드가 무슨 일을 하는지 그 코드 하나만 보고도 파악할 수 있어야 한다. 동작이 여러 파일에 흩어질수록 이해 비용이 늘어난다.

---

## 행위의 국소성을 왜 쓰는지 감 잡기

코드를 수정하려고 파일을 열었는데, 실제 동작은 다른 파일의 이벤트 핸들러에 숨어 있다. 그 파일을 열면 또 다른 유틸 함수가 나온다. 이렇게 동작이 여러 곳에 분산된 상태를 "먼 거리에서의 갑작스러운 동작(action at a distance)"이라 부른다. 행위의 국소성(Locality of Behavior, LoB)은 리처드 가브리엘이 정리한 원칙으로, 어떤 코드 단위를 볼 때 그 동작이 같은 위치에서 읽힐수록 좋다는 관점이다.

이 원칙이 중요한 이유는 인지 부하(cognitive load) 때문이다. 사람은 한 번에 머릿속에 담을 수 있는 컨텍스트가 제한적이다. 동작을 파악하기 위해 파일을 많이 열수록 오류가 생길 가능성이 높아진다.

`핵심 흐름: 코드 변경 요청 → 관련 위치 파악 → 수정 → 검증`

LoB가 낮으면 "관련 위치 파악" 단계에서 시간과 실수가 집중된다.

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| 행위의 국소성 (LoB) | 동작과 그 동작을 일으키는 코드가 물리적으로 가까이 있는 정도. |
| 인지 부하 | 개발자가 코드를 이해하기 위해 머릿속에 동시에 유지해야 하는 정보의 양. |
| action at a distance | 코드의 정의 위치와 실행 위치가 멀리 떨어져 의도치 않은 부수효과가 생기는 현상. |
| 자기 완결적 컴포넌트 | 마크업, 스타일, 로직이 한 파일 안에 있어 외부 파일 없이 동작을 이해할 수 있는 단위. |
| DRY와의 충돌 | LoB를 지키려다 코드를 복사-붙여넣기하면 DRY(중복 금지) 원칙과 충돌한다. 균형이 필요하다. |

## 예를 들어 설명하면

HTMX 버튼은 LoB가 높다. 버튼 하나만 봐도 동작이 모두 읽힌다.

```html
<button hx-get="/clicked" hx-target="#output" hx-swap="innerHTML">
  클릭
</button>
<div id="output"></div>
```

같은 기능을 jQuery로 분리하면 LoB가 낮아진다.

```html
<!-- HTML 파일 -->
<button id="clickButton">클릭</button>
<div id="output"></div>
```

```javascript
// 별도 JS 파일
$("#clickButton").on("click", function () {
  $.ajax({ url: "/clicked", method: "GET",
    success: function (res) { $("#output").html(res); }
  });
});
```

버튼의 동작을 파악하려면 두 파일을 모두 열어야 한다. 팀원이 버튼 ID를 바꾸거나 JS 파일을 삭제하면 동작이 조용히 깨진다.

React의 컴포넌트 기반 접근도 LoB를 높이는 방식이다. JSX, 스타일, 핸들러가 한 파일에 모이기 때문에 해당 컴포넌트 파일만 열면 무슨 일을 하는지 알 수 있다.

## 이 단계에서 중요한 판단 기준

코드를 이해하기 위해 몇 개의 파일을 열어야 하는가. 세 개 이상이라면 LoB가 낮은 것이고 구조를 재검토할 시점이다.

## 한 줄 요약 — 이것만 기억하면 된다

**동작의 정의와 호출이 멀리 떨어질수록 이해 비용과 버그 가능성이 함께 높아진다.**

## 나중에 더 깊게 들어가면

- LoB와 관심사 분리(SoC)를 동시에 만족시키는 설계 전략
- 모노리식 JS 파일을 컴포넌트로 리팩터링할 때 기준 잡는 법
- HTMX, 알파인(Alpine.js) 등 LoB를 설계 철학으로 삼는 라이브러리 탐구
