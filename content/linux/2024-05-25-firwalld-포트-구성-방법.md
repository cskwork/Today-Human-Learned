> **TL;DR**
> firewalld에서 포트를 열고 닫는 명령어는 세 줄로 끝난다. `--add-port`, `--remove-port`, `--reload`.

---

## firewalld를 왜 쓰는지 감 잡기

Linux 서버는 기본적으로 불필요한 포트를 막아둔다. 웹 애플리케이션을 8080 포트로 띄웠는데 외부에서 접속이 안 된다면, 방화벽이 해당 포트를 차단하고 있기 때문이다. firewalld는 Red Hat 계열(CentOS, RHEL, Fedora)에서 기본으로 사용하는 방화벽 관리 도구다. 서버를 재시작하지 않고 규칙을 실시간으로 적용할 수 있다는 점이 핵심이다.

초보자는 처음에 이렇게 이해하면 된다.

`핵심 흐름: 포트 추가 → 규칙 저장(--permanent) → 재로드(--reload) → 확인`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| 포트(Port) | 서버에서 특정 프로그램이 외부와 통신하는 번호. 문 번호라고 생각하면 된다. |
| TCP | 인터넷 통신에서 가장 흔한 프로토콜. 대부분의 서비스는 TCP를 쓴다. |
| `--permanent` | 이 옵션이 없으면 서버 재시작 시 규칙이 사라진다. 영구 적용 플래그. |
| `--reload` | 영구 규칙을 지금 당장 활성화하는 명령. 서버 재시작 없이 적용된다. |
| zone | firewalld가 네트워크 인터페이스를 구분하는 단위. 기본값은 `public`. |

## 예를 들어 설명하면

Spring Boot 앱을 8080 포트로 올렸는데 외부 접속이 안 되는 상황이다.

```bash
# 1. 포트 열기 (--permanent 없으면 재시작 시 사라짐)
sudo firewall-cmd --add-port=8080/tcp --permanent

# 2. 여러 포트를 한 번에 열 때
sudo firewall-cmd --add-port={8080/tcp,3306/tcp,6379/tcp} --permanent

# 3. 규칙 즉시 활성화
sudo firewall-cmd --reload

# 4. 열린 포트 확인
firewall-cmd --list-ports
```

포트가 목록에 보이면 성공이다.

## 이 단계에서 중요한 판단 기준

`--permanent`를 빠뜨리면 재부팅 후 규칙이 사라진다. 테스트할 때는 빼도 되지만, 운영 서버에서는 반드시 붙인다.

## 한 줄 요약 — 이것만 기억하면 된다

**포트를 열 때는 `--add-port`, 적용할 때는 `--reload`, 재부팅 후에도 유지하려면 `--permanent`를 함께 쓴다.**

## 나중에 더 깊게 들어가면

- firewalld zone 개념과 인터페이스 바인딩
- 서비스(service) 단위로 포트를 관리하는 방법 (`--add-service=http`)
- rich rule로 특정 IP만 허용하는 세밀한 규칙 설정
