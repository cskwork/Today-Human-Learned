> **TL;DR**
> Excel은 1990년대부터 대괄호를 수식 구문 문자로 예약해왔으며, 2025년 5월 보안 업데이트로 이 제약이 더 엄격하게 적용되어 `[이름]파일.xlsx` 형태의 파일이 열리지 않는다.

---

## 이 문제가 왜 생기는지 감 잡기

Excel은 다른 워크북의 셀을 참조할 때 `=[파일명.xlsx]시트명!셀주소` 형식을 쓴다. 여기서 대괄호 `[` `]`는 파일명을 감싸는 구문 기호다. 이 때문에 Excel은 파일명 안의 대괄호를 수식의 일부로 파싱하려 시도하고, 결과적으로 실제 파일 경로를 잘못 해석한다.

Microsoft는 이를 "버그가 아닌 의도된 동작"으로 공식 분류했다. 2025년 5월 13일 보안 업데이트(KB5002717)는 이 파싱 로직을 더 엄격하게 적용했고, `[Test]Report.xlsx` 같은 파일을 열 때 Excel이 `[Test]` 부분을 절단하여 `Report.xlsx`만 찾으려 하는 현상이 발생한다. Office 365 및 Office 2021에서 확인되었으며, 구형 Office 2016 MSI 버전에서는 아직 문제가 없다.

`핵심 흐름: 대괄호 포함 파일명 → Excel 파서가 수식 구문으로 오인 → 파일명 절단 → 파일 못 찾음 오류`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| 구문 문자 (Syntax Character) | 프로그램이 특별한 의미로 해석하는 예약 기호 — 여기서는 `[` `]` |
| KB5002717 | 2025년 5월 Microsoft Office 보안 업데이트 식별 번호 |
| 피벗테이블 | Excel에서 대량 데이터를 요약하는 기능 — 대괄호 파일명에서 특히 오류가 잘 남 |
| Content-Disposition | 웹 서버가 파일 다운로드 시 파일명을 전달하는 HTTP 헤더 |
| 레거시 시스템 | 오래된 코드나 시스템 — COBOL 등이 대괄호 파일명을 자동 생성하는 경우가 많음 |

## 예를 들어 설명하면

서버에서 `[2025-05]report.xlsx`라는 파일을 생성해 사용자에게 배포하는 시스템이 있다면, 2025년 5월 이후 Microsoft 365 사용자는 이 파일을 열 수 없다. 가장 빠른 임시 해결책은 파일명 변환이다.

```
# 대괄호를 하이픈으로 치환하는 예시 (서버 측 스크립트)
파일명 변경 전: [2025-05]report.xlsx
파일명 변경 후: 2025-05-report.xlsx
```

서버에서 파일을 생성할 때부터 대괄호를 제외하는 것이 근본 해결책이다. IT 관리자라면 파일 서버에 대괄호 포함 파일을 자동으로 이름 변경하는 스크립트를 배포 정책으로 적용할 수 있다.

## 이 단계에서 중요한 판단 기준

Microsoft가 이를 의도된 동작으로 분류했기 때문에 패치로 되돌아갈 가능성은 낮다 — 파일명에서 대괄호를 제거하는 방향으로 시스템을 먼저 조정해야 한다.

## 한 줄 요약 — 이것만 기억하면 된다

**Excel은 파일명의 대괄호를 수식 구문으로 해석하도록 설계되어 있으며, 2025년 5월 보안 업데이트로 이 제약이 강화되었으므로 파일명에서 대괄호를 완전히 제거하는 것이 유일한 영구 해결책이다.**

## 나중에 더 깊게 들어가면
