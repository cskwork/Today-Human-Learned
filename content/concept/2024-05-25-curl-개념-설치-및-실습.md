> **TL;DR**
> cURL은 터미널에서 URL을 입력해 HTTP, SFTP 등 다양한 프로토콜로 데이터를 주고받을 수 있는 오픈 소스 클라이언트 도구다.

---

## cURL을 왜 쓰는지 감 잡기

API를 개발하거나 서버 간 통신을 테스트할 때, 브라우저 없이 HTTP 요청을 직접 날려야 하는 경우가 있다. cURL(client URL)이 그 역할을 한다. 터미널 한 줄로 GET, POST 요청은 물론 파일 업로드, 인증, 리다이렉트 추적까지 처리할 수 있다.

내부적으로 libcurl이라는 C 라이브러리를 사용하며, 2500명 이상의 개발자가 기여한 성숙한 오픈 소스 프로젝트다.

초보자는 처음에 이렇게 이해하면 된다.

`핵심 흐름: URL 입력 → DNS 조회 → TCP 연결 → TLS 핸드셰이크(HTTPS) → 프로토콜로 요청 → 응답 수신`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| cURL | 터미널에서 URL로 데이터를 주고받는 클라이언트 프로그램 |
| libcurl | cURL이 내부적으로 쓰는 C 라이브러리. 다른 프로그램에서도 임베드 가능 |
| TLS 핸드셰이크 | HTTPS 통신 전에 서버와 클라이언트가 신뢰를 확인하는 과정 |
| -v (verbose) | 요청과 응답의 상세 과정을 화면에 출력하는 옵션 |
| 포트(Port) | 서버의 어느 통로로 연결할지 정하는 번호. HTTP 기본값은 80 |

## 예를 들어 설명하면

기본 GET 요청부터 시작해 옵션을 붙이는 방식이다.

```bash
# 상세 로그와 함께 GET 요청
curl -v http://example.com

# 리다이렉트 자동 추적 (-L) + 상세 로그
curl -vL http://example.com

# 긴 옵션 이름도 가능 (-- 두 개)
curl --verbose --location http://example.com

# POST로 JSON 데이터 전송
curl -d '{"name": "test"}' -H 'Content-Type: application/json' http://example.com/api

# SFTP 파일 업로드 (사용자 인증 포함)
curl sftp://example.com/upload/ -u username:password -T localfile.txt
```

옵션 순서는 상관없다. `-v -L`과 `-L -v`는 동일하게 작동한다. 특정 옵션을 끄려면 `--no-verbose`처럼 `--no-` 접두사를 쓴다.

## 이 단계에서 중요한 판단 기준

API 동작을 빠르게 확인하거나 스크립트에서 HTTP 호출이 필요할 때 cURL을 먼저 떠올린다. GUI 도구보다 자동화와 재현이 쉽다.

## 한 줄 요약 — 이것만 기억하면 된다

**cURL은 터미널에서 네트워크 요청을 직접 실행하는 가장 빠른 방법이며, HTTP부터 SFTP까지 대부분의 프로토콜을 커버한다.**

## 나중에 더 깊게 들어가면

- `--cert`, `--cacert` 옵션으로 클라이언트 인증서 다루기
- cURL 출력을 파이프로 연결해 jq로 JSON 파싱하기
- libcurl을 C/Python 코드에 임베드해 HTTP 클라이언트 구현하기
