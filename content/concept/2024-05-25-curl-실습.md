> **TL;DR**
> cURL은 HTTP뿐 아니라 SFTP 프로토콜도 지원해, 터미널 한 줄로 원격 서버 파일의 업로드·다운로드·이름 변경·삭제까지 처리할 수 있다.

---

## cURL SFTP를 왜 쓰는지 감 잡기

파일 서버에 접근할 때 GUI FTP 클라이언트 대신 cURL을 쓰면 스크립트 자동화가 훨씬 쉬워진다. 배포 파이프라인이나 배치 작업에서 특히 유용하다. cURL은 `-k` 옵션으로 인증서 검증을 생략할 수 있어 내부망 SFTP 서버에도 빠르게 접근 가능하다.

초보자는 처음에 이렇게 이해하면 된다.

`핵심 흐름: cURL 명령 → SFTP 연결 (-k로 인증서 우회 가능) → 사용자 인증 (--user) → 파일 조작`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| SFTP | SSH 기반 파일 전송 프로토콜. FTP보다 보안이 강하다 |
| -k | 서버 인증서 검증을 건너뛰는 옵션. 테스트/내부망용 |
| --user | "사용자명:비밀번호" 형식으로 인증 정보를 전달하는 옵션 |
| -T | 로컬 파일을 서버로 업로드(Transfer)할 때 쓰는 옵션 |
| -Q | SFTP 서버에 추가 명령(RENAME, MKDIR 등)을 보내는 옵션 |

## 예를 들어 설명하면

자주 쓰는 SFTP 작업을 cURL로 표현하면 다음과 같다.

```bash
# 파일 목록 조회
curl -k sftp://192.168.1.10:22/data/ --user "user:password"

# 파일 업로드 (디렉터리 없으면 자동 생성)
curl -k "sftp://192.168.1.10:22/upload/" --user "user:password" \
  -T "/local/path/file.xml" --ftp-create-dirs

# 파일 다운로드
curl -k "sftp://192.168.1.10:22/upload/file.xml" --user "user:password" \
  -o "/local/path/file.xml" --create-dirs

# 파일 이름 변경
curl -k "sftp://192.168.1.10:22/upload/" --user "user:password" \
  -Q "-RENAME '/upload/old.xml' '/upload/new.xml'"

# 파일 삭제
curl -k "sftp://192.168.1.10:22/upload/" --user "user:password" \
  -Q "–RM /upload/file.xml"
```

윈도우에서 작성한 셸 스크립트를 리눅스에서 실행할 때 `'\r': command not found` 오류가 나면 줄바꿈 형식 문제다.

```bash
# DOS 형식을 Unix 형식으로 변환
dos2unix run.sh

# 원본을 유지하고 새 파일로 변환
dos2unix -n input.sh output.sh
```

## 이 단계에서 중요한 판단 기준

SFTP 작업을 자동화해야 한다면, GUI 클라이언트보다 cURL 명령을 셸 스크립트에 넣는 쪽이 재현성과 버전 관리 면에서 낫다.

## 한 줄 요약 — 이것만 기억하면 된다

**cURL로 SFTP를 다루면 업로드·다운로드·이름 변경·삭제를 스크립트 한 줄로 자동화할 수 있다.**

## 나중에 더 깊게 들어가면

- SSH 키 인증으로 비밀번호 없이 SFTP 접속하기 (`--key` 옵션)
- cURL 멀티 전송으로 병렬 파일 업로드하기
- 네트워크 포트 연결 확인: `curl -v telnet://ip:port`
