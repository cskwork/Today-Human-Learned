> **TL;DR**
> 인터넷은 전 세계 수십억 대의 기기가 IP 주소와 TCP/IP 규약으로 연결된 거대한 네트워크들의 네트워크다.

---

## 인터넷을 왜 이해해야 하는지 감 잡기

웹 개발, 앱 개발, 클라우드 서비스 — 어떤 분야든 인터넷 위에서 동작한다. 요청이 어떻게 전달되고, 응답이 어디서 오는지 모르면 네트워크 오류를 만났을 때 원인을 짐작조차 하기 어렵다. 인터넷은 단일 시스템이 아니라 수많은 작은 네트워크가 표준 규약으로 연결된 구조다. 이 구조를 이해하면 DNS, HTTP, CDN 같은 개념이 자연스럽게 연결된다.

초보자는 처음에 이렇게 이해하면 된다.

`핵심 흐름: 브라우저 요청 → 패킷으로 분할 → 라우터 경유 → 서버 도달 → 응답 패킷 조립 → 화면 표시`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| IP 주소 | 인터넷에 연결된 기기마다 붙는 고유 번호. 우편 주소처럼 데이터가 어디로 가야 할지 알려준다. |
| TCP/IP | 데이터를 어떻게 나누고, 어떻게 전달하고, 어떻게 다시 합치는지 정의한 규약 세트. |
| 패킷 (Packet) | 전송 데이터를 잘게 나눈 조각. 각 조각이 독립적으로 이동하고, 목적지에서 재조립된다. |
| 라우터 (Router) | 패킷이 목적지까지 가는 길을 안내하는 장비. 도로의 교차로와 같다. |
| 서버 / 클라이언트 | 서버는 자원을 제공하는 컴퓨터, 클라이언트는 그 자원을 요청하는 컴퓨터(주로 브라우저). |

## 예를 들어 설명하면

브라우저에서 `example.com`을 입력했을 때 일어나는 일이다.

1. 브라우저가 `example.com`의 IP 주소를 DNS 서버에 물어본다.
2. IP 주소를 얻으면 해당 서버로 HTTP 요청 패킷을 보낸다.
3. 패킷은 여러 라우터를 거쳐 가장 빠른 경로로 서버에 도달한다.
4. 서버가 HTML, CSS, 이미지를 패킷으로 나눠 응답한다.
5. 브라우저가 받은 패킷을 순서에 맞게 재조립해 화면에 그린다.

이 과정 전체가 보통 100밀리초 안에 완료된다.

## 이 단계에서 중요한 판단 기준

인터넷 통신 문제를 디버깅할 때 가장 먼저 확인해야 할 것은 "IP 주소 도달 가능 여부(ping)"와 "DNS 조회 성공 여부(nslookup)"다. 이 두 가지만으로 장애 범위의 절반을 좁힐 수 있다.

## 한 줄 요약 — 이것만 기억하면 된다

**인터넷은 IP 주소로 기기를 구별하고, TCP/IP 규약으로 데이터를 패킷 단위로 주고받는 전 지구적 네트워크 연합이다.**

## 나중에 더 깊게 들어가면

- DNS 동작 원리 — 도메인 이름이 IP 주소로 바뀌는 전체 과정
- HTTP vs HTTPS — 암호화가 어떻게 통신을 보호하는지
- CDN(콘텐츠 전송 네트워크) — 전 세계 엣지 서버를 이용해 응답 속도를 줄이는 방법
