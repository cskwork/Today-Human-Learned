> **TL;DR**
> kubectl은 쿠버네티스 클러스터를 제어하는 CLI다. get·describe·logs·exec·apply·rollout 여섯 개를 익히면 일상 업무 대부분을 처리할 수 있다.

---

## kubectl을 왜 쓰는지 감 잡기

쿠버네티스에는 GUI 대시보드도 있지만, CI/CD 파이프라인 자동화나 긴급 트러블슈팅은 결국 CLI로 돌아온다. kubectl은 클러스터 API 서버에 요청을 보내는 공식 CLI 도구로, 리소스 조회부터 배포·롤백·디버깅까지 모든 작업이 이 도구로 이루어진다.

명령어 구조는 단순하다.

`핵심 흐름: kubectl [명령어] [리소스 타입] [이름] [플래그]`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| 파드(Pod) | 쿠버네티스에서 실행되는 가장 작은 단위, 컨테이너를 하나 이상 포함 |
| 네임스페이스(Namespace) | 클러스터 안에서 리소스를 논리적으로 분리하는 가상 공간 |
| 디플로이먼트(Deployment) | 파드를 몇 개 유지할지, 어떻게 업데이트할지 관리하는 상위 오브젝트 |
| 레이블(Label) | 리소스에 붙이는 키-값 태그. `-l app=nginx` 같이 필터링에 사용 |
| 컨텍스트(Context) | 어느 클러스터·네임스페이스에 접속할지 설정한 프로파일 |

## 예를 들어 설명하면

실무에서 자주 쓰는 명령어를 카테고리별로 정리한다.

```bash
# 조회
kubectl get pods -A                        # 전체 네임스페이스 파드 목록
kubectl get pods -o wide                   # 노드/IP 포함 상세 조회
kubectl describe pod my-pod                # 이벤트 포함 상세 정보
kubectl get pods -l app=nginx              # 레이블 필터 조회

# 생성/적용
kubectl apply -f deployment.yaml           # 선언적 생성·업데이트 (권장)
kubectl apply -f deployment.yaml --dry-run=client  # 실제 반영 없이 검증

# 디버깅
kubectl logs -f my-pod                     # 실시간 로그
kubectl logs my-pod --previous             # 이전 컨테이너 로그
kubectl exec -it my-pod -- bash            # 컨테이너 내부 접속
kubectl port-forward svc/my-service 8080:80  # 로컬에서 서비스 접근

# 배포 관리
kubectl rollout status deployment/my-app   # 롤아웃 진행 확인
kubectl rollout undo deployment/my-app     # 이전 버전 롤백
kubectl scale deployment my-app --replicas=5  # 레플리카 수 조정

# 실용 팁
alias k='kubectl'                          # 타이핑 절반으로 줄이기
kubectl get events --sort-by=.metadata.creationTimestamp  # 이벤트 시간순 정렬
kubectl config use-context production-cluster  # 클러스터 전환
```

배포 방식 비교:

| 방식 | 특징 | 사용 상황 |
|---|---|---|
| 선언적 (`apply`) | YAML 파일로 관리, Git으로 이력 추적 | 운영 환경, GitOps |
| 명령형 (`create`) | 즉시 실행, 재현성 낮음 | 빠른 테스트·실험 |

## 이 단계에서 중요한 판단 기준

운영 환경에서는 `kubectl create`보다 `kubectl apply`를 사용한다. YAML 파일을 Git으로 관리하면 변경 이력이 남고 팀 협업이 수월해진다.

## 한 줄 요약 — 이것만 기억하면 된다

**apply로 배포하고, describe와 logs로 상태를 확인하며, rollout undo로 롤백한다 — 이 세 패턴으로 실무의 90%를 처리할 수 있다.**
