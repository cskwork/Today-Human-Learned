> **TL;DR**
> VPC는 AWS 클라우드 안에 논리적으로 격리된 내 전용 네트워크다. 서버를 어떤 방에 배치할지, 외부와 어떻게 통신할지, 누구를 들일지 모두 내가 결정한다.

---

## VPC를 왜 쓰는지 감 잡기

AWS에 EC2 인스턴스를 올리면 그 서버는 인터넷에 바로 노출될까? 그렇게 되면 데이터베이스까지 공개되는 셈이다. VPC는 이 문제를 막기 위해 존재한다.

VPC를 만들면 AWS 안에 나만의 사설 네트워크 구역이 생긴다. 그 안에서 서버를 공개 구역(public)과 비공개 구역(private)으로 나누고, 각 구역이 외부와 통신하는 방식을 직접 제어한다.

초보자는 처음에 이렇게 이해하면 된다.

`내 VPC → 서브넷(방) → 인스턴스(서버) → 인터넷 게이트웨이 → 인터넷`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| 서브넷(Subnet) | VPC 안에서 IP 대역을 나눈 구역. 공개(public)와 비공개(private)로 구분한다. |
| 인터넷 게이트웨이(IGW) | VPC와 인터넷 사이를 연결하는 문. 이게 없으면 public 서브넷도 인터넷에 못 나간다. |
| NAT 게이트웨이 | private 서브넷 안의 서버가 외부로 요청만 보낼 수 있게 해주는 중계소. 외부에서 먼저 접근하는 것은 막는다. |
| 라우트 테이블 | 네트워크 패킷이 어디로 가야 하는지 알려주는 규칙표. 서브넷마다 하나씩 연결된다. |
| 보안 그룹(Security Group) | 인스턴스 단위로 붙는 가상 방화벽. 어떤 IP, 어떤 포트의 트래픽을 허용할지 규칙으로 정한다. |

## 예를 들어 설명하면

웹 서비스를 하나 만든다고 가정한다. 웹 서버는 외부 사용자가 접근해야 하므로 public 서브넷에 올린다. 데이터베이스는 외부에 노출되면 안 되므로 private 서브넷에 올린다.

```
인터넷
  |
인터넷 게이트웨이(IGW)
  |
[public 서브넷]  웹 서버 (EC2)
  |
[private 서브넷] DB 서버 (RDS)
  |
NAT 게이트웨이 (DB가 업데이트 받을 때만 사용)
```

DB 서버는 외부에서 접근할 수 없지만, 소프트웨어 업데이트는 NAT 게이트웨이를 통해 나갈 수 있다. 웹 서버와 DB 서버 사이의 통신은 보안 그룹으로 DB 포트(3306 등)만 허용한다.

## 이 단계에서 중요한 판단 기준

서버를 public 서브넷에 넣을지 private 서브넷에 넣을지를 먼저 결정하라 — 인터넷에서 직접 접근이 필요한 서버만 public, 나머지는 무조건 private이 기본이다.

## 한 줄 요약 — 이것만 기억하면 된다

**VPC는 AWS 안에 내가 직접 설계하는 격리된 사설 네트워크이며, 서브넷·IGW·NAT·보안 그룹으로 트래픽 흐름을 제어한다.**

## 나중에 더 깊게 들어가면

- NACL(네트워크 ACL) — 서브넷 단위 방화벽, 보안 그룹과의 차이
- VPC 피어링 — 두 VPC를 사설 IP로 연결하는 방법
- AWS Direct Connect / VPN — 온프레미스 데이터센터와 VPC를 연결하는 방법
