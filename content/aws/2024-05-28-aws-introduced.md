> AWS는 서버, 스토리지, 데이터베이스, AI 도구 등 IT 인프라를 인터넷으로 빌려주는 클라우드 플랫폼이다. 필요한 만큼만 쓰고 쓴 만큼만 낸다.

---

## AWS를 왜 쓰는지 감 잡기

과거에는 서비스를 운영하려면 서버 장비를 직접 구매하고, 데이터센터 공간을 임대하고, 네트워크 케이블을 연결해야 했다. 장비값만 수천만 원이고, 트래픽이 몰릴 때를 대비해 평소보다 몇 배 큰 서버를 사둬야 했다.

AWS는 이 과정을 없앴다. 서버가 필요하면 웹 콘솔에서 몇 번 클릭하면 수 분 안에 준비된다. 트래픽이 늘면 자원을 늘리고, 줄면 다시 반납한다. 물리 서버를 구매하는 대신 자동차를 렌트하듯 빌리는 방식이다.

초보자는 처음에 이렇게 이해하면 된다.

`핵심 흐름: 내 앱 코드 → AWS 서비스 선택 → 배포 → 운영`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| 클라우드 컴퓨팅 | 서버, 스토리지, 네트워크 같은 IT 자원을 인터넷으로 빌려 쓰는 방식 |
| EC2 | AWS에서 빌리는 가상 서버. 내 컴퓨터 대신 Amazon 데이터센터에 있는 컴퓨터를 쓰는 것 |
| S3 | 파일(이미지, 동영상, 백업 등)을 무제한에 가깝게 저장하는 객체 스토리지 |
| RDS | MySQL, PostgreSQL 같은 관계형 데이터베이스를 AWS가 대신 관리해주는 서비스 |
| 리전(Region) | AWS 데이터센터가 모인 지리적 구역. 서울, 도쿄, 버지니아 등 전 세계 곳곳에 있다 |

## 예를 들어 설명하면

쇼핑몰 웹 앱을 만든다고 가정하자.

```
[사용자 브라우저]
      |
   Route 53 (DNS)
      |
   EC2 (웹 서버 · 앱 서버)
      |
   RDS (상품·주문 DB)   +   S3 (상품 이미지)
```

- EC2 인스턴스에 앱을 올린다.
- 상품 이미지는 S3에 저장하고 URL로 접근한다.
- 주문·회원 데이터는 RDS(MySQL)에 넣는다.
- 트래픽이 몰리면 Auto Scaling이 EC2를 자동으로 늘린다.

## 이 단계에서 중요한 판단 기준

AWS를 처음 쓸 때는 "이 작업이 컴퓨팅(EC2/Lambda)인지, 저장(S3/EBS)인지, 데이터베이스(RDS/DynamoDB)인지"를 먼저 구분하면 어떤 서비스를 써야 할지 빠르게 좁힐 수 있다.

## 한 줄 요약 — 이것만 기억하면 된다

**AWS는 IT 인프라를 물리 장비 없이 필요한 만큼 빌려 쓰는 플랫폼이며, 서비스는 컴퓨팅·스토리지·데이터베이스·네트워킹·AI 범주로 나뉜다.**

## 나중에 더 깊게 들어가면

- IAM: 누가 어떤 AWS 자원에 접근할 수 있는지 권한을 제어하는 방법
- VPC: AWS 안에서 나만의 격리된 네트워크를 구성하는 방법
- Lambda: 서버 없이 코드를 실행하는 서버리스 컴퓨팅
