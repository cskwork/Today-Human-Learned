> **TL;DR**
> AI에게 좋은 질문을 하는 것만으로는 부족하다. 좋은 답을 끌어내려면 AI가 필요로 하는 정보, 도구, 기억, 상태를 시스템 수준에서 설계해야 한다.

---

## Context Engineering을 왜 쓰는지 감 잡기

프롬프트 엔지니어링은 AI에게 잘 질문하는 기술이다. 그런데 실제 업무에 AI를 붙여보면 금방 한계가 드러난다. AI는 최신 정보를 모르고, 방금 전 대화를 기억하지 못하며, 외부 시스템을 직접 건드릴 수 없다.

Context Engineering은 이 문제를 해결하는 상위 개념이다. AI가 답을 만들기 전에 필요한 것을 모두 준비해주는 설계 기술이다. 질문 하나가 아니라 전체 정보 환경을 설계한다.

초보자는 처음에 이렇게 이해하면 된다.

`핵심 흐름: 질문 수신 → 관련 정보·도구 조립 → AI 처리 → 답변 반환`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| Context Engineering | AI가 좋은 답을 내도록 정보·도구·기억을 미리 준비해주는 시스템 설계 기술 |
| 컨텍스트 윈도우 | AI가 한 번에 읽을 수 있는 정보의 양; 책상 크기라고 생각하면 된다 |
| RAG | 질문이 들어오면 관련 문서를 먼저 찾아서 AI에게 건네주는 검색 시스템 |
| 기억 시스템 | 이전 대화나 사용자 정보를 저장해두고 다음 대화에서 꺼내 쓰는 장치 |
| 상태 관리 | 현재 작업 진행 상황, 장바구니, 사용자 선택지 등 실시간 맥락을 추적하는 것 |

## 예를 들어 설명하면

고객 서비스 챗봇에 Context Engineering을 적용하면 차이가 극명하다.

**적용 전**
```
사용자: "제품 환불하고 싶어요"
AI: "환불 정책에 따르면 일반적으로 14일 이내..."
```

**적용 후**
```
[AI 내부 처리]
1. 고객 구매 이력 조회
2. 해당 제품 환불 정책 검색
3. 구매일과 현재 날짜 비교
4. 고객 등급별 혜택 확인

AI: "3일 전 구매하신 노트북은 VIP 고객 30일 환불 정책이 적용됩니다.
     택배 수거를 예약해드릴까요?"
```

## 이 단계에서 중요한 판단 기준

컨텍스트의 품질이 AI 답변의 품질을 결정한다. 많은 정보보다 적절한 정보가 낫다.

## 한 줄 요약 — 이것만 기억하면 된다

**AI를 잘 쓰려면 질문을 잘 만드는 것이 아니라, AI가 일할 수 있는 환경 전체를 설계해야 한다.**

## 나중에 더 깊게 들어가면

- RAG 파이프라인 구체적 구현 (벡터 DB, 청킹 전략)
- 에이전트가 여러 도구를 조합하는 멀티스텝 추론
- 장기 기억과 단기 기억을 분리하는 메모리 아키텍처
