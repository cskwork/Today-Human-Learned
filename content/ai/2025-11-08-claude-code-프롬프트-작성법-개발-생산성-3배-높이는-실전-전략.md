## Claude Code 프롬프트를 왜 따로 배워야 하는지 감 잡기

Claude Code는 터미널에서 동작하는 AI 개발 파트너다. 파일을 읽고, 코드를 수정하고, 테스트를 실행하고, Git 커밋까지 처리한다. 그런데 프롬프트가 모호하면 설명만 돌아오거나, 단순 수정 요청에 전체 파일이 뒤집힌다. Claude Code가 "똑똑한 시니어 개발자"처럼 동작하느냐, "헷갈리는 인턴"처럼 동작하느냐는 프롬프트가 결정한다.

초보자는 이렇게 이해하면 된다.

`핵심 흐름: CLAUDE.md 설정 → 탐색 → 계획 → 구현 → 검증`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| CLAUDE.md | 프로젝트 규칙·명령어·금지 사항을 저장하는 파일; Claude가 매 세션 시작 시 자동으로 읽음 |
| Plan Mode | 코드를 바로 수정하지 않고 계획만 먼저 세우는 모드; Shift+Tab 두 번으로 진입 |
| SubAgent | 특정 작업(코드 리뷰, 테스트 작성 등)에 특화된 전문 AI 어시스턴트 |
| Slash Command | 자주 쓰는 프롬프트를 `.claude/commands/` 폴더에 저장해 `/명령어`로 재사용하는 기능 |
| Few-shot 프롬프팅 | 원하는 출력 패턴의 예시를 2~5개 보여주어 일관된 결과를 유도하는 기법 |

## 예를 들어 설명하면

같은 요청이라도 프롬프트 품질이 결과를 가른다.

| 나쁜 프롬프트 | 좋은 프롬프트 |
|---|---|
| "인증 관련 코드 수정해줘" | "src/auth/jwt.ts의 refreshToken 함수를 수정해줘" |
| "성능 개선해줘" | "users 테이블 조회에 인덱스를 추가해서 조회 시간 50% 단축해줘" |
| "테스트 케이스 추가" | "회원가입 API에 Jest 테스트 3개 작성: 정상·중복 이메일·유효하지 않은 비밀번호 케이스" |

CLAUDE.md에는 프로젝트 규칙을 명시한다. 예를 들어 아이콘 라이브러리를 강제하려면:

```markdown
# 아이콘 사용 규칙
- lucide-react 라이브러리 사용 필수
- SVG 직접 작성 금지
```

이 파일을 만들어두면 매 세션마다 같은 내용을 설명하지 않아도 된다.

## 이 단계에서 중요한 판단 기준

복잡한 작업일수록 탐색 단계를 먼저 분리하라. "관련 파일 3~5개를 찾아서 읽어봐"로 시작하면 Claude가 맥락을 충분히 파악한 뒤 구현에 들어간다.

## 한 줄 요약 — 이것만 기억하면 된다

**CLAUDE.md로 프로젝트 맥락을 관리하고, 탐색 → 계획 → 구현 → 검증 순서를 지키면 Claude Code가 예측 가능하게 동작한다.**

## 나중에 더 깊게 들어가면

- XML 태그로 복잡한 요구사항을 구조화하는 방법
- SubAgent를 활용한 병렬 작업 처리
- Checkpoint 기능으로 잘못된 구현을 안전하게 되돌리기
