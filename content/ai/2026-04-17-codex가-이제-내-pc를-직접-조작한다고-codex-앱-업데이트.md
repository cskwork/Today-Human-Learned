> **TL;DR**
> 이번 Codex 업데이트는 코드 편집 창 밖으로 나와 컴퓨터·웹·팀 도구를 직접 조작하는 에이전트로 재정의된다.

---

## Codex 업데이트를 왜 주목해야 하는지 감 잡기

개발 중에 JIRA 확인, Slack 답장, 브라우저에서 UI 검토를 번갈아 하면 오전이 금세 사라진다. 기존 Codex는 코드 생성과 편집에 머물렀지만, 이번 릴리스는 에이전트가 직접 커서를 움직이고 앱을 클릭하며 작업하는 방향으로 확장됐다. 모델이 똑똑해졌다기보다, 에이전트가 앉은 자리가 바뀐 것이다.

초보자는 처음에 이렇게 이해하면 된다.

`핵심 흐름: 지시 입력 → 에이전트가 앱·브라우저 직접 조작 → 결과 요약 패널에 표시`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| 컴퓨터 유즈 | 에이전트가 자체 커서로 내 앱을 보고 클릭하고 타이핑하는 기능. 내 작업을 방해하지 않고 백그라운드에서 돌아간다. |
| 인앱 브라우저 | Codex 안에서 실행되는 브라우저. 화면 요소에 직접 코멘트를 달아 에이전트에게 정밀한 지시를 전달할 수 있다. |
| 장기 자동화 | 에이전트가 며칠·몇 주짜리 작업을 이어가는 기능. 미래 시점을 지정하면 그때 스스로 깨어나 작업을 재개한다. |
| 메모리 프리뷰 | 내가 반복해서 교정했던 컨벤션이나 선호를 에이전트가 기억해 다음 작업에 반영하는 기능. |
| SDLC 오케스트레이터 | 소프트웨어 개발 라이프사이클 전 구간(코드 작성, 리뷰, 배포, 이슈 처리)을 단일 에이전트가 관리하는 역할. |

## 예를 들어 설명하면

CLI에서 플러그인 목록을 확인하고 Codex를 시작하는 기본 흐름이다.

```bash
# Node.js 20+, @openai/codex 기준
npm install -g @openai/codex
codex login
codex plugins list   # 90여 개 플러그인 중 설치 가능 목록 확인
codex --help         # 자동화·메모리 플래그 확인
```

실제 활용 예는 세 가지다.

1. **컴퓨터 유즈로 프런트엔드 이터레이션**: Figma 목업을 띄우고 "이 화면을 Next.js로 구현하고 브라우저에서 동작 확인까지 끝내 줘"라고 지시하면 에이전트가 편집기와 브라우저를 왕복하며 처리한다.

2. **인앱 브라우저로 UI 결함 정밀 지시**: localhost 개발 서버를 인앱 브라우저에서 열고, 버튼이나 폼에 직접 코멘트를 남겨 좌표·요소 맥락과 함께 지시를 전달한다. 스크린샷 붙여넣기 왕복이 사라진다.

3. **장기 자동화**: "금요일 오후 5시에 깨어나 PR 댓글 반영 후 merge 큐에 올려 줘" 같은 시간 지정 지시가 가능하다.

## 이 단계에서 중요한 판단 기준

컴퓨터 유즈와 개인화 기능은 EU/UK 지역에 순차 배포 중이므로, 사용 지역에 따라 기능 가용 여부를 먼저 확인해야 한다.

| 패턴 | 장점 | 주의점 |
|---|---|---|
| OpenAI Codex (이번 업데이트) | 컴퓨터 유즈·인앱 브라우저·이미지 생성·90여 개 플러그인·메모리가 단일 앱에 통합 | 데스크톱 앱 중심이라 IDE 친화도 낮음, 일부 기능 지역 순차 배포 |
| GitHub Copilot | IDE 내 자동완성과 채팅 경험 성숙, 엔터프라이즈 감사 로그 강점 | 멀티 앱 오케스트레이션·장시간 태스크는 Codex 대비 제한적 |
| Claude Code | 터미널·SDK·MCP 생태계 유연성, 장문 컨텍스트와 서브에이전트 자유도 높음 | 네이티브 컴퓨터 유즈 UX는 Codex 앱보다 나중에 따라오는 편 |

## 한 줄 요약 — 이것만 기억하면 된다

**Codex는 코드 편집 도구에서 컴퓨터·브라우저·팀 도구를 직접 조작하는 SDLC 오케스트레이터로 재정의됐다.**

## 나중에 더 깊게 들어가면

- 90여 개 플러그인 중 실무에서 유용한 조합 선택 기준 (Atlassian Rovo, CircleCI, GitLab Issues 등)
- 장기 자동화에서 에이전트 중단·재개 조건 설계 방법
- 메모리 프리뷰에 저장되는 컨텍스트 범위와 삭제·관리 방법
