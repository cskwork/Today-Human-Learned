> AI가 대화를 기억하고 스스로 행동하게 만드는 두 가지 축은 마크다운 기반 메모리와 SKILL.md 기반 스킬이다.

---

## 이 주제를 왜 쓰는지 감 잡기

ChatGPT나 Claude에게 어제 했던 대화를 언급하면 "이전 대화는 기억하지 못합니다"라는 답이 돌아온다. 매번 같은 맥락을 처음부터 설명해야 하는 것이 현재 AI 도구의 가장 큰 불편함 중 하나다.

OpenClaw과 NanoClaw은 이 문제를 "메모리"와 "스킬"이라는 두 축으로 해결하는 오픈소스 에이전트 프레임워크다. 세션이 끝나도 기억이 남고, 메신저에서 "내일 미팅 잡아줘"라고 말하면 실제로 캘린더에 일정이 추가된다.

`핵심 흐름: 대화 축적 → 마크다운 파일로 기억 저장 → 스킬 호출 → 외부 서비스 실행`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| AI 에이전트 | 사용자의 맥락을 기억하고 외부 도구를 써서 자율적으로 작업하는 AI |
| 메모리 플러시 | 컨텍스트 한계에 도달하기 전에 중요한 내용을 파일에 자동 저장하는 과정 |
| SKILL.md | AI에게 새 능력을 가르치는 마크다운 파일. 필요할 때만 읽어 컨텍스트를 절약한다 |
| Heartbeat | AI가 주기적으로 깨어나 먼저 메시지를 보내는 기능 |
| ClawHub | OpenClaw 커뮤니티 스킬 저장소. 700개 이상의 스킬이 등록되어 있다 |

## 예를 들어 설명하면

OpenClaw의 워크스페이스 구조는 이렇게 생겼다.

```
~/.openclaw/workspace/
├── SOUL.md          # 에이전트의 성격과 말투
├── USER.md          # 사용자 이름, 관심사, 타임존
├── MEMORY.md        # 장기 기억 (핵심 선호도)
├── memory/
│   └── 2026-02-07.md  # 일별 자동 기록
└── skills/          # 커스텀 스킬
```

벡터 데이터베이스가 아니라 사람이 직접 읽고 수정할 수 있는 텍스트 파일이 기억의 원본이다. 내 AI가 나에 대해 무엇을 기억하는지 텍스트 에디터로 바로 확인할 수 있다.

메모리와 스킬이 결합된 실제 흐름을 보면 이렇다.

1. 며칠간 프로젝트에 대해 대화하면 `memory/2026-02-07.md`에 "프로젝트 X 데드라인 2월 말 확정" 같은 요약이 자동으로 남는다.
2. Heartbeat 기능으로 AI가 먼저 "데드라인까지 3주 남았습니다. 이번 주 할 일을 정리해 드릴까요?"라고 묻는다.
3. "좋아, 노션에 올려줘"라고 응답하면 Notion 스킬이 실제 페이지를 생성한다.

## 이 단계에서 중요한 판단 기준

OpenClaw과 NanoClaw 중 선택할 때는 보안 요구사항을 먼저 확인하라. OpenClaw은 호스트 머신에 무제한 접근 권한을 가질 수 있어 신뢰할 수 없는 스킬 설치 전에 코드 검토가 필수다. NanoClaw은 그룹별 컨테이너 격리로 보안 면에서 더 엄격하다.

| 항목 | OpenClaw | NanoClaw |
|---|---|---|
| 코드 규모 | 43만 줄, 52개 이상 모듈 | 500줄 핵심 코드 |
| 스킬 생태계 | ClawHub 700개 이상 | Claude Code 스킬 변환 방식 |
| 보안 모델 | 애플리케이션 레벨 | OS 레벨 컨테이너 격리 |
| 지원 플랫폼 | WhatsApp, Telegram 등 12개 | WhatsApp 기본, 스킬로 확장 |

## 한 줄 요약 — 이것만 기억하면 된다

**AI를 도구에서 비서로 바꾸는 열쇠는 마크다운 파일 기반의 영속적 메모리와 SKILL.md 기반의 행동 능력이다.**

## 나중에 더 깊게 들어가면

- BM25와 벡터 유사도를 결합한 OpenClaw의 하이브리드 메모리 검색 구조
- ClawHub 스킬 보안 감사 방법 및 악성 스킬 식별 체크리스트
- NanoClaw 포크에서 커스텀 스킬을 추가하는 Claude Code 변환 방식
