> **TL;DR**
> AgentKit은 에이전트 설계부터 UI 임베드, 평가, 파인튜닝까지 하나의 루프로 묶은 올인원 툴킷이다. 개별 도구를 엮는 수작업을 없애고, 프로덕션까지의 시간을 단축한다.

---

## AgentKit를 왜 쓰는지 감 잡기

AI 에이전트를 만들 때 가장 고통스러운 부분은 "모델 선택"이 아니다. 모델을 오케스트레이션(조율)하고, 외부 도구와 데이터를 연결하고, 대화 UI를 붙이고, 성능을 측정하고, 다시 튜닝하는 전 과정을 직접 엮는 것이다. 이 모든 단계가 서로 다른 팀, 다른 도구, 다른 주기로 돌아가면 결국 몇 주가 사라진다.

AgentKit은 이 문제를 "표준화된 빌딩 블록"으로 해결한다. 설계 캔버스(Agent Builder), 연결 관리자(Connector Registry), 채팅 UI(ChatKit), 평가 도구(Evals), 강화 파인튜닝(RFT)을 하나의 플랫폼에서 제공한다.

초보자는 이렇게 이해하면 된다.

`핵심 흐름: 설계(Agent Builder) → 연결(Connector Registry) → 배포(ChatKit) → 측정(Evals) → 개선(RFT)`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| Agent Builder | 드래그앤드롭으로 에이전트 로직 흐름을 그리는 시각적 설계 도구 |
| Connector Registry | 데이터 소스와 외부 도구를 에이전트에 연결하는 중앙 관리 패널 |
| Guardrails | 에이전트가 개인정보를 유출하거나 악의적 명령을 따르지 않도록 막는 안전 레이어 |
| Evals | 에이전트가 실제로 잘 동작하는지 데이터셋과 자동 채점으로 측정하는 평가 시스템 |
| RFT (강화 파인튜닝) | "어떤 도구를 언제 쓸지"를 특정 업무에 맞게 모델에 학습시키는 파인튜닝 방법 |

## 예를 들어 설명하면

고객지원 에이전트를 만든다고 하자. 기존 방식이라면 오케스트레이션 코드, Slack 연동, 채팅 위젯, 평가 스크립트를 각각 따로 작성해야 한다.

AgentKit에서는 이렇게 진행한다.

```
1. Agent Builder: 분류 노드 → Guardrails → 지식검색 노드 → 응답 노드 연결
2. Connector Registry: SharePoint 문서 저장소 + 사내 티켓 DB 추가
3. ChatKit: 웹 앱에 <ChatKit /> 위젯 한 줄로 임베드
4. Evals: 100개 샘플로 정확도 측정 → 자동 프롬프트 최적화 실행
```

Canva는 이 방식으로 개발자 지원 에이전트를 2주 걸릴 작업을 1시간 내에 통합했다.

## 이 단계에서 중요한 판단 기준

에이전트의 성패는 모델 성능보다 설계-연결-평가-UI를 하나의 루프로 반복할 수 있느냐에 달려 있다.

## 한 줄 요약 — 이것만 기억하면 된다

**AgentKit은 에이전트 개발의 '설계 → 배포 → 측정 → 개선' 루프를 기본값으로 제공하는 플랫폼이다.**

## 나중에 더 깊게 들어가면

- Trace grading: 멀티에이전트 워크플로의 각 단계를 개별 채점하는 방법
- RFT Custom graders: 업무별 채점 기준으로 모델 행동을 정렬하는 방법
- Responses API와 AgentKit의 연동: 추론 컨텍스트를 턴 간에 보존하는 방법
