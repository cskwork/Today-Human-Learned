---

## RAG를 왜 쓰는지 감 잡기

LLM은 학습 데이터 안에 있는 것만 안다. 최신 사내 문서, 어제 업데이트된 제품 정보, 학습 시점 이후 발생한 사건은 모른다. 그리고 모르는 것을 아는 척 그럴듯하게 꾸며내는 환각(Hallucination) 문제가 있다. RAG는 LLM이 답변하기 전에 실제 문서를 검색해서 프롬프트에 붙여주는 방식으로 이 두 문제를 동시에 완화한다. 2025년 현재 기업 AI 시스템의 대부분이 RAG를 쓰고 있고, 패턴도 8가지로 분화됐다.

초보자는 처음에 이렇게 이해하면 된다.

`핵심 흐름: 사용자 질문 → 문서 검색 → 프롬프트 증강 → LLM 답변 생성`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| 환각(Hallucination) | AI가 없는 사실을 그럴듯하게 만들어내는 현상 |
| 임베딩(Embedding) | 텍스트를 숫자 벡터로 변환해 의미 기반 검색을 가능하게 하는 것 |
| 청킹(Chunking) | 긴 문서를 의미 있는 조각으로 잘라 검색 정확도를 높이는 작업 |
| 하이브리드 검색 | 키워드 검색(Sparse)과 의미 검색(Dense)을 합친 방식 |
| 재순위화(Reranking) | 검색된 문서 후보를 다시 정렬해 가장 관련 높은 것을 위로 올리는 단계 |

## 예를 들어 설명하면

기본 RAG 구현의 뼈대는 이렇다.

```python
def basic_rag(query, knowledge_base):
    # 1. 검색: 관련 문서 찾기
    relevant_docs = vector_search(query, knowledge_base)

    # 2. 증강: 프롬프트 구성
    augmented_prompt = f"질문: {query}\n\n참고 문서:\n{relevant_docs}\n\n위 정보를 바탕으로 답변해주세요."

    # 3. 생성: LLM 호출
    return llm.generate(augmented_prompt)
```

## 8가지 RAG 패턴 선택 기준

| 패턴 | 언제 쓰나 |
|---|---|
| Basic RAG | 단순 FAQ, 정적 문서 |
| Long RAG | 논문·계약서 등 긴 문서 분석 |
| Self-RAG | 검색 필요성을 AI가 스스로 판단해야 할 때 |
| Corrective RAG | 검색 결과 품질이 불안정할 때 자동 재검색 |
| Adaptive RAG | 쿼리 복잡도가 다양할 때 전략을 실시간 조정 |
| Graph RAG | 엔티티 간 관계 파악이 핵심일 때 |
| Agentic RAG | 문서마다 에이전트를 두고 메타 에이전트가 조율 |
| HyDE RAG | 이상적인 답변을 먼저 생성한 뒤 유사 문서 검색 |

## 이 단계에서 중요한 판단 기준

복잡한 아키텍처가 항상 좋은 게 아니다. 먼저 Basic RAG로 시작하고, 정확도가 부족한 이유를 측정한 뒤 패턴을 바꾼다.

## 한 줄 요약 — 이것만 기억하면 된다
