> **TL;DR**
> MCP는 AI와 외부 도구를 연결하는 표준 프로토콜이고, GitHub·Slack·PostgreSQL 등 검증된 서버 몇 개를 조합하면 개발 워크플로가 체감 수준으로 달라진다.

---

## MCP를 왜 쓰는지 감 잡기

AI 모델마다 GitHub, Slack, DB 등 각각의 도구와 별도로 연동 코드를 작성하면 모델 N개 × 도구 M개만큼 통합 코드가 필요하다. 이를 "N×M 문제"라 부른다. MCP(Model Context Protocol)는 Anthropic이 2024년 11월 공개한 오픈 프로토콜로, 모델과 도구 사이에 표준 규격을 제공해 이 문제를 해소한다. USB-C가 기기 연결을 통일한 것처럼, MCP는 AI와 도구 연결을 통일한다. 2025년 3월 OpenAI, 4월 Google DeepMind가 공식 채택하면서 생태계가 빠르게 커졌다.

초보자는 이렇게 이해하면 된다.

`핵심 흐름: AI 클라이언트 → MCP 서버 → 외부 도구/데이터 소스`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| MCP 서버 | AI가 GitHub, DB 같은 외부 도구와 대화할 수 있게 중간에서 통역해주는 소프트웨어 |
| MCP 호스트 (클라이언트) | Claude Desktop, Cursor, VS Code처럼 MCP 서버를 연결해 쓰는 AI 앱 |
| JSON-RPC 2.0 | MCP 통신의 기반 규격 — 모델과 도구가 주고받는 메시지 형식을 정의한다 |
| 프롬프트 인젝션 | 외부 데이터(이메일, DB 값 등)에 숨겨진 악성 지시가 AI의 행동을 바꾸는 공격 |
| 최소 권한 원칙 | MCP 서버에 꼭 필요한 권한만 부여하고, 작업 전 사용자 승인을 요구하는 보안 원칙 |

## 예를 들어 설명하면

Cursor에서 GitHub MCP와 PostgreSQL MCP를 동시에 연결하는 설정이다.

```json
{
  "mcpServers": {
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": { "GITHUB_TOKEN": "<YOUR_TOKEN>" }
    },
    "postgres": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-postgres"],
      "env": { "DATABASE_URL": "postgresql://user:pass@localhost/db" }
    }
  }
}
```

이 설정 하나로 "리뷰 대기 중인 PR 목록 알려줘"나 "주문 테이블에서 오늘 취소된 건 몇 개야?"를 자연어로 질문할 수 있다.

검증된 10개 서버 목록은 다음과 같다.

| 서버 | 핵심 역할 |
|---|---|
| GitHub MCP | 이슈, PR, CI/CD 워크플로 자동화 |
| Slack MCP | 채널 메시지, 파일 공유 자동화 |
| PostgreSQL MCP | 자연어 SQL, 스키마 검사 |
| Puppeteer MCP | 브라우저 자동화, 웹 스크래핑 |
| Google Drive MCP | 드라이브 문서를 AI 컨텍스트로 주입 |
| Brave Search MCP | 프라이버시 중심 웹 검색 (무료 월 2,000회) |
| Cloudflare MCP | DNS, WAF 규칙 자동화 |
| File System MCP | 로컬 파일/디렉토리 읽기·쓰기 |
| AWS API MCP | AWS 서비스 자연어 제어, IAM 연동 |
| Context7 MCP | 최신 라이브러리 문서를 프롬프트에 직접 주입 |

## 이 단계에서 중요한 판단 기준

MCP 서버를 도입하기 전, 해당 서버가 접근하는 리소스의 범위를 최소화했는지와 도구 실행 전 사용자 승인 단계가 있는지를 먼저 확인하라.

## 한 줄 요약 — 이것만 기억하면 된다

**MCP는 AI와 외부 도구를 표준 방식으로 연결하는 규격이고, 팀 업무에 맞는 서버 2~3개만 잘 조합해도 워크플로가 달라진다.**

## 나중에 더 깊게 들어가면

- 내부 API를 MCP 서버로 래핑해 사내 LLM이 자사 서비스를 직접 조작하도록 구성하는 방법
- 프롬프트 인젝션, Confused Deputy 공격 등 MCP 특유의 보안 위협 대응 방법
- 2025년 4월 스펙 업데이트 (OAuth 리소스 서버 분류, Resource Indicators 의무화) 적용 방법
