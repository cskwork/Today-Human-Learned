> **TL;DR**
> Agent Teams는 여러 Claude Code 인스턴스가 공유 태스크 리스트와 메시지 시스템으로 협업하는 멀티 에이전트 시스템으로, 단일 에이전트의 컨텍스트 한계를 우회하고 병렬 탐색을 가능하게 한다.

---

## Agent Teams를 왜 쓰는지 감 잡기

하나의 AI 에이전트에게 대규모 리팩토링을 맡기면 컨텍스트 윈도우가 바닥나고, PR 리뷰를 시키면 보안은 잡지만 성능 문제를 놓친다. 한 명의 개발자에게 프론트엔드, 백엔드, 테스트, 문서화를 동시에 맡기는 것과 다르지 않다.

Agent Teams는 이 문제를 역할 분담과 병렬 실행으로 푼다. 하나의 리더 세션이 여러 독립된 Claude Code 인스턴스(팀원)를 생성하고, 공유 태스크 리스트와 메시지 시스템으로 작업을 조율한다. 각 팀원은 신선한 컨텍스트 윈도우에서 시작하기 때문에 단일 에이전트가 80~90%까지 채우던 컨텍스트를 팀원당 약 40% 수준으로 유지할 수 있다.

초보자는 처음에 이렇게 이해하면 된다.

`핵심 흐름: 리더가 팀 생성 → 태스크 리스트 공유 → 팀원 병렬 실행 → 메일박스로 소통 → 리더에게 결과 보고`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| 팀 리더(Team Lead) | 팀을 만들고 팀원을 생성하며 전체 작업을 조율하는 메인 Claude Code 세션 |
| 팀원(Teammate) | 각각 독립된 컨텍스트 윈도우를 가진 Claude Code 인스턴스. 리더의 대화 기록은 이어받지 않는다 |
| 태스크 리스트(Task List) | 팀원이 공유하는 칸반 보드. pending/in progress/completed 세 상태와 태스크 간 의존성을 관리한다 |
| 메일박스(Mailbox) | 에이전트 간 메시징 시스템. message는 특정 팀원에게, broadcast는 전체에 보낸다 |
| 위임 모드(Delegate Mode) | 리더가 직접 코드를 작성하지 않고 순수하게 조율에만 집중하도록 제한하는 설정 |

## 예를 들어 설명하면

서브에이전트와의 차이를 조직에 비유하면 이해하기 쉽다. 서브에이전트는 심부름꾼이다. 팀장이 지시하면 결과만 보고하고 돌아온다. 다른 심부름꾼과 대화할 수 없다. Agent Teams의 팀원은 프로젝트 팀 멤버다. 각자 독립된 업무 공간이 있고, 서로 메시지를 주고받으며, 공유 칸반 보드를 보면서 자율적으로 일을 진행한다.

실전에서 효과적인 시나리오는 세 가지다.

**병렬 코드 리뷰**: 보안, 성능, 테스트 커버리지를 각각 독립 도메인으로 분리한다.

```
PR #142를 리뷰할 에이전트 팀을 만들어줘.
- 한 명은 보안 취약점 집중
- 한 명은 성능 영향 분석
- 한 명은 테스트 커버리지 검증
각자 리뷰 후 결과를 보고하도록 해줘.
```

**경쟁 가설 기반 디버깅**: 원인이 불분명한 버그에서 여러 팀원이 각각 다른 가설을 세우고 서로의 이론을 반증한다. 살아남는 이론이 실제 근본 원인일 확률이 높다.

**크로스 레이어 기능 개발**: 프론트엔드, 백엔드, 테스트가 동시에 변경되어야 할 때 각 레이어를 별도 팀원이 담당하면 파일 충돌 없이 병렬 작업이 가능하다.

## 이 단계에서 중요한 판단 기준

팀원들이 서로 소통해야 하는 작업인가? 소통이 필요 없다면 서브에이전트, 서로 발견한 내용을 공유하고 검증해야 한다면 Agent Teams가 맞다. 각 팀원이 별도 컨텍스트 윈도우를 사용하므로 토큰 비용은 팀원 수에 비례해 증가한다는 점도 사전에 계산해야 한다.

## 한 줄 요약 — 이것만 기억하면 된다

**Agent Teams는 읽기 전용 탐색 작업(코드 리뷰, 버그 조사)부터 시작해 병렬 탐색의 가치를 체감한 뒤 기능 개발로 확장하면 된다.**

## 나중에 더 깊게 들어가면

- 파일 소유권 분리 전략: 팀원 간 파일 충돌을 사전에 방지하는 설계 방법
- Context Compaction과 Agent Teams를 함께 쓸 때의 비용 추정 방법
- 세션 재개 불가 제약을 우회하는 팀 구성 전략
