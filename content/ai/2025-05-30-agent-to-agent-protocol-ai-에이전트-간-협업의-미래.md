> **TL;DR**
> Google이 만든 A2A 프로토콜은 서로 다른 회사의 AI 에이전트들이 표준화된 방식으로 통신하고 협업하게 하는 규격이다.

---

## A2A를 왜 쓰는지 감 잡기

기업마다 AI 에이전트를 따로 구축하면 각자는 제 역할을 하지만 서로 협력하지 못한다. 고객 서비스 챗봇이 일정 관리 AI에게 직접 요청을 넘길 수 없고, 개발자가 중간에 통합 코드를 별도로 작성해야 한다. 회사와 프레임워크가 다르면 호환 자체가 불가능하다.

A2A(Agent-to-Agent) 프로토콜은 이 문제를 해결하기 위해 Google이 개발했다. HTTP 위에서 동작하는 표준 인터페이스를 정의해, 어떤 프레임워크로 만든 에이전트든 서로 통신할 수 있게 한다. 2025년 기준 50개 이상의 기업이 참여하고 있으며 Microsoft도 합류했다.

초보자는 이렇게 이해하면 된다.

`핵심 흐름: 클라이언트 에이전트(요청) → A2A 프로토콜 → 원격 에이전트(수행) → 결과 반환`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| A2A | AI 에이전트들이 서로 통신할 수 있는 HTTP 기반 표준 프로토콜. Google 주도로 개발 |
| Agent Card | 에이전트가 JSON 형식으로 자신의 기능을 광고하는 문서. 다른 에이전트가 이를 보고 협업 가능 여부를 판단 |
| 클라이언트 에이전트 | 작업을 요청하는 쪽의 에이전트 |
| 원격 에이전트 | 요청을 받아 실제 작업을 수행하는 쪽의 에이전트 |
| UX Negotiation | 두 에이전트가 어떤 형식(텍스트, 폼, 파일 등)으로 데이터를 주고받을지 협상하는 과정 |

## 예를 들어 설명하면

채용 프로세스를 A2A로 자동화한다고 가정한다. 채용 매니저가 메인 에이전트에게 "이 이력서 검토하고 면접 일정 잡아줘"라고 요청하면 다음처럼 작업이 분배된다.

```
채용 매니저 (Human)
        |
메인 에이전트 (요청 분배)
   |         |         |
채용 사이트  일정 관리  배경 조사
에이전트    에이전트   에이전트
```

각 에이전트는 Agent Card를 통해 자신이 무엇을 할 수 있는지 선언하고, A2A 프로토콜로 서로 데이터를 주고받는다. Python SDK 설치는 `pip install a2a-sdk` 한 줄이다.

## 이 단계에서 중요한 판단 기준

에이전트 간 통신은 반드시 HTTPS로 암호화하고, 각 에이전트가 내부 상태나 메모리를 외부에 노출하지 않도록 설계하라.

## 한 줄 요약 — 이것만 기억하면 된다

**A2A는 서로 다른 회사의 AI 에이전트들이 Agent Card로 능력을 선언하고 HTTP로 협업하는 표준으로, 복잡한 작업을 에이전트 팀이 분담 처리하는 구조를 가능하게 한다.**
