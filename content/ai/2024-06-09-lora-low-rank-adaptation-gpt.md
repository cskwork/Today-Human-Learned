## LoRA를 왜 쓰는지 감 잡기

GPT-4 같은 대형 언어 모델(LLM)은 수백억 개의 파라미터로 이루어져 있다. 특정 용도(법률 문서 생성, 의료 상담 등)에 맞게 조정하려면 원래는 이 파라미터를 전부 다시 학습시켜야 한다. 이 과정을 파인튜닝(fine-tuning)이라고 부른다. 문제는 비용이다. GPU 수백 대를 수일 이상 돌려야 하므로 대부분의 팀은 엄두를 내기 어렵다.

LoRA(Low-Rank Adaptation)는 이 문제를 우회한다. 원본 모델의 파라미터는 그대로 두고, 각 레이어 옆에 아주 작은 보조 행렬 두 개만 추가해 그것만 학습한다. 학습해야 할 파라미터 수가 원본 대비 0.1~1% 수준으로 줄어든다.

핵심 흐름: `사전학습 모델 고정 → 저랭크 보조 행렬 추가 → 보조 행렬만 학습 → 추론 시 합산`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| 파인튜닝 (Fine-tuning) | 이미 학습된 모델을 특정 작업에 맞게 추가 학습하는 것 |
| 파라미터 (Parameter) | 모델이 학습 중에 조정하는 수치들. 숫자가 많을수록 모델이 크다 |
| 랭크 (Rank) | 행렬이 담고 있는 정보의 "차원 수". 낮을수록 단순하지만 작다 |
| 저랭크 행렬 | 원본 행렬의 핵심 패턴만 압축해서 담은 작은 행렬 |
| 어댑터 (Adapter) | 원본 모델에 붙이는 소형 추가 모듈. LoRA가 이 방식을 씀 |

## 예를 들어 설명하면

GPT 모델에 법률 문서 생성 능력을 추가한다고 가정하자. 원본 모델의 어텐션 레이어 가중치 행렬 W(크기 4096x4096)를 수정하는 대신, LoRA는 A(4096x8)와 B(8x4096) 두 행렬만 만든다. 학습은 A와 B만 진행하고, 추론 시에는 W + A*B를 계산해 사용한다.

```
# LoRA 적용 개념 (의사코드)
W_original = pretrained_weight  # 고정, 학습 안 함
A = random_init(4096, rank=8)   # 학습 대상
B = zeros(rank=8, 4096)         # 학습 대상

output = (W_original + A @ B) @ input
```

rank=8이면 학습 파라미터가 4096x4096 대신 2x(4096x8) = 65,536개. 원본의 약 0.4%다.

## 이 단계에서 중요한 판단 기준

LoRA를 쓸 때는 rank 값이 핵심이다. rank가 낮을수록 학습 비용이 싸지만 표현력이 줄어들고, 높을수록 파인튜닝 효과가 커지지만 비용도 늘어난다. 실제로는 r=4~16 사이에서 시작해 성능을 측정한다.

## 한 줄 요약 — 이것만 기억하면 된다

**LoRA는 모델 전체 대신 0.1~1%짜리 보조 행렬만 학습해서 파인튜닝 비용을 극적으로 낮춘다.**
