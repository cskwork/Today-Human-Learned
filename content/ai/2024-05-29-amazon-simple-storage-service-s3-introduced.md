> **TL;DR**
> S3는 파일을 버킷에 넣고 키로 꺼내는 클라우드 오브젝트 스토리지다. 용량 제한이 없고, 11 nine(99.999999999%) 내구성을 보장한다.

---

## S3를 왜 쓰는지 감 잡기

서버 한 대에 파일을 저장하면 디스크가 꽉 차거나, 서버가 죽으면 파일도 사라진다. S3는 이 두 문제를 동시에 해결한다. 저장 공간은 무제한으로 늘어나고, 내부적으로 여러 데이터센터에 자동 복제되므로 데이터가 손실될 확률이 사실상 0이다.

사용처는 광범위하다. 웹사이트 정적 파일(HTML, CSS, 이미지), 사용자 업로드 영상, 데이터 분석용 로그, 데이터베이스 백업까지 전부 S3에 넣는다.

초보자는 처음에 이렇게 이해하면 된다.

`핵심 흐름: 버킷 생성 → 오브젝트 업로드(키 지정) → URL 또는 SDK로 조회`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| 버킷(Bucket) | 파일을 담는 최상위 컨테이너. 이름은 전 세계에서 유일해야 한다. |
| 오브젝트(Object) | 버킷 안에 저장하는 개별 파일. 데이터 + 메타데이터로 구성된다. |
| 키(Key) | 오브젝트의 이름이자 주소. `images/profile/user123.png` 형태로 경로처럼 쓸 수 있다. |
| 스토리지 클래스 | 접근 빈도에 따른 비용 등급. 자주 쓰면 Standard, 거의 안 쓰면 Glacier. |
| 버전 관리(Versioning) | 같은 키로 덮어써도 이전 버전을 보존하는 기능. 실수로 삭제했을 때 복원 가능. |

## 예를 들어 설명하면

동영상 플랫폼을 운영한다고 하자. 사용자가 영상을 업로드하면 `videos/user123/2024-intro.mp4` 라는 키로 S3에 저장한다. 최근 1개월치 영상은 Standard 클래스에 두고, 1년이 지난 영상은 자동으로 Glacier로 이동시켜 보관 비용을 90% 줄인다. 사용자가 실수로 영상을 삭제해도 Versioning이 켜져 있으면 이전 버전을 복원할 수 있다.

버킷 정책(Bucket Policy)으로 특정 IP 대역이나 IAM 역할만 읽기 허용하면, 퍼블릭 노출 없이 내부 시스템끼리만 파일을 주고받을 수 있다.

## 이 단계에서 중요한 판단 기준

접근 빈도를 먼저 파악하라. 자주 읽히는 데이터를 Glacier에 넣으면 꺼낼 때 수 시간이 걸려 서비스가 멈춘다.

## 한 줄 요약 — 이것만 기억하면 된다

**S3는 버킷+키 구조로 무한히 확장되는 파일 저장소이며, 스토리지 클래스 선택이 비용을 결정한다.**

## 나중에 더 깊게 들어가면

- S3 수명 주기 정책(Lifecycle Policy): 날짜 기반으로 클래스 자동 전환 설정
- S3 이벤트 알림: 파일 업로드 시 Lambda를 자동 실행하는 패턴
- S3 Transfer Acceleration: 전 세계 엣지 로케이션을 통해 업로드 속도를 높이는 방법
