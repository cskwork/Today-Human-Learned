## MCP와 고급 입력 방식을 왜 쓰는지 감 잡기

파트 1의 기본 패턴을 익히면 다음 병목이 드러난다. 데이터베이스 구조를 확인하려면 별도 DB 클라이언트를 열어야 하고, 최신 프레임워크 문서는 Claude가 모르는 경우가 있으며, 수백 개 파일에 걸친 마이그레이션은 Claude가 중간에 놓치는 경우가 생긴다.

MCP(Model Context Protocol)는 Claude와 외부 데이터 소스를 연결하는 개방형 표준이다. Postgres, GitHub, Slack, JIRA 등 수백 개 도구를 Claude가 직접 읽고 쓸 수 있게 된다. 이 연결이 구축되면 컨텍스트 스위칭 자체가 사라진다.

초보자는 이렇게 이해하면 된다.

`핵심 흐름: Claude + MCP 연결 → 외부 데이터 직접 읽기 → 코드/쿼리 생성 → 결과 검증`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| MCP 서버 | Claude와 외부 시스템(DB, GitHub 등)을 연결하는 중간 어댑터 |
| 체크리스트 마이그레이션 | 작업 목록을 Markdown 파일로 만들어 Claude가 하나씩 완료하며 체크하게 하는 방식 |
| Headless 모드 | 대화형 터미널 없이 -p 플래그로 프롬프트를 전달해 자동화 스크립트에서 Claude를 실행하는 모드 |
| 파이프 입력 | 로그 파일 등을 `cat file | claude` 형태로 Claude에게 직접 넘기는 방식 |
| Conventional Commits | feat/fix/refactor 같은 타입 접두어를 사용하는 커밋 메시지 표준 |

## 예를 들어 설명하면

대규모 린트 오류 수정에서 체크리스트 방식이 왜 효과적인지 보여주는 패턴:

```
프롬프트:
"1단계: 린트를 실행하고 모든 에러를 파일명과 라인 번호 포함해서
LINT_ERRORS.md에 체크리스트로 작성해줘.

2단계: 각 항목을 하나씩 수정하고 완료하면 체크박스를 체크해줘.

3단계: 수정 후 린트를 다시 실행해서 에러가 사라졌는지 확인.

4단계: 모든 체크박스 완료까지 반복."
```

Claude가 중간에 멈춰도 LINT_ERRORS.md를 보면 어디까지 했는지 바로 알 수 있다. Postgres MCP를 설정하면 DB 쿼리 결과를 직접 받아 마케팅 이메일 템플릿까지 연결하는 것도 단일 프롬프트로 가능하다.

## 이 단계에서 중요한 판단 기준

MCP를 설정하기 전에 먼저 물어볼 것: "이 도구와 컨텍스트를 얼마나 자주 전환하는가?" — 하루 5회 이상이면 MCP 설정 비용을 금방 회수한다.

## 한 줄 요약 — 이것만 기억하면 된다

**MCP로 외부 도구를 Claude에 연결하고, 대규모 작업은 체크리스트 파일로 상태를 관리하면 Claude가 중간에 멈춰도 안전하게 이어서 진행할 수 있다.**
