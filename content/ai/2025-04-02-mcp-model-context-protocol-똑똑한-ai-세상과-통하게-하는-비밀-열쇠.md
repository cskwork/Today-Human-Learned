> **TL;DR**
> MCP는 AI 모델이 외부 도구와 데이터에 접근하는 방식을 표준화한 프로토콜이다. USB 포트처럼 한 번 규격을 맞추면 어떤 서비스든 연결할 수 있다.

---

## MCP를 왜 쓰는지 감 잡기

AI 챗봇에게 "내 캘린더 일정 알려줘"라고 물어도, AI가 캘린더 앱에 직접 접근할 수 없다면 대답하지 못한다. 예전에는 AI를 Slack, 데이터베이스, Google Drive 같은 외부 서비스와 연결하려면 서비스마다 별도의 연결 코드를 작성해야 했다. 서비스가 10개면 연결 코드도 10개, 유지보수 부담도 10배였다.

MCP는 Anthropic이 이 문제를 해결하기 위해 만든 개방형 표준이다. AI 모델(클라이언트)과 외부 서비스(서버) 사이의 소통 방식을 하나로 통일하여, MCP 규격을 따르는 서비스라면 어떤 AI 모델에서도 즉시 사용할 수 있게 한다.

`핵심 흐름: AI 클라이언트 → MCP 프로토콜(JSON-RPC 2.0) → MCP 서버(외부 서비스) → 결과 반환`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| MCP 클라이언트 | AI 모델 또는 AI 앱. 필요한 기능이나 데이터를 서버에 요청한다. |
| MCP 서버 | 외부 서비스(DB, Slack, Git 등)를 MCP 규격으로 포장한 게이트웨이. |
| 도구 (Tools) | 서버가 제공하는 실행 가능한 기능. 예: 메시지 보내기, 파일 검색하기. |
| 리소스 (Resources) | 서버가 제공하는 데이터 조각. 예: 특정 고객 정보, 최근 이메일 목록. |
| 동적 발견 | 클라이언트가 주변 MCP 서버와 그 기능을 자동으로 탐지하는 메커니즘. |

## 예를 들어 설명하면

개발자가 AI에게 "방금 작업한 내용 Git에 커밋하고 푸시해줘"라고 요청하는 상황이다.

1. AI 클라이언트가 Git MCP 서버에 "커밋 실행" 도구를 요청한다.
2. MCP 서버가 로컬 Git 저장소에 명령을 실행한다.
3. 결과를 AI 클라이언트에게 반환한다.

MCP 이전에는 이 연동 코드를 개발자가 직접 작성해야 했다. MCP 이후에는 Git MCP 서버 하나만 설치하면 규격을 지원하는 모든 AI 앱에서 동일하게 사용할 수 있다.

## 이 단계에서 중요한 판단 기준

MCP 서버는 중요한 데이터와 시스템으로 통하는 문이다. 서버를 구성할 때 인증(누가 접근할 수 있는지)과 권한(무엇을 할 수 있는지) 설정을 반드시 먼저 갖춰야 한다. 인증 없이 열어두면 외부에서 데이터에 접근할 수 있다.

## 한 줄 요약 - 이것만 기억하면 된다

**MCP는 AI가 외부 도구를 쓰는 방식을 표준화해서, 한 번 만든 MCP 서버를 어떤 AI 앱에서든 재사용할 수 있게 한다.**

## 나중에 더 깊게 들어가면

- Python과 TypeScript SDK를 이용한 MCP 서버 직접 구현
- MCP와 에이전트 프레임워크(LangChain, LlamaIndex 등) 연동 방식
- 로컬 MCP 서버로 민감한 데이터를 외부에 노출하지 않고 처리하는 패턴
