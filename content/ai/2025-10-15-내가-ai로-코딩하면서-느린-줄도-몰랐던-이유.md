> **TL;DR**
> AI 코딩 도구는 타이핑 시간을 줄이지만, 검증과 디버깅 시간을 늘린다. 경력 개발자 실험에서 실제 속도는 19% 감소했으나 당사자들은 20% 빨라졌다고 느꼈다.

---

## 이 역설을 왜 알아야 하는지 감 잡기

AI 코딩 도구를 쓰면 분명히 뭔가 빠른 느낌이 든다. 코드가 자동으로 생성되고, 타이핑할 양이 확 줄기 때문이다. 문제는 이 느낌이 실제 생산성과 다를 수 있다는 점이다.

한 연구에서 경력 개발자들이 Cursor Pro + Claude를 사용했을 때 실제 작업 완료 속도는 19% 감소했다. 그런데 같은 개발자들이 자신이 20% 빨라졌다고 평가했다. 이 괴리가 생기는 이유는 측정 대상이 다르기 때문이다. AI는 코드 생성 속도를 높이지만, 생성된 코드를 읽고, 이해하고, 검증하고, 버그를 찾아 고치는 시간은 오히려 늘어난다. 전자는 눈에 보이고, 후자는 잘 보이지 않는다.

한편 구글의 다른 연구에서는 AI 사용 시 21% 속도 향상이 나타났다. 둘 다 틀리지 않았다. 어떤 작업을 측정했느냐의 차이다.

초보자는 이렇게 이해하면 된다.

`핵심 흐름: AI 생성 속도 향상 → 검증·디버깅 시간 증가 → 순 효과는 작업 유형에 따라 다름`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| 보일러플레이트 | API 라우트나 DB 스키마처럼 반복적으로 쓰는 표준 코드 패턴 |
| 검증 비용 | AI가 만든 코드를 읽고 맞는지 확인하는 데 드는 시간과 인지 부담 |
| 아키텍처 | 시스템 전체 구조 설계. AI가 생성하기 어렵고 인간 판단이 필요한 영역 |
| 레거시 코드베이스 | 오래된 코드베이스. AI가 맥락을 잘못 이해하면 핵심 로직을 망가뜨릴 수 있다 |
| PR 봇 비율 | 풀 리퀘스트 중 AI가 생성한 코드의 비율. 현재 전체 PR의 약 13% |

## 예를 들어 설명하면

같은 개발자라도 작업 유형에 따라 AI의 순 효과가 달라진다.

| 작업 유형 | AI 활용 권장 수준 | 이유 |
|---|---|---|
| API 라우트, DB 스키마 작성 | 적극 활용 | 반복 패턴이 명확해 검증 비용이 낮다 |
| 복잡한 비즈니스 로직 | 보조적 활용 | 미묘한 버그 가능성이 높고 검증 비용이 크다 |
| 보안 관련 코드 | 사용 자제 | 오류가 시스템 전체에 영향을 준다 |
| 내가 이해 못 한 코드 영역 | 사용 금지 | 검증 자체가 불가능해 위험이 숨는다 |

## 이 단계에서 중요한 판단 기준

AI로 작성한 코드를 "내가 직접 이 코드를 설명할 수 있는가?"라는 기준으로 판단하라. 설명할 수 없다면 AI가 생성했어도 내 코드가 아니다.

## 한 줄 요약 — 이것만 기억하면 된다

**AI 코딩 도구는 타이핑 속도가 아니라 전체 작업 흐름(생성-검증-디버깅)에서 판단해야 하며, 작업 유형에 따라 선택적으로 사용할 때 실질적 이득이 생긴다.**

## 나중에 더 깊게 들어가면

- AI 생성 코드의 검증 비용을 줄이는 테스트 주도 개발(TDD) 방식
- MCP와 Claude Code를 활용한 컨텍스트 인식 코드 생성
- AI 코딩 도구별 벤치마크: SWE-Bench, HumanEval 지표 해석
