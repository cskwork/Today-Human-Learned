---

## 멀티 에이전트를 왜 쓰는지 감 잡기

단일 AI 모델 하나에 "시장 조사 보고서를 써줘"라고 요청하면, 리서치도 하고, 경쟁사 분석도 하고, 정리까지 혼자 해야 한다. 작업이 길어질수록 컨텍스트가 꼬이고, 한 분야에 깊이 집중하기 어렵다.

멀티 에이전트 시스템은 이 문제를 "분업"으로 푼다. 리서처, 분석가, 작성자, 편집자 에이전트가 각자의 역할에만 집중하고, 결과를 이어받아 처리한다. 실제 개발팀이 일하는 방식과 비슷하다.

초보자는 이렇게 이해하면 된다.

`핵심 흐름: 문제 분해 → 역할별 에이전트 설계 → 통신 규약 정의 → 공유 메모리 → 테스트`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| 오케스트레이터 | 전체 작업 흐름을 지휘하고 서브에이전트에게 일을 분배하는 관리자 에이전트 |
| 서브에이전트 | 특정 역할만 담당하는 전문 에이전트; 오케스트레이터의 지시를 받음 |
| 핸드오프 | 한 에이전트의 출력이 다음 에이전트의 입력이 되는 전달 과정 |
| 공유 상태 | 에이전트들이 중간 결과를 읽고 쓰는 공유 메모리 또는 저장소 |
| 계층형 vs 분산형 | 관리자-작업자 구조(계층형)인지, 에이전트들이 동등하게 소통하는 구조(분산형)인지의 아키텍처 선택 |

## 예를 들어 설명하면

"시장 조사 보고서 작성" 작업을 멀티 에이전트로 나누면:

1. `Researcher` 에이전트: 웹 검색 도구로 시장 트렌드 수집
2. `Competitor_Analyst` 에이전트: 경쟁사 데이터 분석
3. `Writer` 에이전트: 두 에이전트의 결과를 받아 초안 작성
4. `Editor` 에이전트: 초안을 검토하고 품질 확인

각 에이전트는 자신의 도구만 가진다. `Researcher`는 `web_search`를 쓰지만 `Editor`는 읽기 도구만 갖는다. 도구를 제한하면 에이전트가 권한 밖의 행동을 하지 않는다.

## 이 단계에서 중요한 판단 기준

작업이 독립적인 단위로 명확히 분해되는지 먼저 확인하라. 분해가 모호하면 단일 에이전트가 오히려 낫다.

## 한 줄 요약 — 이것만 기억하면 된다

**멀티 에이전트는 분업으로 복잡한 작업을 푸는 구조이며, 역할·도구·통신 규약 설계가 성패를 가른다.**
