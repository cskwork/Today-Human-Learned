> **TL;DR**
> Claude 3.5 Sonnet은 트랜스포머 구조 위에 RLHF 방식의 정렬 훈련을 거친 LLM으로, 텍스트와 이미지를 함께 이해하는 멀티모달 능력을 갖추고 있다.

---

## Claude 3.5 Sonnet을 왜 알아야 하는지 감 잡기

AI 모델을 도구로 쓰다 보면 "왜 이 모델은 이런 답을 내놓는가"가 궁금해진다. Claude 3.5 Sonnet은 Anthropic이 만든 Claude 3 패밀리 중 속도와 성능의 균형을 맞춘 모델이다. 내부 동작 원리를 이해하면 프롬프트를 더 잘 짤 수 있고, 모델의 한계를 예측해 적절한 작업에 배치할 수 있다.

초보자는 처음에 이렇게 이해하면 된다.

`대규모 텍스트 사전학습 → 미세조정(fine-tuning) → 인간 피드백 정렬(RLHF) → 배포`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| 트랜스포머(transformer) | 입력 전체를 동시에 보며 단어 간 관계를 파악하는 신경망 구조 |
| 사전학습(pretraining) | 인터넷 규모의 텍스트를 읽으며 언어 패턴을 학습하는 1단계 훈련 |
| 미세조정(fine-tuning) | 특정 작업이나 스타일에 맞게 사전학습된 모델을 추가 훈련하는 과정 |
| RLHF | 인간 평가자의 선호도를 피드백으로 삼아 모델 출력을 개선하는 정렬 기법 |
| 멀티모달(multimodal) | 텍스트와 이미지를 함께 입력받아 처리할 수 있는 능력 |

## 예를 들어 설명하면

긴 문서를 요약하는 작업을 예로 들면 모델 내부 흐름이 보인다.

1. **토큰화**: 입력 텍스트를 단어보다 작은 단위(토큰)로 쪼갠다. "프로그래밍" → ["프로", "##그래", "##밍"] 같은 식.
2. **어텐션 계산**: 트랜스포머가 각 토큰이 다른 토큰과 얼마나 관련 있는지 계산한다. 핵심 문장에 높은 가중치를 부여한다.
3. **핵심 추출**: 중요도가 높은 정보를 선별한다.
4. **요약 생성**: 선별된 정보를 바탕으로 자연스러운 문장을 토큰 단위로 순서대로 생성한다.

RLHF가 없으면 모델은 문법적으로는 맞지만 사실과 다르거나 해로운 내용을 출력할 수 있다. RLHF는 "사람이 더 좋다고 평가한 출력"을 강화해 이를 억제한다.

## 이 단계에서 중요한 판단 기준

Claude 3.5 Sonnet을 선택하는 기준은 속도와 품질의 균형이다. 빠른 응답이 중요한 대화형 앱에는 Haiku, 최고 품질이 필요한 복잡한 추론에는 Opus를 쓰고, 그 중간의 일반 작업에 Sonnet이 적합하다.

## 한 줄 요약 — 이것만 기억하면 된다

**Claude 3.5 Sonnet은 사전학습 + RLHF 정렬을 거친 멀티모달 LLM으로, Claude 3 패밀리 안에서 속도와 성능의 균형점에 위치한다.**

## 나중에 더 깊게 들어가면

- Claude와 GPT-4의 RLHF 접근 방식 차이 (Constitutional AI vs. InstructGPT)
- 멀티모달 입력이 어텐션 레이어에서 처리되는 방식
- 모델 컨텍스트 길이(context window)가 성능에 미치는 영향
