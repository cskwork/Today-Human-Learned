## 샌드박싱을 왜 쓰는지 감 잡기

Claude Code는 코드베이스를 탐색하고 파일을 수정하며 명령을 실행한다. 이 넓은 접근 권한은 강력하지만, 프롬프트 인젝션(악의적인 입력이 Claude의 행동을 조종하는 공격) 시 심각한 피해로 이어질 수 있다.

기존 방식은 매 작업마다 사용자 승인을 요청하는 것이었는데, 이는 "승인 피로"를 만든다. 사용자가 내용을 제대로 보지 않고 승인하면 오히려 더 위험해진다.

샌드박싱은 다른 접근이다. 미리 안전한 경계를 정의하고, 그 안에서는 Claude가 자유롭게 작동하게 한다. 경계 밖 접근 시도는 OS 수준에서 차단된다.

`핵심 흐름: 경계 정의 → 경계 안 자유 작동 → 경계 밖 접근 시 즉시 알림`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| 파일시스템 격리 | Claude가 지정된 디렉토리 외부의 파일을 읽거나 수정하지 못하게 막는 경계 |
| 네트워크 격리 | Claude가 승인된 도메인에만 연결할 수 있게 제한하는 경계 — 정보 유출 경로를 차단 |
| 프롬프트 인젝션 | 악의적인 외부 입력(예: 악성 코드 주석)이 Claude에게 의도치 않은 행동을 지시하는 공격 |
| bubblewrap / seatbelt | Linux와 macOS에서 샌드박스를 구현하는 OS 기본 도구 — Claude Code가 이 위에 샌드박스를 구축 |
| 보안 프록시 | 네트워크 요청을 중간에서 검증하는 서비스 — 허용된 도메인인지 확인하고, 새 도메인은 사용자에게 묻는다 |

## 예를 들어 설명하면

개발자가 오픈소스 라이브러리를 분석하다가, 그 라이브러리 코드 안에 프롬프트 인젝션 페이로드가 심겨있다고 가정하자.

샌드박싱이 없으면: Claude가 지시대로 SSH 키를 읽어 외부 서버로 전송할 수 있다.

샌드박싱이 있으면:
- 파일시스템 격리: `~/.ssh/` 폴더 접근 자체가 차단됨
- 네트워크 격리: 승인되지 않은 외부 서버 연결 시도를 프록시가 차단하고 사용자에게 알림

두 경계가 모두 필요한 이유: 네트워크만 막으면 파일에서 데이터를 추출해 승인된 경로로 우회할 수 있고, 파일시스템만 막으면 코드를 실행해 네트워크로 빠져나갈 수 있다.

## 이 단계에서 중요한 판단 기준

샌드박싱을 설정할 때 가장 먼저 결정해야 할 것은 "Claude가 접근해야 할 디렉토리와 도메인의 최소 집합이 무엇인가"다 — 넓게 열수록 효과가 줄어든다.

## 한 줄 요약 — 이것만 기억하면 된다

**파일시스템 격리와 네트워크 격리, 두 경계를 함께 써야 샌드박싱이 의미 있으며 — 하나만 있으면 우회 경로가 생긴다.**
