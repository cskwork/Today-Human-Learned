# JavaScript 엄격 모드 — use strict가 존재하는 이유

> **TL;DR**
> `"use strict"`는 ES5가 오래된 JavaScript의 결함을 고치면서, 기존 코드와의 호환성을 깨지 않기 위해 도입한 선택적 활성화 장치다.

---

## 엄격 모드를 왜 쓰는지 감 잡기

JavaScript는 오랫동안 하위 호환성을 철저히 지켜왔다. 브라우저에서 10년 전에 짠 코드가 지금도 돌아가야 하기 때문이다. 그 덕분에 초창기에 잘못 설계된 동작들도 그대로 언어 안에 남아 있었다.

2009년 ES5가 나오면서 일부 동작을 수정하거나 제한할 필요가 생겼다. 그런데 기본으로 적용하면 기존 사이트가 갑자기 망가진다. 그래서 `"use strict"`라는 선택적 스위치를 만들었다. 이 선언을 추가한 스크립트만 새로운 엄격한 규칙을 따른다.

초보자는 처음에 이렇게 이해하면 된다.

`핵심 흐름: 기존 느슨한 JS → ES5 문제 인식 → "use strict" 선언 → 엄격 규칙 적용`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| 엄격 모드 (strict mode) | JavaScript 실행 규칙을 더 엄격하게 만드는 모드. 허용되던 일부 동작을 에러로 처리한다. |
| 하위 호환성 | 예전에 작성한 코드가 새 버전의 언어에서도 그대로 작동하는 성질. |
| ES5 | 2009년에 발표된 JavaScript 표준 버전. 엄격 모드가 처음 도입된 버전이다. |
| 클래스 / 모듈 | ES6 이후 도입된 고급 문법 구조. 이 안에서는 엄격 모드가 자동으로 적용된다. |
| 지시자 (directive) | 코드 최상단에 문자열로 선언해 실행 환경에 지시를 내리는 방식. `"use strict"`가 대표적이다. |

## 예를 들어 설명하면

엄격 모드를 활성화하려면 스크립트나 함수의 첫 줄에 문자열로 선언한다.

```js
"use strict";

// 이 파일 전체가 엄격 모드로 실행됨
// 선언되지 않은 변수 사용 등 느슨한 동작은 에러로 처리됨
x = 5; // ReferenceError: x is not defined
```

브라우저 콘솔에서는 기본적으로 엄격 모드가 비활성화되어 있다. 콘솔에서 테스트하려면 `'use strict'`를 입력하고 Shift+Enter로 줄 바꿈한 뒤 코드를 이어 입력해야 한다.

ES6 `class`나 `import/export` 모듈 문법을 사용하면 별도 선언 없이 자동으로 엄격 모드가 켜진다.

## 이 단계에서 중요한 판단 기준

새 프로젝트는 클래스나 모듈을 쓰므로 엄격 모드가 자동 적용된다. 레거시 스크립트를 수정할 때만 파일 상단에 `"use strict"`를 명시적으로 추가할지 검토하면 된다.

## 한 줄 요약 — 이것만 기억하면 된다

**`"use strict"`는 구식 JavaScript의 느슨한 동작을 차단하는 선택적 스위치이며, 모던 클래스/모듈 코드에서는 자동으로 켜진다.**

## 나중에 더 깊게 들어가면

- 엄격 모드가 실제로 막는 동작 목록 (선언 없는 변수 할당, `with` 문, 중복 파라미터 등)
- 함수 단위로만 엄격 모드를 적용하는 패턴
- ES6 모듈 시스템이 엄격 모드를 강제하는 이유
