# Node.js 논블로킹 I/O — 기다리지 않아서 빠른 이유

> **TL;DR**
> Node.js는 I/O 작업이 끝날 때까지 멈추지 않고 다른 일을 계속 처리하기 때문에 적은 자원으로 많은 요청을 소화할 수 있다.

---

## 논블로킹 I/O를 왜 알아야 하는지 감 잡기

서버가 파일을 읽거나 DB에 쿼리를 날릴 때, 결과가 돌아오기까지 수십~수백 밀리초가 걸린다. 이 시간 동안 그냥 기다리면(블로킹) 서버는 다른 요청을 처리하지 못한다. 동시 접속자가 늘수록 대기줄이 길어진다.

Node.js는 I/O 작업을 운영체제에 맡기고, 결과가 오면 나중에 알려달라는 방식(이벤트 드리븐)을 쓴다. 덕분에 단일 스레드로도 수천 개의 동시 연결을 처리할 수 있다. 채팅 서버, 실시간 알림, API 게이트웨이처럼 I/O가 많고 대기 시간이 긴 서비스에 특히 유리하다.

초보자는 처음에 이렇게 이해하면 된다.

`I/O 요청 발송 → 다른 작업 처리 → I/O 완료 알림 수신 → 콜백 실행`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| 블로킹 (Blocking) | 작업이 끝날 때까지 다음 코드를 실행하지 않고 기다리는 방식 |
| 논블로킹 (Non-blocking) | 작업 완료를 기다리지 않고 바로 다음 코드로 넘어가는 방식 |
| 이벤트 루프 (Event Loop) | Node.js가 완료된 I/O를 감지하고 해당 콜백을 실행하는 핵심 메커니즘 |
| 콜백 (Callback) | I/O가 끝났을 때 실행하도록 미리 등록해두는 함수 |
| async/await | 콜백을 중첩하지 않고 순서대로 읽히는 코드처럼 비동기 로직을 작성하는 문법 |

## 예를 들어 설명하면

파일을 읽는 두 가지 방식을 비교하면 차이가 바로 보인다.

```js
const fs = require('fs');

// 블로킹: 파일을 다 읽을 때까지 서버가 다른 요청을 처리하지 못함
const data = fs.readFileSync('/path/to/file', 'utf8');
console.log(data);
console.log('파일 읽기 완료 후에만 여기 실행됨');

// 논블로킹: 파일 읽기를 OS에 맡기고 즉시 다음 줄로 넘어감
fs.readFile('/path/to/file', 'utf8', (err, data) => {
  if (err) throw err;
  console.log(data); // 파일이 준비됐을 때 실행
});
console.log('파일 읽는 동안 이미 여기 실행됨');
```

`readFileSync`는 파일 I/O가 끝나야 다음 줄로 넘어간다. `readFile`은 요청만 하고 즉시 다음 코드를 실행한다. 1000명이 동시에 파일을 요청해도 서버는 멈추지 않는다.

## 이 단계에서 중요한 판단 기준

Node.js의 논블로킹 모델은 I/O 대기 시간이 긴 작업에 강하지만, CPU를 오래 점유하는 계산 작업에는 오히려 병목이 된다.

## 한 줄 요약 — 이것만 기억하면 된다

**Node.js는 I/O 결과를 기다리는 대신 이벤트 루프가 완료 신호를 받아 콜백을 실행하므로, 하나의 스레드로 수많은 요청을 동시에 처리할 수 있다.**

## 나중에 더 깊게 들어가면

- 이벤트 루프의 단계별 동작 (timers, poll, check 큐)
- Promise 체이닝과 async/await 에러 처리 패턴
- CPU 집중 작업을 Worker Threads로 분리하는 방법
