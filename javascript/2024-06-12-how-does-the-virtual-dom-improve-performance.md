# 가상 DOM — React가 화면을 빠르게 업데이트하는 방법

> **TL;DR**
> 가상 DOM은 실제 DOM의 사본을 메모리에 두고, 변경된 부분만 실제 DOM에 반영해 브라우저 작업을 최소화한다.

---

## 가상 DOM을 왜 쓰는지 감 잡기

웹 브라우저에서 화면을 바꾸는 작업(실제 DOM 조작)은 생각보다 무겁다. 한 요소를 바꿔도 브라우저는 스타일을 다시 계산하고, 레이아웃을 다시 잡고, 화면을 다시 그린다. 항목 하나 추가될 때마다 이 작업 전체를 반복하면 느릴 수밖에 없다.

React는 이 문제를 가상 DOM으로 해결한다. 실제 DOM을 직접 건드리기 전에, 메모리 안의 가벼운 사본에서 변경 사항을 계산하고 필요한 부분만 실제 DOM에 한번에 적용한다.

`핵심 흐름: 상태 변경 → 새 가상 DOM 생성 → 이전 가상 DOM과 비교(Diffing) → 달라진 부분만 실제 DOM 업데이트`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| 실제 DOM | 브라우저가 화면을 그리기 위해 유지하는 페이지 구조 트리 |
| 가상 DOM | React가 메모리에 유지하는 실제 DOM의 경량 사본 |
| Diffing | 이전 가상 DOM과 새 가상 DOM을 비교해 달라진 부분을 찾는 과정 |
| 재조정(Reconciliation) | Diffing 결과를 바탕으로 실제 DOM을 최소한으로 업데이트하는 과정 |
| 배치 업데이트 | 여러 변경사항을 모아서 한 번에 실제 DOM에 적용하는 방식 |

## 예를 들어 설명하면

100개 항목이 있는 목록에서 하나를 추가하는 상황이다.

1. 상태가 바뀌면 React는 새 가상 DOM 트리를 만든다 (101개 항목).
2. 이전 가상 DOM (100개)과 새 가상 DOM (101개)을 비교한다.
3. Diffing 결과: 새 항목 하나만 다르다.
4. 실제 DOM에서 그 항목 하나만 추가한다.

가상 DOM 없이 직접 DOM을 조작했다면 목록 전체를 다시 그리거나, 수동으로 변경점을 추적해야 한다. React는 이 과정을 자동화한다.

## 이 단계에서 중요한 판단 기준

가상 DOM은 자동으로 작동하므로 개발자가 직접 관리할 필요는 없다. 하지만 불필요한 재렌더링을 줄이고 싶다면 `React.memo`, `useMemo`, `useCallback` 같은 최적화 도구를 고려한다.

## 한 줄 요약 — 이것만 기억하면 된다

**가상 DOM은 실제 DOM 조작을 최소화하기 위해, 메모리에서 먼저 변경점을 계산하고 필요한 부분만 화면에 반영한다.**
