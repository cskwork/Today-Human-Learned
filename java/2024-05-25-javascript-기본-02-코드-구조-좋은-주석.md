# Javascript 코드 구조와 좋은 주석 — 읽히는 코드를 쓰는 법

> **TL;DR**
> 주석은 코드가 "왜" 그렇게 작성됐는지를 설명할 때만 가치가 있다. "무엇"을 하는지는 코드 자체가 말해야 한다.

---

## 코드 구조와 주석을 왜 신경 쓰는지 감 잡기

코드는 컴퓨터가 아니라 사람이 읽는다. 6개월 뒤 자신이 쓴 코드를 다시 열었을 때, 혹은 팀원이 처음 보는 코드를 수정할 때, 읽기 쉬운 코드는 오류를 줄이고 작업 속도를 높인다. JavaScript는 세미콜론 자동 삽입(ASI) 같은 함정도 있어서 명확한 문장 구조가 더욱 중요하다.

초보자는 처음에 이렇게 이해하면 된다.

`핵심 흐름: 명확한 이름 → 단일 책임 함수 → 필요한 곳에만 주석`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| 문(Statement) | JavaScript 엔진에 하나의 동작을 지시하는 최소 단위 코드 |
| 세미콜론(;) | 문의 끝을 명시적으로 표시. 없으면 ASI가 잘못 판단할 수 있다. |
| ASI | 자동 세미콜론 삽입. 생략해도 동작하는 경우가 많지만 예외가 있다. |
| 한 줄 주석 | `//` 이후의 텍스트. 한 줄짜리 설명에 쓴다. |
| JSDoc | `/** ... */` 형식의 함수 문서화 주석. IDE 자동완성과 연동된다. |

## 예를 들어 설명하면

세미콜론 누락이 만드는 대표적인 함정이다.

```javascript
// 위험한 코드 — ASI가 두 줄을 하나로 합쳐 오류를 낸다
alert("첫 번째 메시지")
[1, 2].forEach(alert)

// 안전한 코드
alert("첫 번째 메시지");
[1, 2].forEach(alert);
```

좋은 주석과 나쁜 주석의 차이는 명확하다.

```javascript
// 나쁜 주석 — 코드를 그냥 반복한다
i++; // i를 1 증가시킨다

// 좋은 주석 — 왜 이 방식을 선택했는지 설명한다
// 정규식 대신 수동 파싱을 사용한다. 이 형식에서 정규식은 지수 시간 복잡도를 가져
// 입력이 커지면 성능이 급격히 떨어지기 때문이다.
function parseCustomFormat(input) { ... }
```

## 이 단계에서 중요한 판단 기준

주석을 쓰기 전에 "코드 이름을 바꾸거나 함수를 분리하면 주석 없이 이해되지 않을까?"를 먼저 물어본다. 그래도 설명이 필요하면 그때 주석을 쓴다.

## 한 줄 요약 — 이것만 기억하면 된다

**좋은 코드는 주석이 필요 없고, 꼭 필요한 주석은 "왜"를 설명한다.**

## 나중에 더 깊게 들어가면

- JSDoc 전체 문법: `@param`, `@returns`, `@throws`로 함수 API를 문서화하는 방법
- ESLint 규칙: 코드 스타일을 자동으로 강제하는 도구 설정
- TypeScript: 타입 시스템으로 주석 없이도 의도를 코드에 담는 방법
