# 자바 8에서 18까지 — 무엇이 달라졌나

> **TL;DR**
> 자바 8이 람다와 스트림으로 함수형 프로그래밍의 문을 열었다면, 이후 버전들은 반복적인 보일러플레이트를 줄이고 코드를 더 읽기 쉽게 만드는 방향으로 진화했다.

---

## 왜 버전별 차이를 알아야 하는지 감 잡기

많은 회사가 자바 8로 구축된 서비스를 유지하면서 최신 버전으로 마이그레이션을 검토한다. 버전 간 차이를 모르면 새 문법을 낡은 방식으로 쓰거나, 마이그레이션 시 예상치 못한 동작 변화를 겪는다. 각 버전이 어떤 문제를 해결하려 했는지 맥락을 알면 선택이 쉬워진다.

초보자는 처음에 이렇게 이해하면 된다.

`핵심 흐름: 자바 8 (함수형 기초) → 자바 10-11 (편의 문법) → 자바 14-17 (언어 표현력) → 자바 18 (마이너 개선)`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| 람다 표현식 | 이름 없는 함수를 한 줄로 표현하는 문법. `() -> 실행할 코드` 형태 |
| 스트림 API | 컬렉션을 필터·변환·집계하는 파이프라인. SQL처럼 선언적으로 데이터를 처리 |
| 레코드 | 불변 데이터 컨테이너를 선언하는 단축 문법. getter/equals/hashCode를 자동 생성 |
| 봉인 클래스 (sealed) | 어떤 클래스가 이 클래스를 상속할 수 있는지 명시적으로 제한하는 기능 |
| 패턴 매칭 | `instanceof` 검사와 타입 캐스팅을 한 번에 처리하는 문법 |

## 예를 들어 설명하면

버전별 핵심 변화를 코드로 나란히 보면 변화 폭이 명확해진다.

```java
// 자바 8 — 람다와 스트림
List<String> result = names.stream()
    .filter(n -> n.startsWith("J"))
    .map(String::toUpperCase)
    .collect(Collectors.toList());

// 자바 10 — var로 타입 추론
var message = "Hello";  // 컴파일러가 String으로 추론

// 자바 14 — 레코드 (불변 객체)
// 이전: 클래스 선언 + 필드 + 생성자 + getter + equals + hashCode = 수십 줄
// 이후:
public record Person(String name, int age) {}

// 자바 14 — 패턴 매칭 instanceof
if (obj instanceof String s) {
    System.out.println(s.toUpperCase());  // 별도 캐스팅 불필요
}

// 자바 17 — 봉인 클래스
public sealed class Shape permits Circle, Rectangle {}
public final class Circle extends Shape { ... }
public final class Rectangle extends Shape { ... }
```

자바 12에서 개선된 switch 표현식도 자주 쓰인다.

```java
// 이전: break 없으면 fall-through 버그 위험
// 이후:
String label = switch (day) {
    case MONDAY, FRIDAY -> "주요 일정";
    case WEDNESDAY      -> "중간 점검";
    default             -> "일반";
};
```

## 이 단계에서 중요한 판단 기준

신규 프로젝트라면 최소 자바 17(LTS) 이상을 선택하라. 자바 8 코드베이스를 이전할 때는 레코드·패턴 매칭·텍스트 블록 순으로 점진적으로 도입하면 리스크가 낮다.

## 한 줄 요약 — 이것만 기억하면 된다

**자바 8 이후 버전은 같은 일을 더 적은 코드로 표현하게 도와준다. 핵심은 람다(8), var(10), 레코드(16), 봉인 클래스(17)다.**

## 나중에 더 깊게 들어가면

- 자바 21 가상 스레드 (Project Loom) — 수백만 동시 연결을 적은 스레드로 처리하는 방법
- 봉인 클래스 + switch 패턴 매칭 결합 — 대수적 타입을 자바에서 표현하는 방법
- `Stream.toList()` (자바 16) vs `Collectors.toList()` 차이 — 불변성과 null 처리 차이
