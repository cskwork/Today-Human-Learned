# SHA — 데이터의 지문을 찍는 해시 함수

> **TL;DR**
> SHA는 어떤 크기의 입력이든 고정 길이의 고유한 "지문(해시값)"으로 바꾸며, 원본이 조금이라도 바뀌면 지문이 완전히 달라지는 성질로 무결성을 보장한다.

---

## SHA를 왜 쓰는지 감 잡기

파일을 인터넷으로 받았을 때, 그 파일이 중간에 변조되지 않았다는 것을 어떻게 증명할까? SHA(Secure Hash Algorithm)는 원본 데이터에 대한 "디지털 지문"을 만들어 준다. 지문이 같으면 내용이 동일하고, 지문이 다르면 뭔가 바뀐 것이다. 비밀번호 저장, 소프트웨어 배포 검증, 블록체인 트랜잭션 무결성 확인 등 곳곳에 쓰인다.

SHA는 암호화가 아니다. 해시는 단방향이라 원래 데이터를 복원할 수 없다.

초보자는 처음에 이렇게 이해하면 된다.

`핵심 흐름: 입력 데이터 → 블록 분할 → 압축 함수 반복 적용 → 고정 길이 해시값 출력`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| 해시값 (Hash Value) | 입력 데이터를 고정 길이로 압축한 결과물 — 지문에 해당 |
| 단방향성 | 해시에서 원본을 역산할 수 없는 성질 — 지문으로 사람을 복원할 수 없는 것과 같다 |
| 눈사태 효과 (Avalanche Effect) | 입력 한 비트만 바꿔도 출력의 절반 이상이 달라지는 성질 |
| 충돌 저항성 (Collision Resistance) | 같은 해시값을 내는 두 입력을 찾기가 현실적으로 불가능한 성질 |
| 결정론적 (Deterministic) | 같은 입력이면 언제나 같은 해시값이 나온다는 보장 |

## 예를 들어 설명하면

SHA-256으로 "HELLO"를 해싱하면:

```
입력:  "HELLO"
출력:  185f8db32271fe25f561a6fc938b2e264306ec304eda518007d1764826381969
```

"HELLO"에서 소문자 "hello"로 한 글자만 바꾸면:

```
입력:  "hello"
출력:  2cf24dba5fb0a30e26e83b2ac5b9e29e1b161e5c1fa7425e73043362938b9824
```

출력이 완전히 다르다. 파일 배포 사이트가 SHA-256 체크섬을 함께 제공하는 이유가 바로 이 눈사태 효과 때문이다.

## 이 단계에서 중요한 판단 기준

SHA-1은 이미 충돌이 발견됐으므로 신규 시스템에 쓰지 말고, SHA-256 이상을 기본으로 선택해야 한다 — 비밀번호 해싱에는 SHA 계열 대신 bcrypt나 Argon2처럼 속도를 의도적으로 늦춘 함수를 써야 한다.

## 한 줄 요약 — 이것만 기억하면 된다

**SHA는 데이터의 지문을 단방향으로 찍어 무결성을 검증하는 도구이며, 암호화와는 달리 원본 복원이 불가능하다.**

## 나중에 더 깊게 들어가면

- SHA-3: SHA-2와 내부 구조가 완전히 다른 Keccak 스펀지 함수
- HMAC: 해시에 비밀 키를 결합해 메시지 인증에 쓰는 방식
- 비밀번호 저장: SHA 대신 bcrypt·scrypt·Argon2를 써야 하는 이유
