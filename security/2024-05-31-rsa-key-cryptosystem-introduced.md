# RSA 암호화 시스템 — 자물쇠 두 개짜리 금고의 원리

> **TL;DR**
> RSA는 공개 키로 잠그고 비밀 키로만 열 수 있는 비대칭 암호화 방식이며, 보안의 근거는 "큰 수를 소인수분해하기 어렵다"는 수학적 사실에 있다.

---

## RSA를 왜 쓰는지 감 잡기

인터넷으로 비밀 정보를 보낼 때, 먼저 "어떻게 암호화 키를 상대방에게 전달하지?"라는 문제가 생긴다. 키 자체를 평문으로 보내면 도청자가 가로채서 쓸 수 있다. RSA는 이 딜레마를 해결한다. 열쇠를 직접 전달하지 않고, 누구나 잠글 수 있는 공개 자물쇠(공개 키)를 상대방에게 넘겨주고, 열쇠(비밀 키)는 자신이 보관한다. 메시지를 받는 사람만 열 수 있는 구조다.

RSA는 HTTPS 핸드셰이크, 전자서명, SSH 키 인증 등 현대 보안 인프라 전반에 쓰인다.

초보자는 처음에 이렇게 이해하면 된다.

`핵심 흐름: 두 소수 선택 → 공개/비밀 키 생성 → 공개 키로 암호화 → 비밀 키로 복호화`

## 외워야 할 핵심 용어 5개

| 용어 | 초보자식 설명 |
|---|---|
| 공개 키 (Public Key) | 누구에게나 배포하는 자물쇠 — 잠글 수만 있고 열 수는 없다 |
| 비밀 키 (Private Key) | 자신만 보관하는 열쇠 — 공개 키로 잠근 것을 여는 유일한 수단 |
| 소수 (Prime Number) | 1과 자기 자신으로만 나누어지는 수 — RSA 보안의 수학적 기반 |
| 소인수분해 | 큰 수를 소수들의 곱으로 분해하는 것 — 수가 클수록 현실적으로 불가능에 가깝다 |
| 모듈러 연산 | 나눗셈의 나머지만 취하는 연산 (예: 17 mod 5 = 2) — RSA 암복호화 공식의 핵심 |

## 예를 들어 설명하면

소수 p=61, q=53을 선택하면 n=3233이 된다. 공개 키는 (e=17, n=3233), 비밀 키는 (d=2753, n=3233)이다.

```python
# 암호화: 메시지 m=65를 공개 키로 잠금
ciphertext = pow(65, 17, 3233)   # = 2790

# 복호화: 암호문을 비밀 키로 열기
plaintext  = pow(2790, 2753, 3233)  # = 65
```

n=3233은 소수가 아니지만, 61과 53을 모르면 d를 역산하기가 매우 어렵다. 실제 RSA는 n이 2048비트(약 600자리 숫자)여서 현재 컴퓨터로는 분해에 우주 나이보다 긴 시간이 걸린다.

## 이 단계에서 중요한 판단 기준

RSA는 "키 교환"과 "서명"에 쓰고, 대용량 데이터 암호화에는 AES 같은 대칭 키 방식을 써야 한다 — RSA는 느리기 때문에 둘을 조합하는 하이브리드 방식이 표준이다.

## 한 줄 요약 — 이것만 기억하면 된다

**공개 키로 잠그고 비밀 키로만 여는 RSA의 안전성은, 큰 수의 소인수분해가 현실적으로 불가능하다는 수학적 사실에 달려 있다.**

## 나중에 더 깊게 들어가면

- OAEP 패딩 — 평문 RSA가 왜 안전하지 않은지
- 하이브리드 암호화 — RSA + AES를 함께 쓰는 실제 HTTPS 구조
- 양자 컴퓨터와 RSA — Shor 알고리즘이 RSA를 위협하는 이유와 대안(격자 암호)
